프로그램이란 — 컴퓨터에게 순서대로 시키는 일

요리 레시피를 떠올려 보세요. "물 500mL를 끓인다 → 면을 넣는다 → 4분 기다린다 → 불을 끈다." 레시피는 정해진 순서대로 따라 하면 결과가 나오는 지시문의 목록입니다.

프로그램도 똑같습니다. 다만 읽는 쪽이 사람이 아니라 컴퓨터일 뿐입니다. 컴퓨터는 아주 빠르고 지치지 않지만, 융통성이 전혀 없습니다. "적당히", "알아서"를 모릅니다. 그래서 정확한 단어와 정확한 순서로 적어 줘야 합니다. 그 "정확한 단어"의 규칙이 바로 프로그래밍 언어이고, 웹 브라우저가 알아듣는 언어가 JavaScript입니다.

레시피 vs 프로그램 
레시피 (사람이 읽음)            프로그램 (컴퓨터가 읽음)
─────────────────────          ───────────────────────────
1. 물 500mL를 "물"이라고 적어 둔다   const water = 500;
2. 적어 둔 양을 소리 내어 확인한다     console.log(water);
3. 위에서부터 한 줄씩 따라 한다       → 위에서부터 한 줄씩 실행됩니다

HTML이 "화면에 무엇이 있는지", CSS가 "어떻게 보이는지"를 적는 언어였다면, JavaScript는 "무엇을 할지"를 적는 언어입니다. 버튼을 누르면 숫자가 올라가고, 입력이 틀리면 경고가 뜨는 것 같은 동작이 전부 JavaScript의 몫입니다.

마지막 줄이 중요합니다. 지금부터 쓸 console.log()는 console이라는 객체에 딸린 log라는 메서드를 부르는 코드입니다. 점(.)은 "~의"라고 읽으면 됩니다. "console의 log를 실행해라."

console.log — 결과를 눈으로 확인하기

2장에서 console.log("현재 주소:", location.href) 같은 코드를 이미 따라 써 봤습니다. 이제 정식으로 설명합니다.

console.log("안녕하세요");      // 괄호 안의 값을 콘솔에 출력합니다
console.log(1 + 2);             // 3 — 계산한 결과가 나옵니다
console.log("나이:", 20);       // 쉼표로 여러 값을 한 번에 출력할 수 있습니다

프로그램은 눈에 보이지 않는 곳에서 돌아갑니다. console.log는 "지금 이 값이 뭔지 보여 줘"라고 컴퓨터에게 묻는 창문입니다. 화면에는 아무 변화가 없고, 개발자 도구의 콘솔에만 찍힙니다. 이 책의 실행기에서는 실행 결과 칸에 나옵니다.

콘솔 탭 — 여러분의 실험실

개발자 도구(F12 / ⌘⌥I)의 Console 탭에서는 코드를 한 줄씩 바로 실행할 수 있습니다. 문법이 헷갈릴 때 파일을 만들 필요 없이 즉시 확인할 수 있어서, 학습 속도가 크게 달라집니다.

지금은 console.log 하나면 충분합니다. 나머지는 필요할 때 꺼내 쓰는 도구입니다.

메서드용도
console.log()일반 출력. 90%는 이것만 씁니다
console.warn() / error()노란 경고 / 빨간 오류처럼 표시
console.table()배열·객체를 표로 보여줍니다 (배열·객체는 28·29장)

🏷️ 출력에 이름표를 붙이세요

console.log(user);              // 값만 나와서 뭐가 뭔지 모름
console.log("user:", user);     // ✅ 앞에 설명을 붙이면 무엇의 값인지 보입니다

28장에서 객체를 배우면 console.log({ user, count })처럼 이름과 값을 한꺼번에 찍는 요령도 쓸 수 있습니다.

코드를 넣는 방법

HTML 문서에 JavaScript를 넣을 때는 <script> 태그를 씁니다.

세 가지 방법 
<!-- ① 외부 파일 (권장) -->
<script src="main.js" defer></script>

<!-- ② 문서 안에 직접 -->
<script>
  console.log("안녕");
</script>

<!-- ③ 모듈로 (34장) — 기본으로 defer 처럼 동작 -->
<script type="module" src="main.js"></script>

5장에서 배운 defer를 기억하세요. defer 없이 <head>에 스크립트를 두면 아직 만들어지지 않은 요소를 찾게 되어 "못 찾았다"는 뜻의 null을 받고, 거기서 오류가 납니다.

⚠️ src가 있으면 안쪽 내용은 무시됩니다

<script src="main.js">
  console.log("이 줄은 실행되지 않습니다");
</script>

둘을 함께 쓰려면 <script> 태그를 따로 만들어야 합니다.

기본 문법 규칙

세미콜론은 필수인가

JavaScript에는 자동 세미콜론 삽입(ASI)이라는 규칙이 있어서, 대부분의 경우 생략해도 동작합니다. 하지만 몇 가지 상황에서 예상과 다르게 해석됩니다.

const a = 1
const b = 2
const result = a + b
;[1, 2, 3].forEach(n => console.log(n))
//  ↑ 줄이 대괄호 [ 나 괄호 ( 로 시작하면 앞 줄과 이어져 해석될 수 있어
//    앞에 세미콜론을 붙이는 방어 코드가 필요합니다
//  (forEach는 29장, => 화살표 함수는 27장에서 배웁니다. 지금은 줄 맨 앞의 [ 만 보세요)

실무에서는 논쟁하지 않습니다. Prettier 같은 포매터(48장)가 팀 규칙대로 자동 정리해 줍니다. 어느 쪽이든 일관되게만 쓰면 됩니다. 이 책은 세미콜론을 붙이는 쪽으로 씁니다.

엄격 모드

"use strict";   // 파일이나 함수의 맨 앞에

x = 10;   // 엄격 모드에서는 오류. 선언 없이 변수를 만들 수 없습니다

초기 JavaScript의 관대한(그래서 위험한) 동작을 막는 모드입니다. <script type="module">과 ES 모듈(34장), 그리고 class(32장) 내부는 자동으로 엄격 모드이므로 현대적인 코드에서는 따로 선언할 일이 거의 없습니다.

이름 짓기 규칙

  • 문자·숫자·_·$를 쓸 수 있지만 숫자로 시작할 수 없습니다.
  • 대소문자를 구분합니다. userName과 username은 다릅니다.
  • if, for, class 같은 예약어(언어가 이미 쓰고 있는 단어)는 쓸 수 없습니다.
  • 관례: 변수·함수는 카멜케이스(userName), 클래스는 파스칼케이스(UserProfile), 상수는 대문자(MAX_COUNT).
  • 한글 변수명도 문법상 가능하지만 쓰지 않습니다. 협업·도구 호환 문제가 생깁니다.

🛠️ 현장 노트 — 좋은 이름이 주석보다 낫습니다

// 나쁨: 이름이 아무것도 말해 주지 않아 주석이 필요합니다
const d = 30;  // 배송까지 걸리는 일수

// 좋음: 이름 자체가 설명입니다
const deliveryDays = 30;

// 불리언(참·거짓)은 is·has·can 으로 시작하면 읽기 쉽습니다
const isLoggedIn = true;
const hasPermission = false;

오류를 읽는 법

초보자는 빨간 글씨를 보면 당황해서 그냥 다시 실행합니다. 오류 메시지는 문제 해결의 가장 중요한 단서입니다. 반드시 읽으세요.

메시지뜻
x is not defined그런 이름의 변수가 없습니다. 오타이거나 선언 전에 썼습니다
Cannot read properties of null (reading 'x')가장 흔한 오류. 요소를 못 찾아 null(없음)인데 그 안의 값을 꺼내려 했습니다
x is not a function함수가 아닌 것을 함수처럼 호출했습니다. 오타이거나 타입이 다릅니다
Unexpected token문법 오류. 괄호·따옴표 짝이 안 맞는 경우가 대부분입니다

콘솔의 오류 메시지 오른쪽에는 파일명과 줄 번호가 있습니다. 클릭하면 그 줄로 이동합니다. 오류가 난 줄과 그 위 몇 줄을 함께 보는 것이 요령입니다.

배경 지식 — 이름과 역사

여기부터는 코드를 쓰는 데 당장 필요하진 않지만, 대화에서 자주 나오는 용어를 이해하기 위한 배경입니다.

1995년, 넷스케이프의 브렌던 아이크가 웹 브라우저에 넣을 언어를 만들었습니다. 1장에서 말했듯 Java와는 아무 관계가 없고, 당시 인기 있던 Java의 이름값을 빌린 마케팅 결정이었습니다. 이후 1997년 표준화 단체 ECMA International이 규격을 정리했고, 그 규격의 이름이 ECMAScript입니다.

📘 JavaScript vs ECMAScript, 그리고 "ES6"

ECMAScript는 규격(설계도), JavaScript는 그 규격을 구현한 언어입니다. 일상 대화에서는 구분 없이 쓰지만, 버전 이야기를 할 때는 항상 ECMAScript 쪽입니다.

"ES6"는 2015년판(ES2015)을 말합니다. let·const, 화살표 함수 등 이 책에서 배울 문법이 대거 들어와 변화가 가장 컸기 때문에 지금도 자주 언급됩니다. 이후로는 해마다 조금씩 추가되고, 이 책의 문법은 모든 현대 브라우저가 지원합니다.

어디서 실행되나 — 엔진과 Node.js

JavaScript 코드를 실제로 해석하고 실행하는 프로그램을 엔진이라고 합니다. Chrome·Edge는 V8, Safari는 JavaScriptCore, Firefox는 SpiderMonkey를 씁니다.

Node.js — 브라우저 밖으로

2009년, V8 엔진을 브라우저에서 떼어내 일반 프로그램처럼 실행할 수 있게 만든 것이 Node.js입니다. 이때부터 JavaScript로 서버도, 명령줄 도구도 만들 수 있게 되었습니다.

🚧 언어는 같지만 쓸 수 있는 도구가 다릅니다

브라우저Node.js
있는 것window, document, alert, DOM, localStorage파일 시스템(fs), 프로세스, 네트워크 서버
없는 것파일 읽기·쓰기 (보안상 차단)document, window, 화면

문법(if, for, 함수, 배열)은 완전히 같습니다. 차이는 환경이 제공하는 기능입니다. Node.js에서 document를 쓰면 "document is not defined" 오류가 납니다. 46장에서 다시 다룹니다.

📌 요약

  • 프로그램은 컴퓨터에게 순서대로 시키는 지시문 목록이고, 위에서부터 한 줄씩 실행된다.
  • 값·변수·배열·객체·함수·메서드는 앞으로 계속 나올 기본 단어다. console.log는 console 객체의 log 메서드다.
  • console.log로 값을 눈으로 확인하며 실험한다.
  • <script>에 src가 있으면 태그 안 내용은 무시된다.
  • 세미콜론은 대개 생략 가능하지만 포매터에 맡기고 일관되게 쓴다. 모듈과 class 내부는 자동으로 엄격 모드다.
  • 오류 메시지를 반드시 읽는다. 파일·줄 번호가 함께 나온다.
  • ECMAScript는 규격, JavaScript는 그 구현이다. 브라우저와 Node.js는 언어는 같고 제공하는 기능이 다르다.
