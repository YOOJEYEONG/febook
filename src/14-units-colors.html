절대 단위 — px

px는 픽셀이지만 화면의 물리적 점 하나가 아닙니다. 고해상도(레티나) 화면에서는 CSS의 1px이 실제 점 2~3개로 그려집니다. CSS의 px는 기기와 무관하게 일정한 크기로 보이도록 정의된 논리적 단위입니다. 그래서 아이폰이든 4K 모니터든 16px 글자는 대체로 비슷한 크기로 보입니다.

cm·mm·in·pt 같은 단위도 있지만 화면에서는 쓰지 않습니다. 인쇄용 스타일시트에서만 의미가 있습니다.

em과 rem, 무엇이 다른가

🌀 em은 중첩되면 곱해집니다

html { font-size: 16px; }
.a { font-size: 1.5em; }  /* 16 × 1.5 = 24px */
.b { font-size: 1.5em; }  /* .a 안에 있으면 24 × 1.5 = 36px */
.c { font-size: 1.5em; }  /* .b 안에 있으면 36 × 1.5 = 54px  ← 눈덩이 */

목록 안에 목록이 중첩되는 구조에서 이 현상이 터집니다. rem은 항상 루트만 보므로 몇 겹으로 중첩되어도 값이 변하지 않습니다.

♿ 글자 크기에 rem을 쓰는 진짜 이유

브라우저 설정에서 기본 글꼴 크기를 크게 해 둔 사용자가 있습니다(저시력 사용자에게 흔합니다). 글자 크기를 px로 고정하면 그 설정이 무시됩니다. rem으로 쓰면 루트 크기가 사용자 설정을 따라 커지므로 전체가 함께 커집니다. 그래서 글자 크기는 rem이 권장됩니다. (참고로 브라우저의 확대/축소 기능은 px도 함께 확대하므로 이 문제와는 별개입니다.)

vh의 모바일 함정

모바일 브라우저는 스크롤에 따라 주소창이 나타났다 사라집니다. 그때 100vh가 실제 보이는 높이와 달라져 요소가 화면 밖으로 잘리는 문제가 오래 있었습니다.

단위기준
svh가장 작은 뷰포트 (주소창이 보일 때)
lvh가장 큰 뷰포트 (주소창이 숨겨졌을 때)
dvh실시간으로 변하는 현재 뷰포트 ← 대체로 이것이 정답

Chrome 108+, Safari 15.4+, Firefox 101+에서 지원됩니다. 구형 대비가 필요하면 height: 100vh; height: 100dvh;처럼 두 줄을 겹쳐 쓰면 지원하지 않는 브라우저는 앞줄을, 지원하는 브라우저는 뒷줄을 씁니다.

계산 — calc, min, max, clamp

/* 다른 단위끼리도 계산됩니다 */
width: calc(100% - 40px);
height: calc(100vh - 60px);   /* 화면 높이에서 헤더 높이만큼 뺀다 */

/* 여럿 중 작은 값 / 큰 값 */
width: min(600px, 100%);      /* width:100%; max-width:600px 와 같은 뜻 */
font-size: max(14px, 1vw);

/* 최소, 이상적, 최대 */
font-size: clamp(1rem, 2.5vw, 2rem);

clamp(최솟값, 선호값, 최댓값)은 화면 크기에 따라 부드럽게 변하되 범위를 벗어나지 않는 값을 만듭니다. 미디어 쿼리 없이 반응형 타이포그래피를 구현하는 현대적인 방법이며, 19장에서 다시 다룹니다.

➖ calc()의 공백 규칙

+와 - 양옆에는 반드시 공백이 있어야 합니다. calc(100%-40px)은 동작하지 않습니다. -40px이 음수 값으로 해석되기 때문입니다. *와 /는 공백이 없어도 되지만, 통일해서 쓰는 편이 안전합니다.

🎨 hsl과 oklch가 편한 이유

#1f5f4f를 조금만 더 밝게 만들려면 어떻게 해야 할까요? 16진수로는 감이 오지 않습니다. hsl(165 51% 25%)이라면 마지막 숫자만 35%로 올리면 됩니다. 호버 색, 비활성 색, 다크 모드 색을 만들 때 훨씬 편합니다.

oklch는 여기서 한 걸음 더 갑니다. HSL은 명도 값이 같아도 노랑이 파랑보다 훨씬 밝게 보입니다. oklch는 사람의 시각을 기준으로 만들어져 명도 값이 같으면 실제로 비슷한 밝기로 보입니다. 색 팔레트를 체계적으로 만들 때 유리합니다. Chrome 111+, Safari 15.4+, Firefox 113+에서 지원되어 지금은 실무 사용이 가능합니다.

currentColor와 color-mix

.button {
  color: #1f5f4f;
  border: 1px solid currentColor;  /* 글자색과 항상 같은 테두리 */
}

/* 두 색을 섞는다 — Chrome 111+, Safari 16.2+, Firefox 113+ */
.hover {
  background: color-mix(in srgb, #1f5f4f 80%, white);
}

currentColor는 그 요소의 color 값을 가리키는 키워드입니다. 색을 한 곳만 바꾸면 테두리·아이콘이 함께 따라오게 만들 수 있어 유지보수에 좋습니다.

📌 요약

  • px는 물리적 점이 아니라 논리적 단위다.
  • em은 그 요소 기준이라 중첩되면 곱해진다. rem은 루트만 본다.
  • 글자 크기는 rem — 사용자의 브라우저 글꼴 설정을 존중하기 위해.
  • 모바일 전체 화면은 100vh 대신 100dvh.
  • calc()의 +·- 양옆에는 공백 필수.
  • clamp(최소, 선호, 최대)로 미디어 쿼리 없이 반응형 크기를 만든다.
  • 색 조절이 쉬운 hsl, 시각적 밝기가 일치하는 oklch.
