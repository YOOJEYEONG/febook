클로저란

📦 한 문장 정의

함수가 자기 바깥의 변수를 기억하고, 그 함수가 원래 자리를 떠난 뒤에도 계속 쓸 수 있는 것.
함수와 그 함수가 선언될 때의 주변 환경이 함께 묶인 것을 클로저라고 부릅니다.

왜 사라지지 않을까

JavaScript 엔진은 함수가 끝나면 그 지역 변수를 정리합니다. 하지만 누군가 아직 그 변수를 참조하고 있다면 지우지 않습니다.

위 예에서 반환된 함수가 count를 참조하고 있고, 그 함수는 counter 변수에 담겨 살아 있습니다. 그래서 count도 함께 살아남습니다. 클로저는 특별한 문법이 아니라, 스코프 규칙(24장)의 자연스러운 결과입니다.

📸 값이 아니라 변수 자체를 기억합니다

function outer() {
  let value = "처음";
  const read = () => console.log(value);
  value = "나중에 바뀜";
  return read;
}
outer()();   // "나중에 바뀜"  ← 사진을 찍어 둔 게 아닙니다

데이터 은닉

실전 활용

⌨️ 디바운스는 왜 필요한가

검색창에 "자바스크립트"를 입력하면 input 이벤트가 7번 발생합니다. 그때마다 서버에 요청하면 7번의 낭비입니다. 디바운스는 입력이 멈춘 뒤 일정 시간이 지나야 실행합니다. 비슷한 것으로 스로틀(throttle)이 있는데, 이쪽은 일정 간격마다 최대 한 번만 실행합니다. 스크롤 이벤트 처리에 자주 씁니다.

반복문 함정

// ❌ var — 함수 스코프라 i가 하나뿐
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);   // 3, 3, 3
}

// ✅ let — 반복마다 새 바인딩이 만들어짐
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);   // 0, 1, 2
}

// ES6 이전에는 즉시 실행 함수로 스코프를 만들었습니다
for (var i = 0; i < 3; i++) {
  (function (captured) {
    setTimeout(() => console.log(captured), 0);
  })(i);
}

24장에서 본 그 예제입니다. 이제 원리를 설명할 수 있습니다. let은 반복마다 새로운 변수를 만들고, 각 콜백이 자기 차례의 변수를 클로저로 붙잡습니다.

메모리 주의점

🧠 클로저는 참조를 붙잡아 둡니다

function attach() {
  const hugeData = new Array(1_000_000).fill("...");   // 큰 데이터

  document.getElementById("btn").addEventListener("click", () => {
    console.log("클릭");   // hugeData를 쓰지 않지만…
  });
}
// 엔진 최적화에 따라 다르지만, 클로저가 스코프를 붙잡고 있는 한
// 관련 데이터가 해제되지 않을 수 있습니다.

따라서 더 이상 필요 없는 이벤트 리스너는 removeEventListener로 제거하고, 큰 데이터를 클로저 안에 오래 붙잡아 두지 않도록 주의하세요. React에서 useEffect의 정리 함수(61장)가 하는 일이 정확히 이것입니다.

🛠️ 현장 노트 — 여러분은 이미 클로저를 쓰고 있습니다

const items = ["a", "b", "c"];
items.forEach((item) => {
  button.addEventListener("click", () => {
    console.log(item);   // 각 핸들러가 자기 item을 기억 → 클로저
  });
});

React의 useState가 값을 기억하는 것도, 커스텀 훅이 상태를 유지하는 것도 전부 클로저 위에 세워져 있습니다(59·66장). "클로저를 배운다"는 것은 이미 쓰고 있던 것에 이름을 붙이는 일에 가깝습니다.

📌 요약

  • 클로저 = 함수 + 그 함수가 선언될 때의 주변 환경.
  • 바깥 함수가 끝나도 참조가 남아 있으면 변수는 살아 있다.
  • 값의 사본이 아니라 변수 자체를 기억한다.
  • 클로저로 비공개 상태를 만들 수 있다.
  • 실전 패턴: 함수 팩토리, once, 메모이제이션, 디바운스·스로틀.
  • 반복문에서는 let이 매 회차 새 바인딩을 만들어 클로저가 올바르게 동작한다.
  • 불필요한 리스너는 제거해 메모리 누수를 막는다.
