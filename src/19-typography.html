이 챕터에서 배우는 것

  • font-family가 목록인 이유와 시스템 폰트 스택
  • 한글 웹폰트가 영문보다 수십 배 무거운 이유와 해결책
  • font-display로 글꼴 로딩 중 화면을 통제하기
  • 읽기 좋은 행간·글줄 길이의 기준
  • 한글 줄바꿈을 자연스럽게 만드는 word-break: keep-all

읽는 데 약 20분 · 웹의 95%는 글자입니다

font-family는 목록이다

body {
  font-family: "Pretendard", "Apple SD Gothic Neo", "맑은 고딕", sans-serif;
}

브라우저는 앞에서부터 차례로 시도해 사용 가능한 첫 글꼴을 씁니다. 게다가 글자 하나하나마다 따로 판단합니다. 영문 전용 글꼴을 앞에 두면 영어는 그 글꼴로, 한글은 뒤쪽 글꼴로 표시되는 조합이 만들어집니다.

맨 끝에는 반드시 일반 이름(sans-serif, serif, monospace)을 둡니다. 앞의 것이 모두 없을 때 운영체제가 알아서 비슷한 글꼴을 고릅니다.

⚡ 시스템 폰트 스택 — 다운로드 0바이트

운영체제에 이미 설치된 글꼴만 쓰면 웹폰트를 내려받을 필요가 없습니다. 로딩이 즉시 끝나고, 사용자에게 익숙한 모양이며, 용량은 0입니다.

font-family:
  -apple-system,            /* macOS·iOS의 시스템 글꼴 */
  BlinkMacSystemFont,       /* macOS Chrome */
  "Segoe UI",               /* Windows */
  "Apple SD Gothic Neo",    /* macOS 한글 */
  "맑은 고딕", "Malgun Gothic",  /* Windows 한글 */
  system-ui,
  sans-serif;

웹폰트 — 그리고 한글의 문제

@font-face로 직접 불러오기 
@font-face {
  font-family: "MyFont";
  src: url("/fonts/myfont.woff2") format("woff2");
  font-weight: 400;
  font-style: normal;
  font-display: swap;
}

🇰🇷 한글 웹폰트는 영문의 수십 배입니다

영문 글꼴은 알파벳 대소문자 52자 + 숫자·기호로 200~300자면 충분합니다. 파일은 보통 20~50KB.

한글은 다릅니다. 완성형 한글만 11,172자이고 한자·기호까지 넣으면 훨씬 늘어납니다. 글꼴 하나에 굵기가 여러 개면 그만큼 곱해집니다. 한글 웹폰트 한 벌이 수 MB에 이르는 경우가 흔합니다. 아무 생각 없이 넣으면 페이지에서 가장 무거운 자원이 됩니다.

해결책

방법내용
woff2 사용웹 전용 압축 포맷. ttf·otf 대비 30~50% 작습니다. 모든 현대 브라우저가 지원하므로 woff2 하나만 넣으면 됩니다
서브셋실제로 쓰는 글자만 남기고 잘라냅니다. 한자·특수문자를 빼는 것만으로 크게 줄어듭니다
unicode-range 분할글꼴을 문자 범위별 여러 파일로 나누면 페이지에 실제로 등장한 범위만 내려받습니다. 구글 폰트의 한글 글꼴이 이 방식을 씁니다
굵기 줄이기400·700 두 가지면 대부분 충분합니다. 굵기 6종을 다 넣지 마세요
가변 폰트한 파일에 모든 굵기가 들어 있습니다. 여러 굵기를 쓴다면 오히려 총량이 줄어듭니다

font-display — 로딩 중 무엇을 보여줄까

웹폰트를 내려받는 동안 브라우저는 선택해야 합니다. 글자를 감출까(FOIT), 대체 글꼴로 먼저 보여줄까(FOUT)?

값동작평가
auto브라우저에 맡김대개 글자가 잠깐 안 보입니다
block최대 약 3초간 글자를 감춤내용을 못 읽는 시간이 생깁니다
swap즉시 대체 글꼴로 보여주고, 도착하면 교체대부분의 경우 권장. 글자가 바뀌며 살짝 흔들립니다
fallback아주 짧게 감췄다가 대체 글꼴. 늦게 오면 교체하지 않음절충안
optional느리면 아예 포기하고 대체 글꼴 유지성능 최우선일 때

swap을 쓰면 글꼴이 바뀌는 순간 글자 크기 차이로 레이아웃이 흔들립니다(CLS). 대체 글꼴의 크기를 실제 글꼴에 맞춰 미세 조정하는 속성이 있습니다.

@font-face {
  font-family: "Fallback";
  src: local("Apple SD Gothic Neo");
  size-adjust: 96%;          /* 크기 보정 */
  ascent-override: 90%;      /* 위쪽 여백 보정 */
}

Chrome 87+, Firefox 89+, Safari 17+에서 지원됩니다. 또 가장 중요한 글꼴 한 벌은 미리 받아두면 교체 시점이 빨라집니다.

<link rel="preload" href="/fonts/main.woff2" as="font"
      type="font/woff2" crossorigin>

crossorigin 속성은 같은 도메인이어도 반드시 필요합니다. 글꼴은 CORS 규칙이 적용되는 자원이라, 빠뜨리면 미리 받은 파일을 못 쓰고 두 번 내려받습니다.

읽기 좋은 글의 조건

항목권장이유
본문 크기16~18px16px 미만은 모바일에서 읽기 힘들고, iOS Safari는 16px 미만 입력 칸에서 자동 확대합니다
행간1.5~1.9 (단위 없이)한글은 영문보다 글자가 빽빽해 더 넉넉한 행간이 필요합니다
글줄 길이45~75자 (max-width: 65ch)너무 길면 다음 줄 첫머리를 찾기 어려워집니다
자간본문은 0, 큰 제목은 -0.02em 정도큰 글자는 자간이 넓어 보입니다
정렬text-align: left양쪽 정렬은 단어 사이 간격이 들쭉날쭉해져 난독 사용자에게 특히 불리합니다

📐 line-height에 단위를 붙이지 마세요

body { font-size: 16px; line-height: 24px; }  /* ❌ 계산된 24px가 그대로 상속 */
h1   { font-size: 40px; }                     /* → 40px 글자에 24px 행간. 겹칩니다 */

body { font-size: 16px; line-height: 1.5; }   /* ✅ 비율이 상속 */
h1   { font-size: 40px; }                     /* → 40 × 1.5 = 60px. 자동으로 맞음 */

한글 줄바꿈

브라우저의 기본 줄바꿈 규칙은 영문 기준입니다. 영어는 단어 사이 공백에서 끊지만, 한글은 공백이 없어도 아무 글자 사이에서 끊습니다. 그래서 "프론트엔"에서 줄이 바뀌는 어색한 결과가 나옵니다.

body {
  word-break: keep-all;        /* 한글 단어(어절) 중간에서 끊지 않음 */
  overflow-wrap: break-word;   /* 단, 한 어절이 너무 길면 강제로 끊어 넘침 방지 */
}

text-wrap

h1 { text-wrap: balance; }  /* 제목의 각 줄 길이를 고르게 — 최대 몇 줄까지 */
p  { text-wrap: pretty; }   /* 마지막 줄에 단어 하나만 남는 것을 방지 */

balance는 Chrome 114+, Safari 17.5+, Firefox 121+에서 지원됩니다. 제목이 "긴 제목이 두 줄로 나뉘는데 둘째 줄에 한 단어만" 남는 문제를 해결합니다. 지원하지 않는 브라우저는 이 선언을 무시할 뿐이므로 안전하게 넣어도 됩니다.

말줄임

/* 한 줄 말줄임 */
.one-line {
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;      /* 세 줄이 모두 있어야 동작합니다 */
}

/* 여러 줄 말줄임 */
.multi-line {
  display: -webkit-box;
  -webkit-line-clamp: 3;    /* 3줄까지 */
  -webkit-box-orient: vertical;
  overflow: hidden;
}

여러 줄 말줄임은 -webkit- 접두사가 붙어 있지만 모든 주요 브라우저가 지원합니다. 표준 line-clamp 속성도 도입되고 있으니 두 줄을 함께 써 두면 좋습니다.

✂️ 말줄임은 정보를 감춥니다

잘린 글자는 사용자가 볼 수 없습니다. 중요한 정보(상품명, 오류 메시지)를 자르면 안 됩니다. 잘라야만 한다면 title 속성이나 툴팁으로 전체 내용을 볼 수 있게 해 주세요.

🛠️ 현장 노트 — 한국 웹 프로젝트의 표준 시작 세트

html {
  font-size: 16px;
}
body {
  font-family: "Pretendard Variable", Pretendard, -apple-system,
               "Apple SD Gothic Neo", "맑은 고딕", sans-serif;
  line-height: 1.7;
  word-break: keep-all;
  overflow-wrap: break-word;
  -webkit-font-smoothing: antialiased;  /* macOS에서 글자가 지나치게 두꺼워지는 것 완화 */
}
button, input, select, textarea { font: inherit; }
p { max-width: 70ch; }

📌 요약

  • font-family는 목록이며 글자 단위로 판단된다. 끝에 일반 이름을 꼭 둔다.
  • 시스템 폰트 스택은 다운로드 0바이트다.
  • 한글 웹폰트는 글자 수 때문에 매우 무겁다. woff2 + 서브셋 + 굵기 최소화가 필수.
  • font-display: swap이 대체로 정답. preload에는 crossorigin 필수.
  • line-height는 단위 없이. 한글은 1.5~1.9가 편하다.
  • 글줄은 45~75자(max-width: 65ch).
  • 한글에는 word-break: keep-all을 넣는다.
  • 말줄임은 정보를 감춘다. 중요한 내용에는 쓰지 않는다.
