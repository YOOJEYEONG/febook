문서의 기본 골격

모든 HTML 문서는 이 뼈대에서 시작합니다. 지금은 외우지 말고 각 줄이 왜 있는지만 이해하세요.

index.html 
<!doctype html>
<html lang="ko">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>내 첫 페이지</title>
  </head>
  <body>
    <h1>안녕하세요</h1>
    <p>첫 번째 문단입니다.</p>
  </body>
</html>
줄없으면 무슨 일이
<!doctype html>브라우저가 호환 모드(quirks mode)로 전환됩니다. 1990년대 낡은 규칙으로 화면을 그려서 CSS가 예상과 다르게 동작합니다. 반드시 첫 줄에 있어야 합니다
lang="ko"스크린 리더가 어느 언어로 읽을지 모릅니다. 한글을 영어 발음으로 읽는 사고가 납니다. 검색엔진과 브라우저 번역 기능도 이 값을 봅니다
<meta charset="utf-8">한글이 깨집니다. 문자를 어떤 방식으로 해석할지 알려주는 선언입니다. <head> 안에서 가능한 한 앞쪽에 둡니다
viewport meta휴대폰에서 PC 화면을 축소한 것처럼 보입니다. 글자가 개미만 해집니다. 반응형의 출발점입니다(18장)
<title>브라우저 탭 제목, 북마크 이름, 검색 결과 제목이 비어 버립니다

head와 body

  • <head> — 화면에 보이지 않는 정보. 제목, 문자 인코딩, CSS 연결, 검색용 설명 등.
  • <body> — 화면에 보이는 모든 내용.

태그, 요소, 속성

세 단어를 정확히 구분해서 쓰면 앞으로 문서를 읽기 훨씬 쉬워집니다.

용어 구분 
<a href="https://example.com" target="_blank">예제 사이트</a>
│                                            │           │
└─ 여는 태그 ────────────────────────────────┘  내용      └─ 닫는 태그

   속성 이름 ─┘        └─ 속성 값

<a> 부터 </a> 까지 전체 = "a 요소(element)"
  • 태그 — <a>, </a> 처럼 꺾쇠로 감싼 표시 자체.
  • 요소 — 여는 태그부터 닫는 태그까지, 내용을 포함한 덩어리 전체.
  • 속성 — 여는 태그 안에 적는 추가 설정. 이름="값" 형태.

속성 작성 규칙

  • 속성은 여는 태그에만 씁니다. 닫는 태그에는 쓰지 않습니다.
  • 값은 따옴표로 감싸는 것을 권장합니다. 문법상 생략 가능한 경우도 있지만, 값에 공백이 들어가면 즉시 깨집니다.
  • 태그 이름과 속성 이름은 대소문자를 구분하지 않지만, 관행적으로 소문자로 씁니다.
  • 값이 필요 없는 속성도 있습니다. <input required>처럼 있으면 참, 없으면 거짓인 불리언 속성입니다. required="false"라고 써도 참이 되니 주의하세요. 끄려면 속성 자체를 지워야 합니다.

⚠️ required="false"는 참입니다

불리언 속성은 존재 여부만 봅니다. 값은 무시됩니다. disabled="false", checked="no" 전부 켜진 상태가 됩니다. 초보자가 가장 많이 빠지는 함정 중 하나입니다.

닫는 태그가 없는 요소

내용을 담을 수 없는 요소는 닫는 태그가 없습니다. 빈 요소(void element)라고 부릅니다.

대표적인 빈 요소 
<br>                              <!-- 줄바꿈 -->
<hr>                              <!-- 구분선 -->
<img src="cat.jpg" alt="고양이">  <!-- 이미지 -->
<input type="text">               <!-- 입력 칸 -->
<meta charset="utf-8">            <!-- 메타 정보 -->
<link rel="stylesheet" href="style.css">  <!-- 외부 파일 연결 -->

<br />처럼 끝에 슬래시를 붙인 코드도 자주 봅니다. HTML에서는 있어도 없어도 똑같이 동작합니다. XHTML이라는 옛 규격의 흔적이고, 지금은 JSX(React)에서 필수라서 습관적으로 붙이는 사람이 많습니다.

중첩 규칙

요소 안에 요소를 넣을 수 있습니다. 단 순서를 지켜 열고 닫아야 합니다.

중첩 
<!-- 올바름: 나중에 연 것을 먼저 닫는다 -->
<p>이것은 <strong>중요한</strong> 내용입니다.</p>

<!-- 잘못됨: 순서가 엇갈림 -->
<p>이것은 <strong>중요한</p></strong>

부모·자식·형제라는 말도 여기서 나옵니다. 위 예에서 p는 strong의 부모, strong은 p의 자식입니다. 이 관계는 CSS 선택자(12장)와 DOM 조작(38장)에서 계속 쓰입니다.

🩹 브라우저는 틀린 HTML을 고쳐서 읽는다

HTML은 관대합니다. 태그를 잘못 닫아도 브라우저가 알아서 고쳐서 DOM을 만듭니다. 에러 화면을 띄우지 않습니다. 이게 장점이자 함정입니다.

화면이 멀쩡해 보여도 구조는 엉망일 수 있습니다. 그러면 CSS 선택자가 예상과 다르게 걸리고, JavaScript가 엉뚱한 요소를 잡습니다. 개발자 도구 Elements 탭에서 실제 DOM을 확인하는 습관이 필요합니다(5장).

또 아무 요소나 아무 데나 넣을 수는 없습니다. 대표적인 규칙 두 가지만 기억하세요.

  • <p> 안에 <div>를 넣을 수 없습니다. 넣으면 브라우저가 <p>를 강제로 닫아 버립니다.
  • <ul>·<ol>의 직계 자식은 <li>여야 합니다.

주석

HTML 주석 
<!-- 이 부분은 화면에 나오지 않습니다 -->

⚠️ 주석은 숨기는 수단이 아닙니다

주석은 화면에만 안 보일 뿐, 소스 보기를 하면 그대로 보입니다. 주석 안에 개발용 계정 정보나 아직 공개하면 안 되는 내용을 남기면 그대로 유출됩니다. 실제로 자주 발생하는 정보 노출 사고입니다.

공백은 하나로 합쳐진다

HTML에서 연속된 공백·줄바꿈·탭은 전부 공백 하나로 취급됩니다.

문자 엔티티 — 특수문자 쓰기

<는 태그의 시작을 뜻하는 예약된 문자입니다. 그래서 화면에 <를 보여주고 싶으면 그대로 쓸 수 없고 엔티티를 씁니다.

표시하고 싶은 문자이렇게 쓴다왜
<&lt;태그 시작으로 오해되므로
>&gt;태그 끝으로 오해되므로
&&amp;엔티티 시작 문자이므로
"&quot;속성 값 안에서 필요할 때
줄바꿈 안 되는 공백&nbsp;이 공백에서는 줄이 안 넘어감

🛠️ 현장 노트

이 규칙은 단순한 표기법이 아니라 보안의 핵심입니다. 사용자가 입력한 글을 화면에 그대로 붙이는데, 그 안에 <script>가 들어 있다면? 브라우저는 진짜 스크립트로 실행합니다. 이것이 XSS 공격입니다. 그래서 사용자 입력을 화면에 넣을 때는 반드시 <·&를 엔티티로 바꿔야(이스케이프) 합니다. 78장에서 자세히 다룹니다. 다행히 React 같은 도구는 이 처리를 기본으로 해 줍니다.

블록과 인라인

요소는 화면에서 차지하는 방식이 크게 두 가지로 나뉩니다. 정확히는 CSS의 display 기본값이지만(13장), 지금 감을 잡아 두면 좋습니다.

블록 (block)인라인 (inline)
줄혼자 한 줄을 차지글자처럼 옆으로 나열
너비기본적으로 가로 전체내용만큼만
크기 지정가능너비·높이 지정이 먹히지 않음
예div, p, h1~h6, ul, li, sectionspan, a, strong, em, img

🚫 자주 하는 오해

오해 — HTML은 프로그래밍 언어이고, 잘못 쓰면 에러가 난다. 사실 — HTML에는 조건문도 반복문도 없어 프로그래밍 언어가 아니며, 문법이 틀려도 에러를 띄우지 않습니다. 브라우저는 어떻게든 화면을 그립니다. "에러가 안 났으니 맞게 썼다"는 판단이 통하지 않는다는 뜻입니다. 그래서 W3C 검사기 같은 도구로 따로 확인해야 합니다.

📌 요약

  • 문서는 <!doctype html>로 시작한다. 없으면 옛 호환 모드로 동작한다.
  • lang, charset, viewport, title은 매 문서에 꼭 들어간다.
  • 태그는 표시, 요소는 덩어리 전체, 속성은 여는 태그 안의 설정.
  • 불리언 속성은 존재 여부만 본다. required="false"도 참이다.
  • 빈 요소(br, img, input…)는 닫는 태그가 없다.
  • 브라우저는 틀린 HTML도 고쳐서 그린다. 화면이 멀쩡해도 구조는 틀릴 수 있다.
  • 연속 공백은 하나로 합쳐진다. 예외는 <pre>.
  • &lt; 같은 엔티티는 표기법이자 XSS 방어의 기본이다.
