작업 환경 만들기

코드는 글자만 적힌 파일입니다. 특별한 프로그램 없이도 만들 수 있지만, 처음부터 코드 편집기를 쓰는 편이 실수가 훨씬 적습니다. 이 책은 무료 편집기 VS Code(Visual Studio Code)를 기준으로 설명합니다. 아래 다섯 단계를 한 번만 해 두면 이 책의 모든 실습을 같은 방식으로 할 수 있습니다.

🧪 본문의 실행기만으로도 충분할 때

이 책의 회색 실행기 상자는 브라우저 안에서 바로 코드를 고쳐 실행해 볼 수 있습니다. 짧은 실험은 실행기로 하고, 파일로 남기고 싶은 연습은 아래처럼 내 컴퓨터에 만드세요. 실무는 언제나 후자입니다.

1단계 — VS Code 설치

  1. code.visualstudio.com에 접속해 Download 버튼을 누릅니다. 운영체제에 맞는 파일이 자동으로 골라집니다.
  2. Windows — 받은 설치 파일(VSCodeUserSetup-….exe)을 실행하고 다음을 누릅니다. "추가 작업 선택" 화면에서 "PATH에 추가"(기본으로 켜져 있음)와 탐색기의 오른쪽 클릭 메뉴에 "Code(으)로 열기"를 추가하는 항목 두 개를 켜 두면 편합니다.
  3. macOS — 받은 압축 파일을 열면 나오는 Visual Studio Code 앱을 응용 프로그램(Applications) 폴더로 끌어다 놓습니다. 다운로드 폴더에서 바로 실행하면 업데이트가 제대로 되지 않습니다.
  4. 메뉴를 한국어로 보고 싶다면 VS Code 왼쪽의 확장(Extensions, 블록 4개 모양) 아이콘을 눌러 Korean Language Pack을 설치하고 VS Code를 다시 시작합니다. 영어 그대로 써도 무방합니다.

✅ 체크포인트 — VS Code를 실행하면 "시작(Welcome)" 탭이 있는 창이 열립니다.

2단계 — 작업 폴더 만들고 열기

  1. 바탕화면(또는 문서 폴더)에 my-first-site라는 새 폴더를 만듭니다. 폴더 이름은 영문 소문자와 하이픈(-)으로 짓는 습관을 들이세요. 한글·공백이 든 경로는 나중에 터미널(44장)과 도구에서 자주 말썽을 일으킵니다.
  2. VS Code 메뉴에서 파일 → 폴더 열기(File → Open Folder…)를 누르고 방금 만든 폴더를 고릅니다.
  3. "이 폴더에 있는 파일의 작성자를 신뢰합니까?"라는 창이 뜨면, 내가 만든 폴더이므로 "예, 작성자를 신뢰합니다"를 누릅니다.

✅ 체크포인트 — 왼쪽 탐색기(Explorer) 패널 맨 위에 MY-FIRST-SITE라는 폴더 이름이 대문자로 보입니다. 안 보이면 왼쪽 맨 위 문서 두 장 모양 아이콘을 누르세요.

3단계 — 새 파일 만들고 저장하기

  1. 탐색기 패널의 폴더 이름 옆에 마우스를 올리면 나타나는 새 파일 아이콘(종이에 + 표시)을 누릅니다.
  2. 이름을 index.html로 입력하고 Enter를 누릅니다. 오른쪽에 빈 편집 화면이 열립니다.
  3. 아래 기본 골격 코드를 그대로 입력하거나 복사해 붙여 넣습니다.
  4. 저장합니다. Windows는 Ctrl+S, macOS는 Cmd+S.

✅ 체크포인트 — 편집 탭의 파일 이름 옆에 있던 동그라미(●)가 사라지면 저장된 것입니다. 동그라미가 남아 있으면 아직 저장 안 된 변경이 있다는 뜻입니다. 코드 글자가 태그·속성별로 색깔이 다르게 보이면 VS Code가 HTML 파일로 제대로 인식한 것입니다.

🪤 index.html.txt 함정 — 파일 이름 끝을 확인하세요

Windows 메모장으로 저장하면 이름을 index.html로 적어도 실제로는 index.html.txt로 저장되는 일이 흔합니다. 이 파일은 브라우저에서 웹 페이지가 아니라 글자 그대로 보입니다. (메모장을 꼭 써야 한다면 저장 창의 "파일 형식"을 모든 파일로 바꾸세요. macOS 텍스트 편집기는 기본이 서식 있는 문서(.rtf)라서 포맷 → 일반 텍스트로 만들기를 먼저 해야 합니다.) VS Code로 만들면 이 문제가 없습니다.

문제는 Windows와 macOS 모두 확장자를 기본으로 숨긴다는 점입니다. 지금 바로 켜 두세요.
· Windows 11 — 파일 탐색기 위쪽 보기 → 표시 → 파일 확장명 체크
· Windows 10 — 파일 탐색기 보기 탭 → 파일 확장명 체크
· macOS — Finder 메뉴 설정(환경설정) → 고급 → 모든 파일 확장자 보기 체크

4단계 — 브라우저로 열고 새로고침하기

  1. 파일 탐색기(또는 Finder)에서 index.html을 더블클릭합니다. 기본 브라우저로 열립니다. 열리지 않거나 다른 프로그램이 뜨면 파일을 Chrome 창 위로 끌어다 놓아도 됩니다.
  2. VS Code로 돌아와 <h1> 안의 글자를 바꾸고 저장합니다.
  3. 브라우저로 돌아와 새로고침합니다. Windows는 F5(또는 Ctrl+R), macOS는 Cmd+R.

✅ 체크포인트 — 화면에 큰 글씨 "안녕하세요"가 보이고, 브라우저 탭 제목이 "내 첫 페이지"입니다. 주소창은 file:///C:/Users/…/index.html(Windows) 또는 file:///Users/…/index.html(macOS)처럼 file://로 시작합니다. 글자를 바꿨는데 화면이 그대로라면 ① 저장했는지(●) ② 새로고침했는지 두 가지를 먼저 확인하세요. 초보자가 막히는 원인의 대부분이 이것입니다.

🔁 수정 → 저장 → 새로고침

앞으로 HTML·CSS를 배우는 동안 이 세 동작을 수천 번 반복하게 됩니다. 브라우저는 파일이 바뀌어도 스스로 다시 읽지 않습니다. 저장할 때마다 자동으로 새로고침되기를 원하면 나중에 VS Code 확장 Live Server나 로컬 서버(44장)를 쓰면 됩니다. 지금은 손으로 새로고침하는 것으로 충분합니다.

5단계 — 개발자 도구 열어 보기

브라우저에는 페이지의 속을 들여다보는 개발자 도구가 들어 있습니다. 열어 보기만 해 두세요.

  • Windows — F12 또는 Ctrl+Shift+I
  • macOS — Cmd+Option+I
  • 또는 페이지의 아무 곳이나 마우스 오른쪽 클릭 → 검사(Inspect)

✅ 체크포인트 — 화면 옆이나 아래에 패널이 열리고, Elements(요소) 탭에 내가 쓴 <html>, <head>, <body>가 접었다 폈다 할 수 있는 형태로 보입니다. 지금은 "여기서 실제 구조를 볼 수 있다"는 것만 알면 됩니다. 자세한 사용법은 49장에서 다룹니다.

🛠️ 현장 노트 — 골격을 빠르게 만드는 단축 입력

VS Code에서 빈 .html 파일에 ! 한 글자를 치고 Tab(또는 Enter)을 누르면 아래 골격이 자동으로 채워집니다(Emmet 기능). 실무자는 거의 이렇게 시작합니다. 다만 자동 생성된 골격은 lang="en"이므로 lang="ko"로 바꾸는 것을 잊지 마세요. 처음 몇 번은 손으로 직접 쳐 보는 것을 권합니다. 각 줄의 의미가 손에 남습니다.

문서의 기본 골격

모든 HTML 문서는 이 뼈대에서 시작합니다. 위에서 만든 index.html에 이 코드를 넣고 저장한 뒤 브라우저로 열어 보세요. 지금은 외우지 말고 각 줄이 왜 있는지만 이해하세요.

index.html 
<!doctype html>
<html lang="ko">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>내 첫 페이지</title>
  </head>
  <body>
    <h1>안녕하세요</h1>
    <p>첫 번째 문단입니다.</p>
  </body>
</html>
줄없으면 무슨 일이
<!doctype html>브라우저가 호환 모드(quirks mode)로 전환됩니다. 1990년대 낡은 규칙으로 화면을 그려서 CSS가 예상과 다르게 동작합니다. 반드시 첫 줄에 있어야 합니다
lang="ko"스크린 리더가 어느 언어로 읽을지 모릅니다. 한글을 영어 발음으로 읽는 사고가 납니다. 검색엔진과 브라우저 번역 기능도 이 값을 봅니다
<meta charset="utf-8">한글이 깨집니다. 문자를 어떤 방식으로 해석할지 알려주는 선언입니다. <head> 안에서 가능한 한 앞쪽에 둡니다
viewport meta휴대폰에서 PC 화면을 축소한 것처럼 보입니다. 글자가 개미만 해집니다. 반응형의 출발점입니다(18장)
<title>브라우저 탭 제목, 북마크 이름, 검색 결과 제목이 비어 버립니다

head와 body

  • <head> — 화면에 보이지 않는 정보. 제목, 문자 인코딩, CSS 연결, 검색용 설명 등.
  • <body> — 화면에 보이는 모든 내용.

태그, 요소, 속성

세 단어를 정확히 구분해서 쓰면 앞으로 문서를 읽기 훨씬 쉬워집니다.

용어 구분 
<a href="https://example.com" target="_blank">예제 사이트</a>
│                                            │           │
└─ 여는 태그 ────────────────────────────────┘  내용      └─ 닫는 태그

   속성 이름 ─┘        └─ 속성 값

<a> 부터 </a> 까지 전체 = "a 요소(element)"
  • 태그 — <a>, </a> 처럼 꺾쇠로 감싼 표시 자체.
  • 요소 — 여는 태그부터 닫는 태그까지, 내용을 포함한 덩어리 전체.
  • 속성 — 여는 태그 안에 적는 추가 설정. 이름="값" 형태.

속성 작성 규칙

  • 속성은 여는 태그에만 씁니다. 닫는 태그에는 쓰지 않습니다.
  • 값은 따옴표로 감싸는 것을 권장합니다. 문법상 생략 가능한 경우도 있지만, 값에 공백이 들어가면 즉시 깨집니다.
  • 태그 이름과 속성 이름은 대소문자를 구분하지 않지만, 관행적으로 소문자로 씁니다.
  • 값이 필요 없는 속성도 있습니다. <input required>처럼 있으면 참, 없으면 거짓인 불리언 속성입니다. required="false"라고 써도 참이 되니 주의하세요. 끄려면 속성 자체를 지워야 합니다.

⚠️ required="false"는 참입니다

불리언 속성은 존재 여부만 봅니다. 값은 무시됩니다. disabled="false", checked="no" 전부 켜진 상태가 됩니다. 초보자가 가장 많이 빠지는 함정 중 하나입니다.

닫는 태그가 없는 요소

내용을 담을 수 없는 요소는 닫는 태그가 없습니다. 빈 요소(void element)라고 부릅니다.

대표적인 빈 요소 
<br>                              <!-- 줄바꿈 -->
<hr>                              <!-- 구분선 -->
<img src="cat.jpg" alt="고양이">  <!-- 이미지 -->
<input type="text">               <!-- 입력 칸 -->
<meta charset="utf-8">            <!-- 메타 정보 -->
<link rel="stylesheet" href="style.css">  <!-- 외부 파일 연결 -->

<br />처럼 끝에 슬래시를 붙인 코드도 자주 봅니다. HTML에서는 있어도 없어도 똑같이 동작합니다. XHTML이라는 옛 규격의 흔적이고, 지금은 JSX(React)에서 필수라서 습관적으로 붙이는 사람이 많습니다.

중첩 규칙

요소 안에 요소를 넣을 수 있습니다. 단 순서를 지켜 열고 닫아야 합니다.

중첩 
<!-- 올바름: 나중에 연 것을 먼저 닫는다 -->
<p>이것은 <strong>중요한</strong> 내용입니다.</p>

<!-- 잘못됨: 순서가 엇갈림 -->
<p>이것은 <strong>중요한</p></strong>

부모·자식·형제라는 말도 여기서 나옵니다. 위 예에서 p는 strong의 부모, strong은 p의 자식입니다. 이 관계는 CSS 선택자(12장)와 DOM 조작(38장)에서 계속 쓰입니다.

🩹 브라우저는 틀린 HTML을 고쳐서 읽는다

HTML은 관대합니다. 태그를 잘못 닫아도 브라우저가 알아서 고쳐서 DOM을 만듭니다. 에러 화면을 띄우지 않습니다. 이게 장점이자 함정입니다.

화면이 멀쩡해 보여도 구조는 엉망일 수 있습니다. 그러면 CSS 선택자가 예상과 다르게 걸리고, JavaScript가 엉뚱한 요소를 잡습니다. 개발자 도구 Elements 탭에서 실제 DOM을 확인하는 습관이 필요합니다(5장).

또 아무 요소나 아무 데나 넣을 수는 없습니다. 대표적인 규칙 두 가지만 기억하세요.

  • <p> 안에 <div>를 넣을 수 없습니다. 넣으면 브라우저가 <p>를 강제로 닫아 버립니다.
  • <ul>·<ol>의 직계 자식은 <li>여야 합니다.

주석

HTML 주석 
<!-- 이 부분은 화면에 나오지 않습니다 -->

⚠️ 주석은 숨기는 수단이 아닙니다

주석은 화면에만 안 보일 뿐, 소스 보기를 하면 그대로 보입니다. 주석 안에 개발용 계정 정보나 아직 공개하면 안 되는 내용을 남기면 그대로 유출됩니다. 실제로 자주 발생하는 정보 노출 사고입니다.

공백은 하나로 합쳐진다

HTML에서 연속된 공백·줄바꿈·탭은 전부 공백 하나로 취급됩니다.

문자 엔티티 — 특수문자 쓰기

<는 태그의 시작을 뜻하는 예약된 문자입니다. 그래서 화면에 <를 보여주고 싶으면 그대로 쓸 수 없고 엔티티를 씁니다.

표시하고 싶은 문자이렇게 쓴다왜
<&lt;태그 시작으로 오해되므로
>&gt;태그 끝으로 오해되므로
&&amp;엔티티 시작 문자이므로
"&quot;속성 값 안에서 필요할 때
줄바꿈 안 되는 공백&nbsp;이 공백에서는 줄이 안 넘어감

🛠️ 현장 노트

이 규칙은 단순한 표기법이 아니라 보안의 핵심입니다. 사용자가 입력한 글을 화면에 그대로 붙이는데, 그 안에 <script>가 들어 있다면? 브라우저는 진짜 스크립트로 실행합니다. 이것이 XSS 공격입니다. 그래서 사용자 입력을 화면에 넣을 때는 반드시 <·&를 엔티티로 바꿔야(이스케이프) 합니다. 78장에서 자세히 다룹니다. 다행히 React 같은 도구는 이 처리를 기본으로 해 줍니다.

블록과 인라인

요소는 화면에서 차지하는 방식이 크게 두 가지로 나뉩니다. 정확히는 CSS의 display 기본값이지만(13장), 지금 감을 잡아 두면 좋습니다.

블록 (block)인라인 (inline)
줄혼자 한 줄을 차지글자처럼 옆으로 나열
너비기본적으로 가로 전체내용만큼만
크기 지정가능너비·높이 지정이 먹히지 않음
예div, p, h1~h6, ul, li, sectionspan, a, strong, em, img

🚫 자주 하는 오해

오해 — HTML은 프로그래밍 언어이고, 잘못 쓰면 에러가 난다. 사실 — HTML에는 조건문도 반복문도 없어 프로그래밍 언어가 아니며, 문법이 틀려도 에러를 띄우지 않습니다. 브라우저는 어떻게든 화면을 그립니다. "에러가 안 났으니 맞게 썼다"는 판단이 통하지 않는다는 뜻입니다. 그래서 W3C 검사기 같은 도구로 따로 확인해야 합니다.

📌 요약

  • 문서는 <!doctype html>로 시작한다. 없으면 옛 호환 모드로 동작한다.
  • lang, charset, viewport, title은 매 문서에 꼭 들어간다.
  • 태그는 표시, 요소는 덩어리 전체, 속성은 여는 태그 안의 설정.
  • 불리언 속성은 존재 여부만 본다. required="false"도 참이다.
  • 빈 요소(br, img, input…)는 닫는 태그가 없다.
  • 브라우저는 틀린 HTML도 고쳐서 그린다. 화면이 멀쩡해도 구조는 틀릴 수 있다.
  • 연속 공백은 하나로 합쳐진다. 예외는 <pre>.
  • &lt; 같은 엔티티는 표기법이자 XSS 방어의 기본이다.
