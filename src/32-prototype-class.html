이상한 점을 하나 짚어 봅시다. 우리는 map을 만든 적이 없는데 모든 배열이 map을 가지고 있습니다. 어디서 왔을까요?

🔗 프로토타입 체인 한 줄 요약

객체에서 속성을 찾을 때, 자기 것에 없으면 프로토타입으로 올라가며 찾습니다. 끝까지 없으면 undefined. 이 연결 고리가 프로토타입 체인입니다.
24장의 스코프 체인이 "변수"를 찾는 사슬이라면, 프로토타입 체인은 "속성"을 찾는 사슬입니다. 구조가 닮았습니다.

class 문법

예전 방식과 현재 방식 
// ES5 이전: 생성자 함수 + prototype
function PersonOld(name) {
  this.name = name;
}
PersonOld.prototype.greet = function () {
  return this.name + "입니다";
};

// ES2015 이후: class
class Person {
  constructor(name) {
    this.name = name;
  }
  greet() {
    return this.name + "입니다";
  }
}

🍬 class는 "문법 설탕"입니다

오해 — JavaScript에 클래스 기반 객체지향이 새로 도입되었다. 사실 — 동작은 프로토타입 그대로입니다. class는 위의 생성자 함수 + prototype 코드를 읽기 좋게 쓰는 문법일 뿐입니다. typeof Person은 여전히 "function"이고, 메서드는 Person.prototype에 들어갑니다. 다만 완전히 같지는 않습니다. class는 항상 엄격 모드로 동작하고, new 없이 호출하면 오류가 나며, 호이스팅되어도 TDZ에 걸립니다. 이 차이들은 대부분 실수를 막아 주는 방향입니다.

클래스의 구성 요소

🔒 # 비공개 필드

이름 앞에 #를 붙이면 클래스 밖에서 접근할 수 없습니다. 관례상 _name처럼 밑줄을 붙이던 옛 방식과 달리 문법적으로 강제됩니다. Chrome 74+, Safari 14.1+, Firefox 90+, Node 12+에서 지원됩니다.

상속

instanceof와 타입 판별

dog instanceof Dog;          // true — 프로토타입 체인에 Dog.prototype이 있는가

// ⚠️ 배열 판별에 instanceof를 쓰지 마세요
arr instanceof Array;        // 대개 true지만, iframe 등 다른 실행 환경의
                             // 배열에는 false가 됩니다
Array.isArray(arr);          // ✅ 항상 정확

클래스를 언제 쓸까

🛠️ 현장 노트 — 현대 프론트엔드에서의 위치

React를 쓴다면 클래스를 직접 만들 일이 거의 없습니다. 과거에는 클래스 컴포넌트가 표준이었지만, 2019년 훅이 나온 뒤로는 함수형이 사실상 표준입니다. 상태와 로직은 커스텀 훅(66장)으로 재사용합니다.

🪜 상속을 깊게 만들지 마세요

3단계 이상 상속은 어디서 온 메서드인지 추적하기 어려워집니다. 부모를 고치면 모든 자식이 영향을 받아 변경도 위험해집니다. 현대적인 조언은 "상속보다 합성(composition)"입니다. 클래스를 물려받기보다, 필요한 기능을 가진 객체를 안에 담아 쓰는 방식이 대체로 더 유연합니다. React가 상속을 쓰지 않고 컴포넌트를 조립하는 방식을 택한 것도 같은 이유입니다(63장).

📌 요약

  • 객체는 속성을 찾을 때 프로토타입 체인을 따라 올라간다. 끝은 null.
  • [1,2].map은 Array.prototype에 있다.
  • class는 프로토타입 위에 얹은 문법 설탕이다. 동작 원리는 그대로다.
  • 단, class는 항상 엄격 모드이고 new 없이 호출할 수 없다.
  • 메서드는 prototype에 한 벌만 존재한다. 인스턴스마다 복제되지 않는다.
  • # 비공개 필드는 문법적으로 강제되는 은닉이다.
  • extends + super(). super()는 this보다 먼저.
  • 배열 판별은 instanceof가 아니라 Array.isArray().
  • 상속보다 합성. React를 쓴다면 클래스를 직접 만들 일이 드물다.
