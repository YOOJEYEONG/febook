이 챕터에서 배우는 것

  • 배운 것을 실제로 조립하는 경험
  • 난이도가 올라가는 세 개의 프로젝트
  • 각 단계에서 어느 챕터를 다시 볼지
  • 포트폴리오로 다듬는 법

✋ 이 챕터는 읽는 챕터가 아닙니다

읽기만 하면 아무 의미가 없습니다. 지금까지 80개 챕터를 읽었다면, 이제 필요한 것은 직접 막히고 직접 검색하고 직접 고치는 시간입니다. 튜토리얼을 따라 치는 것과 요구사항만 보고 스스로 만드는 것은 완전히 다른 경험입니다.
아래는 정답 코드가 아니라 요구사항입니다. 의도적으로 코드를 거의 넣지 않았습니다.

🎯 스스로 점검할 것

  • key에 인덱스를 쓰지 않았는가(60장) — 항목을 삭제해 보면 압니다
  • 상태를 직접 수정하지 않았는가(59장) — push·splice 금지
  • 남은 개수를 별도 상태로 두지 않았는가(59장)
  • localStorage 접근을 try/catch로 감쌌는가(39장)
  • 입력 칸에 연결된 label이 있는가(9장)

⬆️ 여유가 되면

  • 수정 기능 (더블클릭하면 편집 모드)
  • 드래그로 순서 바꾸기
  • 마감일과 정렬
  • 다크 모드 (21장의 세 가지 상태를 정확히)
  • useReducer로 리팩터링(65장) 후 reducer 테스트 작성(75장)

🔑 API 키가 필요한 서비스라면

프론트엔드 코드에 키를 넣지 마세요(1·47·78장). 키가 필요한 API를 쓰려면 서버(라우트 핸들러·서버리스 함수)를 경유해야 합니다. 학습 단계에서는 키가 필요 없는 공개 API를 고르는 편이 간단합니다.

🎯 스스로 점검할 것

  • if (!response.ok) throw를 썼는가(37장) — 가장 많이 빠뜨립니다
  • 빠르게 여러 번 검색했을 때 결과가 뒤섞이지 않는가(37·61장)
  • "결과 없음"과 "오류"를 구분해서 보여주는가
  • 로딩 상태를 finally에서 해제했는가(33장)
  • 느린 네트워크(Slow 4G)에서 화면이 어떻게 보이는가(49장)

⬆️ 여유가 되면

  • TanStack Query로 전환(67장) — 직접 만든 것과 비교하면 배우는 것이 많습니다
  • 무한 스크롤 (40장의 IntersectionObserver)
  • 즐겨찾기 저장
  • 차트 표시
  • TypeScript로 전환 + Zod로 응답 검증(54장)

  • 조회수 (서버 필요)

막혔을 때

🧗 막히는 것이 학습입니다

  1. 오류 메시지를 끝까지 읽으세요. 대부분 답이 그 안에 있습니다(23장).
  2. 개발자 도구를 여세요. Console → Network → Elements 순서(49장).
  3. 문제를 최소화하세요. 코드를 지워 가며 어디서 문제가 사라지는지 찾습니다.
  4. 공식 문서를 먼저 보세요. MDN, react.dev는 블로그 글보다 정확합니다.
  5. 검색은 영어로. 오류 메시지를 그대로 붙여 넣으세요.
  6. AI에게 물어보되 답을 검증하세요. 그럴듯한 거짓말을 할 수 있습니다. 동작하는 이유를 설명할 수 없는 코드는 쓰지 마세요.

30분 이상 같은 자리에서 막혔다면 잠깐 쉬거나 다른 부분을 하세요. 막힌 상태로 계속 붙들고 있는 것은 대개 비효율적입니다.
