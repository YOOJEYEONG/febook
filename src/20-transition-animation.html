읽는 데 약 20분

transition — 상태가 바뀔 때 부드럽게

.button {
  background: #1f5f4f;
  transition: background 200ms ease, transform 200ms ease;
}
.button:hover {
  background: #2f8f77;
  transform: translateY(-2px);
}

transition은 값이 바뀌는 순간에 개입해 중간 과정을 만들어 줍니다. 네 부분으로 이루어집니다.

부분예설명
transition-propertyopacity, all어떤 속성을. all은 피하세요 — 예상 못 한 속성까지 애니메이션되어 성능을 갉아먹습니다
transition-duration200ms얼마 동안
transition-timing-functionease-out어떤 속도 곡선으로
transition-delay100ms얼마 뒤에 시작

📍 transition은 기본 상태에 씁니다

/* ✅ 들어갈 때도 나올 때도 부드럽다 */
.btn { transition: background 200ms; }
.btn:hover { background: red; }

/* ❌ 마우스를 올릴 때만 부드럽고, 뗄 때는 뚝 끊긴다 */
.btn:hover { background: red; transition: background 200ms; }

애니메이션 되는 것과 안 되는 것

연속적인 숫자로 표현되는 값만 중간 단계를 만들 수 있습니다.

  • 됩니다 — opacity, color, background-color, width, height, margin, transform, box-shadow, filter
  • 안 됩니다 — display, font-family, position 같은 불연속적인 값

그래서 display: none에서 block으로 바꾸며 서서히 나타나게 하려는 시도가 실패합니다. 전통적으로는 opacity와 visibility를 조합해 우회했습니다. 최근에는 transition-behavior: allow-discrete와 @starting-style로 display를 포함한 전환이 가능해졌지만(Chrome 117+, Safari 17.4+, Firefox 129+), 아직 지원 범위 확인이 필요합니다.

transform

함수예의미
translatetranslateX(20px), translate(10px, 20px)이동. %는 자기 크기 기준
scalescale(1.05)확대·축소
rotaterotate(45deg)회전
skewskewX(10deg)기울이기
 
/* 여러 개는 공백으로 나열 — 오른쪽부터 적용됩니다 */
transform: translateX(20px) rotate(45deg) scale(1.2);

/* 회전·확대의 기준점 */
transform-origin: center;      /* 기본값 */
transform-origin: top left;

🎯 완벽한 중앙 정렬의 고전 기법

.modal {
  position: fixed;
  top: 50%;
  left: 50%;
  transform: translate(-50%, -50%);   /* 자기 크기의 절반만큼 되돌린다 */
}

top: 50%는 요소의 위쪽 모서리를 화면 중앙에 둡니다. translate(-50%, -50%)의 %는 자기 자신의 크기 기준이라 크기를 몰라도 정확히 가운데로 옵니다. 지금은 Flex·Grid가 더 간단하지만 position: fixed와 함께 쓸 때는 여전히 유용합니다.

@keyframes — 복잡한 동작

@keyframes fadeInUp {
  from { opacity: 0; transform: translateY(20px); }
  to   { opacity: 1; transform: translateY(0); }
}

/* 중간 지점도 지정할 수 있습니다 */
@keyframes bounce {
  0%, 100% { transform: translateY(0); }
  50%      { transform: translateY(-20px); }
}

.card {
  animation: fadeInUp 400ms ease-out;
}
animation 축약형의 순서 
animation: fadeInUp 400ms ease-out 100ms 1 normal forwards;
/*         이름     시간   이징     지연  횟수 방향  종료후 */

animation-iteration-count: infinite;   /* 무한 반복 */
animation-direction: alternate;        /* 갔다 되돌아오기 */
animation-fill-mode: forwards;         /* 끝난 뒤 마지막 상태 유지 */
animation-play-state: paused;          /* 일시 정지 */

🔚 animation-fill-mode: forwards가 없으면

애니메이션이 끝나는 순간 원래 상태로 되돌아갑니다. "페이드인이 끝나자마자 다시 사라져요"의 원인입니다. 마지막 프레임을 유지하려면 forwards가 필요합니다.

이징 — 속도의 곡선

현실의 물체는 일정한 속도로 움직이지 않습니다. 서서히 출발해 서서히 멈춥니다. 이징이 없으면(linear) 기계적이고 어색해 보입니다.

값느낌어울리는 곳
linear일정한 속도로딩 스피너 회전 정도
ease (기본)빠르게 시작해 천천히 끝무난한 기본값
ease-out빠르게 시작해 부드럽게 정지등장·열기. 가장 자주 씁니다
ease-in천천히 시작해 빠르게 끝퇴장·닫기
ease-in-out양쪽 모두 부드럽게위치 이동
cubic-bezier(…)직접 곡선 정의튕기는 효과 등
steps(n)뚝뚝 끊어서스프라이트 애니메이션, 타이핑 효과

⏱️ 시간 감각

  • 100~200ms — 호버, 버튼 눌림 같은 작은 반응. 즉각적으로 느껴집니다
  • 200~400ms — 드롭다운, 모달 등장
  • 400~600ms — 화면 전환처럼 큰 움직임
  • 600ms 이상 — 대부분 너무 깁니다. 사용자는 기다림으로 느낍니다

부드러운 애니메이션의 조건

5장에서 본 렌더링 파이프라인을 떠올려 보세요. 어떤 속성을 바꾸느냐에 따라 다시 해야 하는 단계가 다릅니다.

바꾸는 속성다시 하는 단계비용
width, height, top, left, margin, padding레이아웃 → 페인트 → 합성매우 비쌈
background-color, color, box-shadow, border-radius페인트 → 합성중간
transform, opacity합성만가장 쌈

🛠️ 현장 노트 — 실무 규칙 세 줄

  1. 움직임은 transform, 사라짐은 opacity. 이 둘만으로 대부분의 UI 애니메이션이 됩니다.
  2. left·top·width·height를 애니메이션하지 마세요. 매 프레임 레이아웃을 다시 계산합니다.
  3. transition: all을 쓰지 마세요. 무엇이 애니메이션될지 통제할 수 없습니다.

will-change

.card { will-change: transform; }

"이 속성이 곧 바뀔 예정"이라고 브라우저에 미리 알려 최적화를 준비시킵니다. 다만 메모리를 먼저 잡아먹고 쌓임 맥락도 만들기 때문에(17장) 남용하면 오히려 느려집니다. 실제로 버벅임을 측정한 뒤, 곧 애니메이션될 요소에만 잠깐 붙이는 것이 원칙입니다.

접근성 — 반드시 지킬 것

@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}

🌀 취향이 아니라 건강 문제입니다

18장에서도 언급했지만 다시 강조합니다. 큰 화면 이동, 확대·축소, 패럴랙스는 전정기관 장애가 있는 사람에게 실제 어지럼증을 유발합니다. 그리고 1초에 3회 이상 번쩍이는 효과는 광과민성 발작을 일으킬 수 있어 WCAG에서 명시적으로 금지합니다. 위 코드 블록은 모든 프로젝트에 넣으세요.

한 걸음 더: View Transitions

페이지나 화면 상태가 바뀔 때 브라우저가 알아서 전환 애니메이션을 만들어 주는 새 기능입니다.

document.startViewTransition(() => {
  // 여기서 DOM을 바꾸면 그 변화가 부드럽게 전환됩니다
  updateTheList();
});

Chrome 111+, Safari 18+에서 지원되며 Firefox는 아직입니다. 지원하지 않는 브라우저에서는 애니메이션 없이 즉시 바뀔 뿐 기능은 정상 동작하므로, 점진적 향상(progressive enhancement)의 좋은 예입니다.

📌 요약

  • transition은 기본 상태에 쓴다. :hover에만 쓰면 되돌아올 때 끊긴다.
  • transition: all은 피한다.
  • transform의 %는 자기 크기 기준이다.
  • animation-fill-mode: forwards가 없으면 끝난 뒤 원상 복귀한다.
  • 이징 기본 선택: 등장은 ease-out, 퇴장은 ease-in. 시간은 100~400ms.
  • 움직임은 transform, 사라짐은 opacity — 합성 단계만 쓰므로 가장 싸다.
  • will-change는 측정 후 필요한 곳에만.
  • prefers-reduced-motion 대응은 필수. 초당 3회 이상 번쩍임은 금지.
