정규표현식이란

문자열에서 패턴을 찾는 작은 언어입니다. "숫자 세 개 다음에 하이픈, 그다음 숫자 네 개" 같은 규칙을 짧게 표현합니다.

// 리터럴 — 패턴이 고정일 때
const pattern = /\d{3}-\d{4}/;

// 생성자 — 패턴을 변수로 만들 때 (백슬래시를 두 번 써야 합니다)
const keyword = "홍길동";
const dynamic = new RegExp(`^${keyword}`, "i");

검증에 쓸 때 — 중요한 주의

📧 "완벽한 이메일 정규식"을 찾지 마세요

인터넷에는 수십 줄짜리 이메일 정규식이 돌아다닙니다. 그럼에도 표준(RFC 5322)을 완전히 만족하는 정규식은 사실상 불가능합니다. 게다가 형식이 맞아도 실제로 존재하는 주소인지는 알 수 없습니다. 정규식을 아무리 정교하게 만들어도 오타를 잡아 주지 못합니다. 실무 정답 — 형식 검사는 느슨하게 하고, 진짜 확인은 인증 메일 발송으로 합니다. HTML의 type="email"(9장)이 하는 검사 정도면 충분합니다. 
// 이 정도로 충분합니다
const looksLikeEmail = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;

🌍 이름·주소·전화번호도 마찬가지입니다

  • 이름 — /^[가-힣]{2,5}$/ 같은 검사는 외국인, 한 글자 성씨, 여섯 글자 이름을 거부합니다.
  • 전화번호 — 국가마다 형식이 다릅니다. 숫자와 몇 개 기호만 허용하는 정도가 안전합니다.
  • 우편번호 — 나라마다 자릿수가 다릅니다.

과도한 검증은 정당한 사용자를 막습니다. "이 값이 명백히 잘못되었는가"만 걸러내고, 나머지는 통과시키는 편이 낫습니다.

실무에서 자주 쓰는 패턴

함정

🔁 g 플래그 + test()의 상태 문제

const re = /a/g;
console.log(re.test("aa"));   // true
console.log(re.test("aa"));   // true
console.log(re.test("aa"));   // false (!) — 검색 위치가 남아 있기 때문

g 플래그가 붙은 정규식 객체는 lastIndex라는 상태를 유지합니다. 같은 객체를 재사용하면 이전 위치부터 검색합니다. 단순 검사에는 g를 붙이지 마세요. 꼭 필요하면 매번 새로 만들거나 re.lastIndex = 0으로 초기화합니다.

💣 재앙적 백트래킹 (ReDoS)

// ⚠️ 실행하지 마세요 — 브라우저가 멈출 수 있습니다
/^(a+)+$/.test("aaaaaaaaaaaaaaaaaaaaaaaaaaaaX");

중첩된 반복((a+)+)은 실패할 때 경우의 수가 지수적으로 폭발합니다. 문자 30개만으로도 몇 분씩 걸릴 수 있고, 그동안 메인 스레드가 완전히 멈춥니다(35장). 공격자가 이런 입력을 일부러 보내는 것을 ReDoS 공격이라고 합니다.
예방: 중첩 반복을 피하고, 사용자 입력으로 정규식을 만들지 말고, 복잡한 패턴이 필요하면 정규식 대신 코드로 푸세요.

🛠️ 현장 노트 — 정규식 사용 원칙

  1. 외우지 마세요. 필요할 때 regex101.com에서 만들고 테스트하면 됩니다. 각 부분이 무슨 뜻인지 설명까지 보여 줍니다.
  2. 반드시 주석을 답니다. 3개월 뒤의 나는 그 정규식을 못 읽습니다.
  3. 세 줄이 넘어가면 코드로 푸세요. split·includes·startsWith가 읽기 훨씬 좋고 버그도 적습니다.
  4. HTML 파싱에 정규식을 쓰지 마세요. 중첩 구조를 정규식으로 다룰 수 없습니다. DOMParser를 쓰세요.
  5. 보안 검증에 쓰지 마세요. XSS 방어를 정규식으로 하려는 시도는 거의 항상 우회됩니다(78장).

📌 요약

  • 정규식은 외우는 것이 아니라 읽고 도구로 만드는 것이다.
  • \w에는 한글이 포함되지 않는다. 한글은 [가-힣]이나 유니코드 속성.
  • match는 g 유무로 결과가 달라진다. matchAll이 더 명확하다.
  • 이름 있는 캡처 그룹((?<name>…))을 쓰면 훨씬 읽기 좋다.
  • .*는 탐욕적, .*?는 게으르다.
  • 이메일·이름·전화번호를 엄격하게 검증하지 마라. 정당한 사용자를 막는다.
  • g + test()는 lastIndex 상태 때문에 결과가 번갈아 나온다.
  • 중첩 반복은 ReDoS를 만든다. 복잡하면 코드로 풀어라.
