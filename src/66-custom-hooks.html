훅의 규칙

📜 두 가지 규칙

  1. 최상위에서만 호출한다. 조건문·반복문·중첩 함수 안에서 호출하면 안 됩니다.
  2. React 함수 안에서만 호출한다. 컴포넌트 또는 다른 훅 안에서만.
// ❌ 조건문 안
if (isLoggedIn) {
  const [name, setName] = useState("");
}

// ❌ 반복문 안
for (const item of items) {
  const [value] = useState(item);
}

// ❌ 이른 반환 뒤
if (!user) return null;
const [data, setData] = useState();

// ✅ 항상 최상위에서
const [name, setName] = useState("");
if (!user) return null;

🔢 왜 이런 규칙이 있나

React는 훅을 이름이 아니라 호출 순서로 구분합니다. 첫 번째 useState, 두 번째 useState… 이렇게 배열처럼 기억합니다.
조건에 따라 호출을 건너뛰면 순서가 어긋나 다른 훅의 값을 가져오게 됩니다. 그래서 "조건이 필요하면 훅 안에서" 처리해야 합니다.

// ✅ 훅은 항상 호출하고, 조건은 안에서
const { data } = useQuery({ queryKey: ["user", id], enabled: Boolean(id) });

커스텀 훅 만들기

✅ 규칙은 단 하나

이름이 use로 시작하는 함수면 커스텀 훅입니다. 특별한 API가 없습니다. 그냥 함수인데 안에서 다른 훅을 쓸 수 있을 뿐입니다.
이름이 use로 시작해야 린터가 훅 규칙을 검사할 수 있습니다(48장).

// 컴포넌트에서 로직만 떼어내면 됩니다
function useToggle(initial = false) {
  const [value, setValue] = useState(initial);
  const toggle = useCallback(() => setValue(v => !v), []);
  const on = useCallback(() => setValue(true), []);
  const off = useCallback(() => setValue(false), []);
  return { value, toggle, on, off };
}

function Modal() {
  const { value: isOpen, on: open, off: close } = useToggle();
  return (
    <>
      <button onClick={open}>열기</button>
      {isOpen && <Dialog onClose={close} />}
    </>
  );
}

🔀 훅은 로직을 공유하지 상태를 공유하지 않습니다

function A() { const { value } = useToggle(); }   // A만의 상태
function B() { const { value } = useToggle(); }   // B만의 상태 — 서로 무관합니다

커스텀 훅을 쓰는 컴포넌트마다 완전히 독립된 상태가 만들어집니다. 31장의 클로저로 만든 카운터가 호출할 때마다 독립적이었던 것과 같은 원리입니다.
상태를 공유하려면 Context나 전역 상태 라이브러리가 필요합니다(65장). "훅으로 만들었으니 전역이 되겠지"는 흔한 오해입니다.

자주 쓰는 훅

① useDebounce — 입력이 멈춘 뒤에만 반응 (31장) 
function useDebounce(value, delay = 300) {
  const [debounced, setDebounced] = useState(value);

  useEffect(() => {
    const timer = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(timer);      // 정리 필수 (61장)
  }, [value, delay]);

  return debounced;
}

// 사용
const [query, setQuery] = useState("");
const debouncedQuery = useDebounce(query, 300);
useEffect(() => { search(debouncedQuery); }, [debouncedQuery]);
② useLocalStorage — 저장소와 동기화 (39장) 
function useLocalStorage(key, initialValue) {
  const [value, setValue] = useState(() => {
    // 초기값을 함수로 주면 첫 렌더링에서만 실행됩니다 (lazy 초기화)
    try {
      const saved = localStorage.getItem(key);
      return saved !== null ? JSON.parse(saved) : initialValue;
    } catch {
      return initialValue;               // 접근이 막힐 수 있습니다 (39장)
    }
  });

  useEffect(() => {
    try {
      localStorage.setItem(key, JSON.stringify(value));
    } catch { /* 용량 초과 등 — 조용히 무시 */ }
  }, [key, value]);

  return [value, setValue];
}
③ useMediaQuery — JS에서 미디어 쿼리 (40장) 
function useMediaQuery(query) {
  const [matches, setMatches] = useState(
    () => window.matchMedia(query).matches
  );

  useEffect(() => {
    const mq = window.matchMedia(query);
    const onChange = (e) => setMatches(e.matches);
    setMatches(mq.matches);
    mq.addEventListener("change", onChange);
    return () => mq.removeEventListener("change", onChange);
  }, [query]);

  return matches;
}

const isMobile = useMediaQuery("(max-width: 768px)");
const prefersDark = useMediaQuery("(prefers-color-scheme: dark)");
④ useOnClickOutside — 바깥 클릭 감지 (38장) 
function useOnClickOutside(ref, handler) {
  useEffect(() => {
    function listener(event) {
      if (!ref.current || ref.current.contains(event.target)) return;
      handler(event);
    }
    document.addEventListener("pointerdown", listener);
    document.addEventListener("keydown", (e) => { if (e.key === "Escape") handler(e); });
    return () => document.removeEventListener("pointerdown", listener);
  }, [ref, handler]);
}
⑤ useIntersectionObserver — 무한 스크롤 (40장) 
function useIntersectionObserver(ref, options) {
  const [isVisible, setIsVisible] = useState(false);

  useEffect(() => {
    const element = ref.current;
    if (!element) return;

    const observer = new IntersectionObserver(
      ([entry]) => setIsVisible(entry.isIntersecting),
      options
    );
    observer.observe(element);
    return () => observer.disconnect();     // 정리 필수 (40장)
  }, [ref, options]);

  return isVisible;
}

초기값을 함수로 주기

// ❌ 매 렌더링마다 실행됩니다 (결과는 첫 번째만 쓰이는데도)
const [value] = useState(expensiveCalculation());

// ✅ 첫 렌더링에서만 실행됩니다
const [value] = useState(() => expensiveCalculation());

localStorage를 읽거나 큰 데이터를 만드는 초기값에는 반드시 함수 형태를 쓰세요. 위의 useLocalStorage 예제가 그 이유입니다.

언제 훅으로 추출할까

추출할 신호설명
같은 로직이 두세 곳에 반복가장 명확한 신호
useEffect가 여러 개로 복잡목적별로 훅으로 나누면 읽기 쉬워집니다
컴포넌트가 길어짐로직을 빼면 화면 구조만 남아 읽기 좋습니다(63장)
로직만 테스트하고 싶음훅은 별도로 테스트할 수 있습니다(75장)

🚫 과하게 추출하지 마세요

// ❌ 아무 이득이 없습니다
function useCount() {
  const [count, setCount] = useState(0);
  return { count, setCount };
}

단순히 useState를 한 번 감싼 것은 파일만 늘리고 추적을 어렵게 합니다.
좋은 커스텀 훅은 이름이 "무엇을 하는지"를 말해 줍니다. useDebounce·useOnClickOutside는 좋고, useData·useLogic은 나쁩니다.

🛠️ 현장 노트

  1. 직접 만들기 전에 찾아보세요. usehooks.com, react-use, @uidotdev/usehooks에 검증된 구현이 많습니다. 직접 만든 훅은 정리 함수·엣지 케이스에서 실수하기 쉽습니다.
  2. 훅에서 조건부로 다른 훅을 부르지 마세요. 규칙 위반입니다.
  3. 반환값은 상황에 맞게. 값이 2개면 배열(구조 분해 시 이름 자유), 3개 이상이면 객체가 읽기 좋습니다.
  4. TypeScript에서는 배열 반환에 as const를 잊지 마세요(56장).
  5. 훅 안에서도 정리 함수를 반드시 작성하세요. 훅이 재사용될수록 누수의 영향이 커집니다.

📌 요약

  • 훅은 최상위에서만, React 함수 안에서만 호출한다.
  • React는 훅을 호출 순서로 구분하기 때문에 이 규칙이 필요하다.
  • 조건이 필요하면 훅 안에서 처리한다(enabled 옵션 등).
  • 커스텀 훅은 use로 시작하는 함수일 뿐이다.
  • 훅은 로직을 공유하지 상태를 공유하지 않는다. 쓸 때마다 독립된 상태가 생긴다.
  • 비싼 초기값은 함수 형태로 준다.
  • 추출 신호: 반복 · 복잡한 Effect · 긴 컴포넌트 · 테스트 필요.
  • 이름이 무엇을 하는지 말해 주는 훅이 좋은 훅이다.
