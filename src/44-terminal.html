왜 터미널을 쓰나

터미널(또는 명령줄, CLI)은 글자로 컴퓨터에 명령하는 창구입니다. 마우스로 클릭하는 것보다 불편해 보이지만, 개발에서는 훨씬 강력합니다.

  • 대부분의 개발 도구가 터미널 전용입니다. npm, Git, 빌드 도구, 배포 명령어 모두 그렇습니다.
  • 반복 작업을 자동화할 수 있습니다. 파일 100개의 이름을 한 줄로 바꿉니다.
  • 정확히 기록됩니다. "메뉴에서 이거 누르고 저거 누르세요" 대신 명령어 한 줄을 공유하면 끝입니다.
  • 원격 서버에는 화면이 없습니다. 터미널이 유일한 창구입니다.

💻 무엇을 열면 되나

  • macOS — 기본 터미널 앱. (Spotlight에서 "터미널") 셸은 zsh가 기본입니다.
  • Windows — Windows Terminal + PowerShell을 권장합니다. 리눅스 명령어를 그대로 쓰고 싶다면 WSL(Windows Subsystem for Linux)을 설치하세요.
  • 가장 편한 방법 — VS Code 안의 터미널(Ctrl+`). 편집기와 같은 창에서 씁니다.

이 책의 명령어는 macOS·리눅스·WSL 기준입니다. Windows PowerShell에서 다르게 써야 하는 명령은 아래 Windows PowerShell 대응표와 각 절의 Windows 표시에 함께 적었습니다. npm, git, node처럼 도구 이름으로 시작하는 명령(45~47장)은 운영체제와 상관없이 똑같습니다.

경로 이해하기

경로 표기 
/Users/hong/projects/my-app/index.html   # 절대 경로 (맨 위부터 전부)
./index.html                              # 현재 폴더의 index.html  (./ 는 생략 가능)
../images/logo.png                        # 한 단계 위 폴더 안의
~/Desktop                                 # 홈 폴더 (사용자 폴더)
/                                         # 최상위 (루트)

8장에서 배운 HTML 경로 규칙과 완전히 같은 개념입니다. 터미널은 항상 "지금 어느 폴더에 있는가"라는 상태를 가지고 있고, 상대 경로는 그 위치를 기준으로 해석됩니다.

💀 rm에는 휴지통이 없습니다

터미널의 rm은 즉시 완전히 지웁니다. 되돌릴 방법이 없습니다. 실행하기 전에 경로를 두 번 확인하세요.
특히 인터넷에서 본 rm -rf로 시작하는 명령어를 이해하지 못한 채 복사해 붙이지 마세요. rm -rf /는 컴퓨터의 모든 파일을 지우려는 명령입니다. PowerShell의 Remove-Item -Recurse -Force도 똑같이 휴지통을 거치지 않습니다. "이 명령이 무엇을 하는지 설명할 수 있는가"를 스스로 물어보는 습관이 필요합니다.

찾기와 보기 — Windows는 아래 대응표 참고 
grep -r "TODO" src/           # src 폴더에서 "TODO"가 든 줄 찾기
find . -name "*.test.js"      # 이름으로 파일 찾기
head -20 log.txt              # 앞 20줄
tail -f server.log            # 마지막 부분을 실시간으로 계속 보기
which node                    # 이 명령이 어디에 설치되어 있는지
node --version                # 버전 확인
조합하기 
ls | grep ".js"               # ls의 결과를 grep에 넘김 (파이프)
npm run build > build.log     # 출력을 파일로 저장
command1 && command2          # 앞이 성공하면 뒤 실행
Ctrl + C                      # 실행 중인 명령 중단 (개발 서버 끄기)
Ctrl + L                      # 화면 지우기 (clear 명령과 같음)
↑ ↓                           # 이전 명령어 다시 꺼내기
Tab                           # 자동 완성 — 오타를 줄이는 최고의 습관

Windows PowerShell 대응표

PowerShell은 ls, cd, pwd, cp, mv, rm, cat, mkdir를 별명(alias)으로 알아듣기 때문에 기본 이동·확인은 그대로 됩니다. 문제는 뒤에 붙는 옵션(-la, -r, -rf)과 macOS·리눅스에만 있는 명령입니다. 아래 표의 오른쪽 열을 쓰세요.

🔢 PowerShell 버전을 확인하세요

Windows에 기본으로 들어 있는 것은 Windows PowerShell 5.1입니다. 5.1에서는 &&와 cd -가 오류를 냅니다. $PSVersionTable.PSVersion을 입력해 버전을 확인하고, 5.x라면 winget install Microsoft.PowerShell로 PowerShell 7을 설치한 뒤 Windows Terminal에서 "Windows PowerShell"이 아닌 "PowerShell" 프로필을 고르세요. 45장 이후의 git switch main && git pull 같은 명령은 7에서 그대로 동작합니다. 5.1을 계속 써야 한다면 두 명령을 한 줄씩 따로 입력하면 됩니다.

Windows에서 셸 고르기 — PowerShell · Git Bash · WSL

Windows 사용자는 세 가지 중 하나를 고르면 됩니다. PowerShell은 별도 설치 없이 쓸 수 있고 위 대응표만 알면 됩니다. Git Bash는 Git for Windows(45장)를 설치하면 함께 따라오는 터미널로, ls -la, touch, rm -rf처럼 이 책의 macOS·리눅스 명령을 거의 그대로 쓸 수 있습니다. 경로는 /c/Users/hong/Desktop처럼 표기됩니다. WSL은 Windows 안에 진짜 리눅스(기본 Ubuntu)를 설치하는 방식으로, 리눅스 서버와 똑같은 환경이 필요할 때 가장 정확하지만 리눅스 쪽에 Node.js·Git을 따로 다시 설치해야 하고 Windows 폴더와 리눅스 폴더를 오가는 개념을 익혀야 합니다. 처음이라면 PowerShell 7 또는 Git Bash로 시작하고, 필요해지면 WSL로 옮기는 것을 권합니다. VS Code 터미널 오른쪽 위 ∨ 메뉴에서 어떤 셸을 쓸지 고를 수 있습니다.

⌨️ Tab 자동 완성을 반드시 쓰세요

긴 폴더 이름을 손으로 다 치지 마세요. 앞 몇 글자만 치고 Tab을 누르면 나머지가 채워집니다. 자동 완성이 안 된다면 그 이름이 없다는 뜻이므로 오타를 즉시 알 수 있습니다. 초보자가 겪는 "파일이 없다는 오류"의 절반이 이것으로 사라집니다.

로컬 서버 띄우기

34장에서 본 것처럼 file://로 열면 모듈과 fetch가 동작하지 않습니다. 내 컴퓨터에 작은 웹 서버를 띄우면 해결됩니다.

# 방법 1: Node.js가 있다면 (46장) — 설치 없이 바로 실행
npx serve

# 방법 2: Python이 있다면 (macOS에는 기본 설치)
python3 -m http.server 8000      # Windows: python -m http.server 8000

# 방법 3: VS Code 확장 "Live Server" — 저장하면 자동 새로고침

실행하면 http://localhost:8000 같은 주소가 나옵니다. 그 주소로 접속하면 진짜 웹사이트처럼 동작합니다. 2장에서 배운 localhost가 바로 이것입니다.

🔌 "포트가 이미 사용 중입니다"

# 원인: 이전에 켠 서버가 아직 돌고 있습니다
lsof -i :3000        # 3000번 포트를 쓰는 프로세스 확인 (macOS·리눅스)
kill -9 <PID>        # 그 프로세스 종료

# Windows PowerShell
netstat -ano | findstr :3000      # 맨 끝 숫자가 PID
Stop-Process -Id <PID> -Force     # 그 프로세스 종료

# 또는 그냥 다른 포트를 쓰면 됩니다
npx serve -l 3001

환경 변수와 PATH

echo $PATH             # 명령어를 찾는 폴더 목록
echo $HOME
export MY_VAR=hello    # 이 터미널 세션에서만 유효
Windows PowerShell 
$env:Path              # 명령어를 찾는 폴더 목록 (; 로 구분)
$HOME
$env:MY_VAR = "hello"  # 이 터미널 세션에서만 유효

PATH는 "명령어를 입력하면 어느 폴더들에서 찾을지"의 목록입니다. node를 설치했는데 command not found가 나온다면 설치는 되었지만 PATH에 없는 것입니다. 터미널을 껐다 켜거나, 설치 안내에 나온 설정을 셸 설정 파일(macOS는 ~/.zshrc, PowerShell은 $PROFILE이 가리키는 파일)에 추가해야 합니다. VS Code 안의 터미널이라면 VS Code 자체를 완전히 종료했다가 다시 여세요. 새 터미널 탭만 열면 예전 PATH가 남아 있는 경우가 있습니다.

🔑 sudo를 습관적으로 쓰지 마세요

sudo는 관리자 권한으로 실행한다는 뜻입니다. 권한 오류가 날 때마다 sudo를 붙이면 당장은 되지만, 파일 소유자가 관리자로 바뀌어 나중에 더 큰 문제가 생깁니다. 특히 sudo npm install -g는 흔한 실수입니다. Node.js는 버전 관리 도구(nvm, fnm 등)로 설치하면 sudo 없이 쓸 수 있습니다(46장).

🛠️ 현장 노트 — 터미널 실력 키우기

  1. 전부 외우려 하지 마세요. 위 15개 정도만 손에 익으면 실무의 90%가 됩니다.
  2. 모르는 명령은 --help를 붙여 보세요. ls --help, git commit --help.
  3. 붙여 넣기 전에 읽으세요. 인터넷에서 복사한 명령어가 무엇을 하는지 모르겠다면 실행하지 마세요.
  4. 탭 자동 완성과 ↑를 쓰세요. 타자 실력이 아니라 도구 활용이 속도를 만듭니다.
  5. 프롬프트를 꾸미고 싶다면 Oh My Zsh, Starship 같은 도구가 있습니다. Git 상태가 프롬프트에 보이면 실수가 줄어듭니다.

📌 요약

  • 터미널은 개발 도구를 쓰기 위한 필수 창구다. 대부분의 도구가 CLI로만 제공된다.
  • 경로 개념은 HTML의 상대·절대 경로와 같다. pwd로 현재 위치를 항상 확인한다.
  • rm에는 휴지통이 없다. 이해하지 못한 명령을 붙여 넣지 않는다.
  • Tab 자동 완성이 오타 문제의 절반을 해결한다.
  • Windows는 PowerShell 7(대응표 참고) 또는 Git Bash로 시작한다. -rf 같은 옵션은 PowerShell에서 통하지 않는다.
  • npx serve나 python3 -m http.server로 로컬 서버를 띄운다.
  • command not found는 대개 PATH 문제다.
  • sudo를 습관적으로 쓰지 않는다.
