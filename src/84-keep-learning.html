🤖 AI를 쓰는 법

AI는 강력한 도구입니다. 다만 그럴듯한 거짓말을 합니다. 존재하지 않는 API, 사라진 옵션, 옛 문법을 자신 있게 알려 줍니다.

  • 좋은 용도 — 개념 설명, 코드 리뷰 요청, 오류 메시지 해석, 시작점 만들기, 반복 작업
  • 위험한 용도 — 검증 없이 복사, 보안 관련 코드, 최신 API 확인
  • 원칙 — 동작하는 이유를 설명할 수 없는 코드는 쓰지 마세요. 그 코드는 여러분이 유지보수할 수 없고, 면접에서도 설명할 수 없습니다.
  • AI가 준 API 이름은 MDN이나 공식 문서에서 실제로 확인하세요.

📈 효과가 큰 순서

  1. 만들기 — 압도적 1위입니다. 읽기만 해서는 늘지 않습니다(81장).
  2. 남의 코드 읽기 — 오픈소스, 팀 동료의 PR. 다른 사고방식을 배웁니다.

  5. 공식 문서 읽기 — 목적 없이 훑는 것도 의외로 효과가 큽니다.
  6. 강의·책 — 체계를 잡는 데 좋지만 실습이 없으면 남지 않습니다.

마치며

🎓 84개 챕터를 지나온 여러분에게

1장에서 "프론트엔드는 사용자의 브라우저에서 실행되는 코드"라는 정의로 시작했습니다. 이제 여러분은 그 한 문장 뒤에 있는 것들을 알고 있습니다.

요청이 서버에 닿기까지의 여정, 브라우저가 픽셀을 그리는 과정, JavaScript가 한 번에 하나씩 처리하면서도 멈추지 않는 이유, 상태를 선언하면 화면이 따라오게 만드는 방식, 그리고 그 모든 것 위에서 누군가가 실제로 서비스를 쓴다는 사실까지.

이 책을 다 읽었다고 실력이 생기지는 않습니다. 지도를 본 것이지 길을 걸은 것은 아닙니다. 이제 필요한 것은 직접 만들고, 막히고, 검색하고, 고치는 시간입니다. 그 과정에서 이 책의 내용이 비로소 여러분의 것이 됩니다.

막히면 언제든 돌아오세요. 이 책은 처음부터 다시 읽는 책이 아니라 필요할 때 펼치는 책으로 만들어졌습니다.

느린 네트워크에서 기다리는 사람, 화면을 볼 수 없어 소리로 듣는 사람, 작은 화면에서 손가락으로 누르는 사람, 오래된 기기를 쓰는 사람.
기술은 그들을 위한 수단입니다. 가장 화려한 코드가 아니라 가장 많은 사람이 쓸 수 있는 코드가 좋은 코드입니다.
