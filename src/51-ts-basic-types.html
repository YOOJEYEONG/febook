기본 타입

타입은 값에 붙이는 이름표입니다. 이삿짐 상자에 "주방 — 깨지는 물건"이라고 적어 두면 옮기는 사람이 상자를 열어 보지 않고도 어떻게 다뤄야 할지 아는 것처럼, 변수에 number라고 적어 두면 TypeScript는 그 변수에 어떤 연산이 허용되는지 압니다. 이름표와 다른 물건을 넣으려 하면 그 자리에서 막아 줍니다.

가장 기본이 되는 이름표는 25장에서 배운 JavaScript의 원시값과 일대일로 대응합니다. 변수 이름 뒤에 : 타입을 붙이는 것이 타입 표기(타입 주석)입니다. 50장에서 본 것처럼 초기값이 있으면 대부분 생략해도 되지만, 여기서는 이름을 익히기 위해 일부러 적었습니다.

let name: string = "홍길동";
let age: number = 20;              // 정수·소수 구분 없음 (25장)
let isActive: boolean = true;
let nothing: null = null;
let notDefined: undefined = undefined;
let big: bigint = 100n;
let unique: symbol = Symbol("id");

// 특별한 타입들
let anything: any;         // 모든 검사 해제 — 피하세요
let safe: unknown;         // 확인 후에만 사용 가능
function fail(): never { throw new Error(); }   // 절대 반환하지 않음
function log(): void { console.log("x"); }      // 반환값이 없음

아래쪽 네 개는 JavaScript에 없는 TypeScript만의 타입입니다. any와 unknown은 50장에서 보았습니다. void는 "이 함수는 돌려주는 값이 없다"는 뜻이고, 버튼 클릭 처리 함수처럼 일만 하고 끝나는 함수에 붙습니다. never는 "이 지점에는 어떤 값도 도달할 수 없다"는 뜻입니다. 항상 오류를 던지는 함수는 정상적으로 끝나는 일이 없으므로 반환 타입이 never입니다. 당장 쓸 일은 드물지만, 54장에서 "모든 경우를 빠짐없이 처리했는지" 검사할 때 다시 만납니다.

🤔 자주 하는 오해 — String과 string은 같다

오해 — 대문자로 써도 소문자로 써도 같은 타입이다. 사실 — string이 맞고 String은 틀립니다. 대문자 String은 JavaScript의 래퍼 객체(new String("a")로 만드는 객체)를 뜻해서 의도와 다르게 동작합니다. number, boolean도 마찬가지로 항상 소문자로 씁니다.

배열과 튜플

배열에는 "무엇의 배열인지"를 적습니다. string[]은 "문자열만 담는 배열"입니다. 이렇게 적어 두면 숫자를 실수로 push하는 순간 오류가 나고, names[0].까지 치면 문자열 메서드가 자동 완성됩니다. 튜플은 한 걸음 더 나아가 "몇 칸짜리이고, 각 칸에 무엇이 오는지"까지 정한 배열입니다. 좌표 [x, y]처럼 자리마다 의미가 정해진 값을 표현할 때 씁니다.

// 배열 — 두 표기법은 완전히 같습니다. 앞의 것을 더 많이 씁니다
let names: string[] = ["a", "b"];
let ages: Array<number> = [20, 30];

// 여러 타입이 섞인 배열
let mixed: (string | number)[] = ["a", 1];

// 2차원
let grid: number[][] = [[1, 2], [3, 4]];

// 튜플 — 길이와 각 자리의 타입이 정해진 배열
let point: [number, number] = [10, 20];
let entry: [string, number] = ["age", 20];

point[0].toFixed(1);        // ✅ number 임을 압니다
// point[2];                ❌ 길이를 벗어남

// 이름을 붙이면 읽기 좋습니다
type Coordinate = [x: number, y: number];

▶ Playground에 붙여 보세요. point[2]의 주석을 풀면 "길이가 2인 튜플에 인덱스 2는 없다"는 오류가 납니다. Array<number>처럼 꺾쇠(<>) 안에 타입을 넣는 표기는 제네릭이라는 문법으로, 53장에서 자세히 봅니다. 지금은 number[]와 같은 뜻이라는 것만 알면 됩니다. 맨 아래 type은 타입에 이름을 붙이는 문법입니다(52장).

튜플을 가장 자주 만나는 곳은 React입니다. 59장에서 배울 const [count, setCount] = useState(0)에서 useState는 [현재 값, 값을 바꾸는 함수]라는 두 칸짜리 튜플을 돌려줍니다. 첫 칸은 숫자, 둘째 칸은 함수로 자리마다 타입이 다르기 때문에 일반 배열이 아니라 튜플이어야 합니다.

🕳️ 배열 인덱스 접근의 함정

const list: string[] = [];
const first = list[0];      // 타입은 string 이지만 실제 값은 undefined!
first.toUpperCase();        // 💥 런타임 오류

기본 설정에서 TypeScript는 인덱스 접근이 항상 성공한다고 가정합니다. tsconfig.json에 "noUncheckedIndexedAccess": true를 켜면 string | undefined로 추론되어 확인을 강제합니다. 안전을 중시한다면 켜는 것을 권합니다. Playground에서는 TS Config 메뉴에서 이 옵션을 켜 보고 차이를 확인할 수 있습니다.

유니온 타입 — 가장 많이 쓰는 기능

현실의 값은 한 가지 타입으로 딱 떨어지지 않을 때가 많습니다. 상품 ID가 어떤 곳에서는 숫자로, 어떤 곳에서는 문자열로 오고, 사용자를 찾는 함수는 찾으면 사용자를, 못 찾으면 null을 돌려줍니다. 유니온 타입은 세로 막대(|)로 "이 중 하나"를 표현합니다. 식당 메뉴의 "밥 또는 면 선택"과 같습니다. 둘 중 무엇이 올지는 모르지만, 그 밖의 것은 오지 않는다는 것은 확실합니다.

let id: string | number;
id = "abc";     // ✅
id = 123;       // ✅
id = true;      // ❌

// null 가능성을 명시적으로 표현합니다
interface User { id: number; name: string; }   // 객체 모양에 이름 붙이기 (52장)

const users: User[] = [{ id: 1, name: "홍길동" }];

function findUser(id: number): User | null {
  return users.find(u => u.id === id) ?? null;  // ?? 는 26장
}

const user = findUser(1);
// user.name;              ❌ 'user' is possibly 'null'
if (user) {
  user.name;            // ✅ 여기서는 User 임이 확실 (54장)
}

▶ Playground에 붙여 보세요. id = true 줄에 오류가 나고, user.name의 주석을 풀어도 오류가 납니다. 그런데 if (user) 안에서는 같은 코드가 통과합니다. TypeScript가 조건문을 읽고 "여기까지 왔다면 null은 아니다"라고 판단해 타입을 좁혔기 때문입니다. 이 동작을 타입 좁히기라고 하며 54장의 주제입니다.

💡 유니온은 "이 중 하나"를 코드로 표현합니다

JavaScript에서는 주석으로만 남기던 정보 ("이 함수는 유저를 찾거나 null을 반환합니다")를 컴파일러가 검사할 수 있는 형태로 만드는 것이 유니온입니다. 그리고 null 검사를 빠뜨리면 즉시 오류가 나므로 실수를 원천 차단합니다.

리터럴 타입 — 값 자체가 타입

string은 세상의 모든 문자열을 허용합니다. 그런데 버튼 크기처럼 정해진 몇 가지 값만 의미가 있는 경우가 많습니다. 이때 "sm", "md" 같은 구체적인 값 자체를 타입으로 쓸 수 있습니다. 이것이 리터럴 타입이고, 유니온과 합치면 "이 몇 개 중 하나"라는 선택지 목록이 됩니다. 신청서의 체크박스처럼 미리 인쇄된 칸에만 표시할 수 있는 것입니다.

let direction: "left" | "right" | "up" | "down";
direction = "left";      // ✅
direction = "back";      // ❌ 자동 완성으로 네 개만 제안됩니다

type Status = "idle" | "loading" | "success" | "error";
type Size = "sm" | "md" | "lg";
type HttpMethod = "GET" | "POST" | "PUT" | "DELETE";

function request(url: string, method: HttpMethod) { }
request("/api", "GET");    // ✅
request("/api", "get");    // ❌ 대소문자까지 정확히

▶ Playground에 붙여 보세요. request("/api", "까지 입력하면 네 가지 메서드가 자동 완성 후보로 뜹니다. 오타나 대소문자 실수("get")는 실행하기 전에 잡힙니다. 서버와 주고받는 상태 값, 디자인 시스템의 크기·색상 이름처럼 "허용된 값의 목록"이 있는 곳이라면 어디든 리터럴 유니온을 쓰는 것이 좋습니다.

⭐ 실무에서 가장 유용한 조합

interface ButtonProps {
  variant: "primary" | "secondary" | "danger";
  size: "sm" | "md" | "lg";
  disabled?: boolean;
}

이렇게 써 두면 컴포넌트를 쓰는 사람이 문서를 볼 필요가 없습니다. 편집기가 가능한 값을 전부 제안하고, 오타는 즉시 잡힙니다. React 컴포넌트 설계에서 이 패턴을 계속 쓰게 됩니다(56·63장).

const 단언

TypeScript는 값이 나중에 바뀔 수 있는지를 보고 타입을 넓게 또는 좁게 추론합니다. let은 다른 문자열로 바뀔 수 있으니 string으로, const는 바뀌지 않으니 "hello" 그 자체로 추론합니다. 객체의 속성은 const로 선언해도 나중에 바꿀 수 있으므로 넓게 추론됩니다. 이때 뒤에 as const를 붙이면 "이 값은 절대 바뀌지 않는다"고 못 박아 가장 좁은 타입으로 고정합니다.

let a = "hello";              // string 으로 추론 (바뀔 수 있으므로)
const b = "hello";            // "hello" 리터럴 타입 (바뀌지 않으므로)

const config = { mode: "dark" };
// config.mode 는 string 으로 추론됩니다

const config2 = { mode: "dark" } as const;
// config2.mode 는 "dark" 리터럴, 그리고 모든 속성이 readonly

const SIZES = ["sm", "md", "lg"] as const;
type Size = typeof SIZES[number];    // "sm" | "md" | "lg"
// ↑ 배열 하나로 값과 타입을 동시에 관리하는 유용한 패턴

마지막 줄은 처음 보면 암호 같습니다. 타입 자리의 typeof SIZES는 "SIZES라는 값의 타입"을, [number]는 "그 배열의 아무 칸에나 들어 있는 것"을 뜻합니다. 합치면 "배열 요소들의 유니온"이 됩니다. 이 문법은 55장에서 자세히 다루므로 지금은 "값 목록 하나로 타입까지 만들 수 있다"는 결과만 기억하세요. ▶ Playground에서 Size에 마우스를 올려 보면 펼쳐진 결과를 볼 수 있습니다.

객체 타입

객체 타입은 "어떤 속성이 있고, 각 속성은 무슨 타입인지"를 적은 설계도입니다. 속성 이름 뒤의 ?는 "없어도 된다", 앞의 readonly는 "만든 뒤에는 고칠 수 없다"는 뜻입니다. 회원 가입 양식에 필수 항목과 선택 항목이 나뉘어 있는 것과 같습니다.

// 인라인으로
function greet(user: { name: string; age: number }) { }

// 이름을 붙여 재사용 (52장에서 자세히)
interface User {
  id: number;
  name: string;
  email?: string;              // 선택적 — 없어도 됩니다
  readonly createdAt: Date;    // 읽기 전용 — 수정 불가
}

const user: User = { id: 1, name: "홍길동", createdAt: new Date() };
// user.createdAt = new Date();   ❌ 읽기 전용

// 인덱스 시그니처 — 키를 미리 알 수 없을 때
interface Scores {
  [subject: string]: number;
}
const scores: Scores = { math: 90, english: 85 };

▶ Playground에 붙여 보세요. user를 만들 때 name을 지우면 "필수 속성이 빠졌다"는 오류가, createdAt을 바꾸는 줄의 주석을 풀면 "읽기 전용"이라는 오류가 납니다. 인덱스 시그니처 [subject: string]: number는 "키는 아무 문자열이나 되고, 값은 숫자"라는 뜻입니다. 과목 이름처럼 키를 미리 다 알 수 없을 때 씁니다.

🔗 미리 보기 — Record (55장)

const scores2: Record<string, number> = { math: 90 };
const labels: Record<"sm" | "md", string> = { sm: "작게", md: "보통" };

Record<키, 값>은 "키가 이 타입이고 값이 저 타입인 객체"를 짧게 쓰는 내장 도구입니다. 위의 Scores와 scores2는 같은 뜻입니다. 이런 도구를 유틸리티 타입이라고 하며 55장에서 모아서 배웁니다. 다른 코드에서 자주 보이니 모양만 눈에 익혀 두세요.

📦 선택적 속성(?)과 | undefined는 다릅니다

interface A { email?: string; }              // 아예 없어도 됨
interface B { email: string | undefined; }   // 반드시 있어야 하되 값이 undefined일 수 있음

const a: A = {};                    // ✅
const b: B = {};                    // ❌ email 속성이 필요합니다
const b2: B = { email: undefined }; // ✅

양식으로 비유하면 ?는 "이 칸은 아예 없어도 되는 칸", | undefined는 "칸은 반드시 있어야 하지만 비워 둘 수는 있는 칸"입니다. API가 "값이 없으면 키 자체를 빼고 보낸다"면 ?, "키는 항상 보내되 값이 비어 있을 수 있다"면 | undefined가 정확합니다.

함수 타입

함수에서 타입을 적는 곳은 두 군데입니다. 매개변수(무엇을 받는가)와 반환 타입(무엇을 돌려주는가)입니다. 50장에서 본 것처럼 매개변수는 추론할 근거가 없으니 반드시 적고, 반환 타입은 대개 추론에 맡깁니다. 잘 적힌 함수 시그니처는 자판기 앞면의 안내문과 같습니다. "1000원을 넣으면 음료 하나가 나온다"만 보면 내부 구조를 몰라도 쓸 수 있습니다.

// 매개변수와 반환 타입
function add(a: number, b: number): number {
  return a + b;
}

// 선택적 매개변수와 기본값
function greet(name: string, greeting: string = "안녕", title?: string) { }

// 나머지 매개변수
function sum(...numbers: number[]): number {
  return numbers.reduce((total, n) => total + n, 0);
}

// 함수 자체를 타입으로 표현
type Handler = (event: MouseEvent) => void;

const onClick: Handler = (event) => {
  event.preventDefault();     // ✅ event의 타입을 알고 있습니다
};

// 콜백을 받는 함수
function repeat(times: number, action: (index: number) => void): void {
  for (let i = 0; i < times; i++) action(i);
}

repeat(3, (i) => console.log(i));   // 0, 1, 2

▶ Playground에 붙여 보세요. add(1, "2")를 추가하면 오류가 나고, Run을 누르면 Logs 탭에 0, 1, 2가 찍힙니다. (event: MouseEvent) => void는 "MouseEvent를 받고 아무것도 돌려주지 않는 함수"라는 함수의 모양입니다. 화살표 함수 문법(27장)과 생김새가 같아서 헷갈리지만, 이것은 실행되는 코드가 아니라 타입입니다. 라이브러리 코드에서 type Comparator<T> = (a: T, b: T) => number 같은 모양을 보게 되는데, <T>는 "어떤 타입이든 받아서 끼워 넣는 자리"로 53장의 제네릭입니다.

🎁 문맥 기반 추론

const names = ["a", "bb", "ccc"];
names.map(name => name.length);
//         ↑ string 으로 자동 추론됩니다. 타입을 쓸 필요가 없습니다

document.addEventListener("click", (event) => {
  //                                ↑ MouseEvent 로 추론
});

콜백의 매개변수는 대개 자동으로 추론됩니다. map은 "배열 요소를 하나씩 넘겨준다"는 것이 이미 타입으로 정해져 있으므로, 콜백을 받는 쪽의 정보로 타입이 채워집니다. "매개변수는 항상 타입을 써야 한다"는 규칙의 예외입니다.

enum 대신

다른 언어를 배운 사람은 "정해진 값 목록"을 만들 때 enum(열거형)을 떠올립니다. TypeScript에도 enum이 있지만, 지금은 쓰지 않는 쪽이 권장됩니다. 가장 큰 이유는 50장에서 본 원칙 때문입니다. TypeScript의 다른 타입 문법은 지우기만 하면 JavaScript가 되는데, enum은 실행 코드를 새로 만들어 내는 예외입니다.

enum — 쓸 수는 있지만 권장되지 않습니다 
enum Status { Idle, Loading, Success }

// 이유:
// ① 런타임 코드를 생성합니다 (타입은 사라진다는 원칙의 예외)
// ② 숫자 enum은 정의되지 않은 숫자도 통과시키는 등 동작이 직관적이지 않습니다
// ③ Node의 타입 제거, erasableSyntaxOnly 설정에서는 쓸 수 없습니다 (50장)

▶ Playground에 붙인 뒤 오른쪽 .JS 탭을 보세요. 타입 선언이었던 것이 JavaScript 객체를 만드는 코드로 바뀌어 있습니다. Node.js가 .ts 파일을 바로 실행할 때는 타입을 지우기만 하므로 이 변환을 할 수 없고, 그래서 enum이 있으면 실행이 실패합니다. 대신 쓸 수 있는 방법은 두 가지입니다.

권장 — 유니온 리터럴, 또는 as const 객체 
// ✅ 값 목록만 필요하면: 유니온 리터럴
type Status = "idle" | "loading" | "success";

// ✅ 코드에서 STATUS.IDLE 처럼 값으로도 쓰고 싶으면: as const 객체
const STATUS = {
  IDLE: "idle",
  LOADING: "loading",
  SUCCESS: "success"
} as const;

type StatusValue = typeof STATUS[keyof typeof STATUS];   // "idle" | "loading" | "success"

대부분은 첫 번째 방법인 유니온 리터럴로 충분합니다. 화면의 드롭다운을 만드는 것처럼 값 목록을 실행 중에 순회해야 할 때만 두 번째 방법을 씁니다. 마지막 줄의 keyof typeof STATUS는 "STATUS 객체의 키들"이라는 뜻이고, 전체로는 "STATUS 객체의 값들의 유니온"입니다. keyof와 typeof의 조합은 55장에서 차근차근 설명하니, 지금은 "객체에서 값 목록 타입을 뽑아내는 관용구"로만 알아 두세요.

🛠️ 현장 노트 — 자주 만나는 타입들

// DOM — querySelector는 Element | null 을 반환합니다
const input = document.querySelector("#email");
if (input instanceof HTMLInputElement) {
  input.value;     // ✅ input 전용 속성은 구체적인 타입이 확인된 뒤에 씁니다
}

// fetch 결과 — 반드시 타입을 붙이세요
interface Member { id: number; name: string; }
const response = await fetch("/api/members");
const members: Member[] = await response.json();
// response.json()은 any 를 반환합니다. 그대로 두면 검사가 사라집니다.

querySelector는 요소가 없을 수도 있고, 있어도 어떤 종류의 태그인지 모르므로 넓은 타입을 돌려줍니다. instanceof로 확인하면 그 안에서는 HTMLInputElement로 좁혀집니다. 다른 자료에서 흔히 보이는 as HTMLInputElement(타입 단언)는 확인 없이 믿으라고 하는 문법이라 위험한데, 54장에서 다룹니다. React의 이벤트 타입(React.ChangeEvent 등)은 56장에서 정리합니다. 또 fetch 결과에 타입을 붙여도 실제로 검사되는 것은 아니므로, 믿을 수 없는 데이터는 런타임 검증이 필요합니다(54장).

📌 요약

  • 타입 이름은 소문자. String이 아니라 string.
  • 튜플은 길이와 각 자리 타입이 정해진 배열. useState가 대표 예.
  • 배열 인덱스 접근은 기본적으로 undefined 가능성을 무시한다. noUncheckedIndexedAccess 권장.
  • 유니온으로 "이 중 하나"를, 리터럴 타입으로 "정확히 이 값"을 표현한다.
  • as const로 리터럴 타입을 고정하고, typeof X[number]로 값에서 타입을 뽑는다(55장).
  • ?와 | undefined는 다르다.
  • 콜백 매개변수는 대개 자동 추론된다.
  • enum 대신 유니온 리터럴이나 as const 객체를 쓴다. enum은 실행 코드를 만든다.
  • response.json()은 any다. 반드시 타입을 붙이고, 믿을 수 없으면 검증한다.
