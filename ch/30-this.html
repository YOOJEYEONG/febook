this는 "나"라는 말과 같습니다

"나는 배가 고프다"라는 문장을 떠올려 보세요. 이 문장만 보고는 "나"가 누구인지 알 수 없습니다. 철수가 말하면 철수, 영희가 말하면 영희입니다. 문장이 적힌 곳이 아니라 누가 말했느냐로 정해집니다.

this도 똑같습니다. 함수 안의 this는 "이 함수를 부른 주인공"을 가리키는 대명사이고, 함수를 부르는 그 순간에 정해집니다.

function introduce() {
  console.log("저는 " + this.name + "입니다");   // "나"에 해당하는 this
}
const chulsoo = { name: "철수", introduce };
const younghee = { name: "영희", introduce };

chulsoo.introduce();    // 저는 철수입니다 — 철수가 "말했다"
younghee.introduce();   // 저는 영희입니다 — 같은 함수, 다른 주인공

핵심 문장 하나

🔑 이것만 기억하면 됩니다

this는 함수가 어디서 선언되었는지가 아니라 어떻게 호출되었는지로 결정됩니다.
같은 함수라도 호출 방식이 다르면 this가 달라집니다. 그래서 함수 정의만 보고는 this를 알 수 없습니다. 호출하는 줄을 봐야 합니다.
(단 화살표 함수는 예외입니다. 화살표 함수에는 자기 this가 아예 없습니다.)

네 가지 규칙

아래에서 번호가 클수록 우선순위가 높습니다.

호출 방식this는
① 그냥 호출 fn()엄격 모드: undefined
느슨한 모드: 전역 객체(window)
② 메서드 호출 obj.fn()obj — 점 왼쪽의 객체
③ 명시 호출 fn.call(x)x — 직접 지정한 값
④ new 호출 new Fn() (32장)새로 만들어진 객체

new는 "이 함수를 틀로 써서 새 객체를 찍어 내라"는 키워드로, 32장에서 자세히 배웁니다. 지금은 ①②③만 확실히 알면 충분합니다.

this를 잃어버리는 순간

실무에서 겪는 this 문제의 99%는 메서드를 객체에서 떼어냈을 때 생깁니다.

💡 원인은 항상 같습니다

counter.increase는 함수 자체이지 "counter에 묶인 함수"가 아닙니다. 변수에 담거나 인자로 넘기는 순간 점 왼쪽이 사라져 그냥 함수가 됩니다. 그래서 호출할 때 this가 없습니다.
JavaScript의 함수는 객체에 소속되지 않습니다. 그저 그 객체의 속성 자리에 놓여 있을 뿐입니다.

화살표 함수의 this

화살표 함수는 자기 this를 만들지 않습니다. 그래서 this를 쓰면 자기가 선언된 위치의 바깥 this를 그대로 찾아 씁니다. 이것을 렉시컬(lexical) this라고 합니다.

상황써야 할 것
객체의 메서드메서드 축약 greet() {}
메서드 안의 콜백 (setTimeout, map 등)화살표 함수
클래스의 메서드일반 메서드 (필요하면 bind)
독립적인 유틸리티 함수둘 다 무방
this로 요소를 참조해야 하는 DOM 핸들러일반 함수, 또는 event.currentTarget

call, apply, bind

function introduce(greeting, punctuation) {
  return `${greeting}, ${this.name}${punctuation}`;
}
const user = { name: "홍길동" };

// call: this와 인자를 하나씩
introduce.call(user, "안녕하세요", "!");

// apply: 인자를 배열로 (전개 구문이 생긴 뒤로는 잘 안 씁니다)
introduce.apply(user, ["안녕하세요", "!"]);

// bind: 지금 실행하지 않고 this가 고정된 '새 함수'를 만든다
const bound = introduce.bind(user);
bound("안녕하세요", "!");

// bind는 인자도 미리 채울 수 있습니다 (부분 적용)
const hello = introduce.bind(user, "안녕");
hello("!");

🔗 bind는 실행하지 않습니다

call·apply는 즉시 실행하고, bind는 새 함수를 반환합니다. 이 차이가 핵심입니다. 그래서 이벤트 핸들러 등록처럼 나중에 실행될 함수에는 bind를 씁니다.
한 번 bind된 함수는 다시 바꿀 수 없습니다.

DOM 이벤트에서의 this

// 일반 함수: this = 이벤트가 걸린 요소 (currentTarget과 같음)
button.addEventListener("click", function (event) {
  console.log(this === event.currentTarget);   // true
  this.classList.add("active");
});

// 화살표 함수: this = 바깥 스코프의 this (요소가 아님!)
button.addEventListener("click", (event) => {
  event.currentTarget.classList.add("active");   // ✅ 이렇게 쓰세요
});

🎯 target과 currentTarget은 다릅니다

  • event.target — 실제로 클릭된 가장 안쪽 요소 (버튼 안의 아이콘일 수도 있습니다)
  • event.currentTarget — 핸들러가 등록된 요소 (항상 버튼)

이벤트 위임(38장)에서 이 구분이 결정적입니다.

클래스에서의 this

class는 같은 모양의 객체를 여러 개 찍어 내는 틀입니다(32장). 32장을 읽은 뒤 돌아와 보면 더 잘 이해됩니다.

class Counter {
  count = 0;

  // 일반 메서드 — 떼어내면 this를 잃습니다
  increase() { this.count++; }

  // 클래스 필드 + 화살표 함수 — this가 인스턴스에 고정됩니다
  decrease = () => { this.count--; };
}

const c = new Counter();
const inc = c.increase;
const dec = c.decrease;

// inc();   ❌ TypeError — this가 undefined
dec();      // ✅ 정상 동작

React 클래스 컴포넌트 시절에는 생성자에서 this.handleClick = this.handleClick.bind(this)를 줄줄이 쓰는 코드가 흔했습니다. 지금은 함수형 컴포넌트와 훅을 쓰기 때문에(8부) React를 쓴다면 this를 거의 만나지 않습니다.

🛠️ 현장 노트 — 가장 실용적인 조언

this를 피할 수 있으면 피하세요. 현대 프론트엔드는 함수와 모듈 위주로 짜기 때문에 this가 필요한 상황이 크게 줄었습니다.
그럼에도 배워야 하는 이유는 남의 코드와 라이브러리를 읽어야 하기 때문이고, 면접에서 반드시 물어보기 때문입니다. "호출 방식이 결정한다"는 한 문장과 위의 네 규칙만 정확히 말할 수 있으면 충분합니다.

📌 요약

  • this는 "나"라는 대명사처럼 누가 불렀느냐로 정해진다.
  • this는 선언 위치가 아니라 호출 방식이 결정한다.
  • 규칙 4가지: 그냥 호출(undefined/전역) · 메서드 호출(점 왼쪽) · call/bind(지정) · new(새 객체).
  • 메서드를 변수에 담거나 콜백으로 넘기면 점 왼쪽이 사라져 this를 잃는다.
  • 화살표 함수는 자기 this가 없어 바깥 것을 쓴다. bind로도 바꿀 수 없다.
  • 객체 메서드에는 축약 문법, 메서드 안의 콜백에는 화살표 함수.
  • call·apply는 즉시 실행, bind는 새 함수를 반환한다.
  • DOM 핸들러에서는 this 대신 event.currentTarget이 안전하다.
