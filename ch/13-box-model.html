모든 요소는 상자다

CSS에서 화면의 모든 것은 사각형 상자입니다. 둥근 버튼도, 원형 프로필 사진도 사실은 사각형 상자에 border-radius를 준 것입니다. 그 상자는 네 겹으로 되어 있습니다.

박스 모델 
┌─────────── margin (바깥 여백, 투명) ────────────┐
│  ┌────────── border (테두리) ────────────────┐  │
│  │  ┌──────── padding (안쪽 여백) ────────┐  │  │
│  │  │                                    │  │  │
│  │  │           content (내용)           │  │  │
│  │  │                                    │  │  │
│  │  └────────────────────────────────────┘  │  │
│  └──────────────────────────────────────────┘  │
└────────────────────────────────────────────────┘
겹역할배경색이 칠해지나
content글자·이미지가 들어가는 실제 내용O
padding내용과 테두리 사이의 여백O ← 자주 헷갈립니다
border테두리 선—
margin다른 요소와의 바깥 거리X — 항상 투명

🎁 언제 padding, 언제 margin?

상자 안쪽을 넓히고 싶으면 padding, 상자끼리 띄우고 싶으면 margin.
버튼의 글자 주변을 넉넉하게 → padding (배경색도 함께 넓어져야 하므로)
버튼과 버튼 사이 간격 → margin

여백 축약 표기

padding: 10px;                 /* 네 방향 모두 */
padding: 10px 20px;            /* 위아래 10, 좌우 20 */
padding: 10px 20px 30px;       /* 위 10, 좌우 20, 아래 30 */
padding: 10px 20px 30px 40px;  /* 위 → 오른쪽 → 아래 → 왼쪽 (시계 방향) */

값이 두 개일 때는 "세로 가로" 순서, 네 개일 때는 12시부터 시계 방향입니다. margin도 규칙이 같습니다.

box-sizing — 반드시 바꿔야 하는 기본값

width: 300px이라고 쓰면, 그 300px은 무엇의 너비일까요? CSS의 원래 기본값에서는 content만의 너비입니다.

기본값의 문제 
.card {
  width: 300px;
  padding: 20px;
  border: 2px solid;
}
/* content-box(기본값) 기준 실제 차지하는 너비:
   300 + 20(왼쪽 padding) + 20(오른쪽) + 2 + 2 = 344px  ← 예상 밖 */

"너비를 300으로 정했는데 344가 되는" 이 동작은 직관에 어긋납니다. 그래서 거의 모든 프로젝트가 이 한 줄로 시작합니다.

사실상의 표준 초기화 
*, *::before, *::after {
  box-sizing: border-box;
}

border-box에서는 width가 border까지 포함한 전체 너비가 됩니다. padding을 늘려도 전체 크기는 300px 그대로이고, 안쪽 내용 영역만 줄어듭니다. "내가 정한 크기가 그대로 지켜지는" 훨씬 예측 가능한 동작입니다.

display

값동작
block혼자 한 줄. 너비·높이·상하 여백 모두 적용. div, p, h1의 기본값
inline글자처럼 흐름. 너비·높이 무시, 상하 margin 무시. span, a, strong의 기본값
inline-block옆으로 나열되면서 크기 지정은 가능. 둘의 절충
flex자식들을 한 줄(또는 한 열)로 배치(15장)
grid자식들을 격자로 배치(16장)
none렌더 트리에서 제거. 자리도 사라짐
contents상자만 없애고 자식은 그대로 남긴다. 중간 래퍼를 지울 때 유용하지만 일부 요소에서 접근성 문제가 보고되어 주의가 필요합니다

📏 인라인 요소에는 크기가 먹지 않습니다

<span>에 width: 200px을 줬는데 아무 변화가 없는 이유입니다. 인라인 요소는 내용만큼만 차지하며, 위아래 margin도 무시합니다. (좌우 margin과 padding은 적용되지만, 위아래 padding은 공간을 밀어내지 않고 다른 요소와 겹칩니다.)
크기를 주고 싶으면 display: inline-block 또는 block으로 바꿔야 합니다.

마진 상쇄 — 여백이 사라지는 현상

"위 요소에 margin-bottom: 30px, 아래 요소에 margin-top: 20px을 줬는데 간격이 50px이 아니라 30px이다." 버그가 아니라 명세대로의 동작입니다.

수직 방향 인접 마진은 합쳐지고, 그중 큰 값 하나만 적용됩니다. 이것을 마진 상쇄라고 합니다.

일어나는 경우설명
형제 사이위 요소의 아래 마진과 아래 요소의 위 마진
부모와 첫/막내 자식 사이부모에 border·padding이 없으면 자식의 마진이 부모 밖으로 삐져나갑니다
빈 요소내용이 없는 요소의 위·아래 마진끼리도 상쇄됩니다

가로 방향에서는 일어나지 않습니다. 또 다음 상황에서는 상쇄가 일어나지 않습니다.

  • 부모가 display: flex 또는 grid인 경우 — 이것이 현대적인 해결책입니다
  • position: absolute·fixed인 요소
  • 부모에 overflow가 visible이 아닌 값이거나, padding·border가 있는 경우

🛠️ 현장 노트 — 마진 상쇄와 싸우지 마세요

요즘 실무에서는 마진 상쇄를 우회하는 트릭을 배우기보다 애초에 겪지 않는 방식으로 만듭니다.

  • 부모에 display: flex; flex-direction: column; gap: 20px;을 주면 간격이 정확히 20px입니다. 상쇄가 없습니다.
  • 또는 마진을 한 방향으로만 씁니다. "모든 요소는 margin-bottom만 쓴다" 같은 팀 규칙을 정하면 대부분 해결됩니다.

overflow

값동작
visible (기본)상자 밖으로 그냥 넘쳐 나옵니다
hidden넘친 부분을 잘라냅니다. 스크롤도 불가하므로 내용 손실에 주의
scroll항상 스크롤바 표시
auto필요할 때만 스크롤바. 대부분 이것이 정답
cliphidden과 비슷하되 프로그램적 스크롤도 막습니다

overflow-x·overflow-y로 방향별 지정도 가능합니다. 넓은 표를 감쌀 때 overflow-x: auto를 쓰면 페이지 전체가 가로로 밀리지 않고 표만 스크롤됩니다. 모바일 대응에서 자주 쓰는 기법입니다.

⚠️ overflow: hidden은 만능 해결책이 아닙니다

레이아웃이 삐져나올 때 습관적으로 붙이는 경우가 많은데, 내용이 잘려 나가 사용자가 볼 수 없게 되는 부작용이 있습니다. 글자 크기를 키워 쓰는 사용자, 긴 번역문이 들어간 다국어 화면에서 특히 위험합니다. 근본 원인(고정 높이, 넘치는 너비)을 먼저 찾으세요.

크기 관련 속성

.box {
  width: 100%;
  max-width: 600px;   /* 아무리 커져도 600px까지만 → 반응형의 핵심 */
  min-height: 200px;  /* 내용이 적어도 최소 200px */
  aspect-ratio: 16 / 9;  /* 가로세로 비율 고정 */
}

width: 100%; max-width: 600px; 조합은 반응형 레이아웃의 가장 기본 패턴입니다. 좁은 화면에서는 화면을 꽉 채우고, 넓은 화면에서는 600px에서 멈춥니다.

📌 요약

  • 모든 요소는 content → padding → border → margin 네 겹의 상자다.
  • padding에는 배경이 칠해지고, margin은 항상 투명하다.
  • *, *::before, *::after { box-sizing: border-box; } 는 사실상 필수 초기화.
  • 인라인 요소는 너비·높이·상하 마진이 적용되지 않는다.
  • 수직 마진은 상쇄된다. flex·grid를 쓰거나 마진을 한 방향으로만 쓰면 겪지 않는다.
  • 넘치는 내용은 overflow: auto가 대체로 정답. hidden은 내용을 없앤다.
  • width: 100%; max-width: …;가 반응형의 기본 패턴.
