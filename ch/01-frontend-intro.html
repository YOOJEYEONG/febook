1장. 프론트엔드 개발자는 무슨 일을 하나

프론트엔드란 무엇인가

프론트엔드(front-end)는 "앞단"이라는 뜻입니다. 여기서 앞이란 사용자 쪽을 말합니다. 여러분이 지금 이 글을 보고 있는 화면, 방금 누른 버튼, 스크롤할 때 부드럽게 따라오는 목차 — 사용자가 직접 보고 만지는 모든 것이 프론트엔드입니다.

반대말은 백엔드(back-end), 즉 "뒷단"입니다. 회원 정보를 저장하는 데이터베이스, 결제를 처리하는 로직, 주문 내역을 계산하는 코드처럼 사용자에게 보이지 않는 곳에서 돌아가는 부분입니다.

🍽️ 식당으로 비유하면

홀이 프론트엔드입니다. 메뉴판의 디자인, 테이블 배치, 종업원이 주문을 받는 방식. 손님이 경험하는 전부죠. 주방이 백엔드입니다. 재료를 어디에 보관하는지, 어떤 순서로 조리하는지. 손님은 볼 수 없지만 없으면 식당이 돌아가지 않습니다.

홀 담당자는 요리를 못 해도 됩니다. 대신 손님이 원하는 것을 정확히 주방에 전달하고, 나온 음식을 보기 좋게 내놓는 일을 잘해야 합니다. 프론트엔드 개발자가 하는 일이 정확히 그것입니다.

둘을 가르는 진짜 기준: 코드가 어디서 실행되는가

"보이는 것 = 프론트엔드"는 이해를 돕는 설명이지 정확한 정의는 아닙니다. 현업에서 쓰는 더 정확한 기준은 코드가 어느 컴퓨터에서 실행되는가입니다.

프론트엔드백엔드
실행되는 곳사용자의 기기(휴대폰·노트북)에 설치된 브라우저회사가 운영하는 서버 컴퓨터
주로 쓰는 언어HTML, CSS, JavaScript(및 TypeScript)제한 없음 — Java, Python, Go, Node.js, Ruby 등
코드 공개 여부사용자에게 전부 전달된다. 누구나 열어볼 수 있다서버 안에만 있다. 외부에서 볼 수 없다
대표적인 일화면 구성, 상호작용, 입력 검증, 성능·접근성데이터 저장, 인증, 결제, 비즈니스 규칙

⚠️ 지금 당장 기억할 한 가지

프론트엔드 코드는 사용자에게 통째로 전달됩니다. 브라우저에서 "페이지 소스 보기"를 누르면 남의 사이트 코드도 그대로 보입니다. 그래서 비밀번호, API 키, 결제 정보 같은 비밀은 절대 프론트엔드 코드에 넣으면 안 됩니다. 이 원칙은 78장 보안에서 다시 자세히 다룹니다.

웹을 만드는 세 가지 언어

프론트엔드는 세 언어로 만들어집니다. 셋은 경쟁 관계가 아니라 역할 분담입니다.

🏠 집짓기 비유

  • HTML = 뼈대와 구조. 여기가 거실, 저기가 방, 이건 문.
  • CSS = 마감과 인테리어. 벽 색, 창문 크기, 가구 배치.
  • JavaScript = 전기와 설비. 스위치를 누르면 불이 켜지고, 초인종을 누르면 소리가 난다.

HTML — 구조와 의미

HTML은 HyperText Markup Language의 약자입니다. 이름 그대로 마크업(markup) 언어, 즉 "이 부분은 제목이다", "이건 문단이다", "이건 목록이다" 하고 글에 표시를 달아주는 언어입니다. 계산을 하거나 조건에 따라 다르게 동작하지 않기 때문에 엄밀히는 프로그래밍 언어가 아닙니다.

HTML 
<h1>오늘의 할 일</h1>
<p>장을 보고 저녁을 준비합니다.</p>
<ul>
  <li>우유</li>
  <li>달걀</li>
</ul>

<h1>은 "heading 1", 가장 큰 제목입니다. <p>는 paragraph(문단), <ul>은 unordered list(순서 없는 목록), <li>는 list item(목록 항목)입니다. 이렇게 꺾쇠 괄호로 감싼 표시를 태그라고 부릅니다.

CSS — 보이는 모습

CSS는 Cascading Style Sheets의 약자입니다. HTML이 만든 구조에 색·크기·간격·배치를 입힙니다. 1996년 W3C 권고안으로 처음 공식화되었고, 지금까지 계속 확장되고 있습니다.

CSS 
h1 {
  color: #1f5f4f;   /* 글자색 */
  font-size: 28px;  /* 글자 크기 */
}

JavaScript — 동작

JavaScript는 브라우저 안에서 돌아가는 프로그래밍 언어입니다. 버튼을 누르면 창이 열리고, 입력값이 틀리면 경고를 띄우고, 서버에서 새 데이터를 받아오는 — 변화하는 모든 것을 담당합니다.

JavaScript 
const button = document.querySelector("button");
button.addEventListener("click", () => {
  alert("버튼을 눌렀습니다!");
});

🚫 자주 하는 오해

오해 — JavaScript는 Java의 간단한 버전이다. 사실 — 완전히 다른 언어입니다. 1995년 넷스케이프의 브렌던 아이크(Brendan Eich)가 만들었을 때, 당시 인기 있던 Java의 유명세에 편승하려고 마케팅 차원에서 붙인 이름일 뿐입니다. 문법도, 쓰임새도, 만든 회사도 다릅니다. "인도"와 "인도네시아"만큼 무관하다고 생각하면 됩니다.

셋이 함께 동작하는 모습

말로 백 번 듣는 것보다 한 번 돌려보는 게 낫습니다. 아래는 세 언어를 한 파일에 담은 예제입니다. 코드를 직접 고쳐 보세요. 오른쪽 결과가 바로 바뀝니다. 망가뜨려도 되돌리기 버튼이 있습니다.

지금 이 코드가 한 줄도 이해되지 않아도 전혀 문제없습니다. 지금 필요한 건 "구조를 만들고(HTML), 꾸미고(CSS), 움직이게 한다(JavaScript)"는 그림 하나뿐입니다. 문법은 6장부터 하나씩 뜯어봅니다.

프론트엔드 개발자가 실제로 하는 일

"화면 예쁘게 만드는 사람"은 절반만 맞는 설명입니다. 실무에서 하는 일은 이렇습니다.

일구체적으로이 책에서
화면 구현디자이너가 준 시안을 실제로 동작하는 화면으로 만든다2·3부
상태 관리"장바구니에 담긴 상품", "로그인 여부" 같은 변하는 정보를 화면과 어긋나지 않게 관리한다8부
서버 연동백엔드가 만든 API를 호출해 데이터를 받아 화면에 뿌린다. 로딩 중·실패 상황까지 처리한다5·8부
성능페이지가 늦게 뜨면 사용자는 떠납니다. 무엇이 느린지 측정하고 고친다10부
접근성눈이 보이지 않는 사용자, 마우스를 못 쓰는 사용자도 쓸 수 있게 만든다11장·77장
협업Git으로 코드를 관리하고, 코드 리뷰를 하고, 기획·디자인·백엔드와 조율한다6부·82장

🛠️ 현장 노트

신입 때 가장 많이 오해하는 부분: 코딩 실력보다 "왜 이렇게 만드는가"를 묻는 능력이 더 중요합니다. "이 버튼을 눌렀을 때 데이터가 아직 안 왔으면 어떻게 보여줄까요?", "이 목록이 1만 개면요?" — 이런 질문을 먼저 던지는 사람이 실무에서 훨씬 빨리 성장합니다.

그리고 실제 업무 시간의 상당 부분은 새 코드를 쓰는 게 아니라 남이 쓴 코드를 읽는 데 씁니다. 그래서 이 책은 문법뿐 아니라 "이 코드가 왜 이렇게 생겼는가"를 계속 설명합니다.

브라우저는 하나가 아니다

우리가 만든 코드를 실제로 해석해서 화면에 그리는 프로그램이 브라우저입니다. 브라우저의 핵심 부품을 렌더링 엔진이라고 부르는데, 2026년 현재 실질적으로 세 종류입니다.

렌더링 엔진쓰는 브라우저
BlinkChrome, Edge, Opera, 삼성 인터넷, 웨일 등 대다수
WebKitSafari (그리고 iOS에서는 오랫동안 모든 브라우저가 이 엔진을 써야 했습니다)
GeckoFirefox

엔진이 다르면 같은 코드가 미묘하게 다르게 보일 수 있습니다. 그래서 프론트엔드 개발자는 "내 크롬에서는 잘 되는데요"가 통하지 않는 직업입니다. 새 기능을 쓸 때는 어느 브라우저가 지원하는지 확인하는 습관이 필요하고, 이 책은 그런 기능이 나올 때마다 지원 범위를 함께 적습니다.

이 책의 지도

84개 챕터는 아무 순서가 아닙니다. 앞 챕터를 알아야 뒤 챕터가 이해되는 순서로 쌓여 있습니다.

  1. 1부 — 웹의 원리(2~5장). 코드를 쓰기 전에, 인터넷에서 페이지 하나가 뜨기까지 무슨 일이 벌어지는지 봅니다. 이걸 건너뛰면 나중에 나오는 문제 대부분이 "마법"처럼 보입니다.
  2. 2~3부 — HTML과 CSS(6~22장). 보이는 것을 직접 만듭니다. 여기까지만 해도 간단한 웹 페이지는 혼자 만들 수 있습니다.
  3. 4~5부 — JavaScript(23~43장). 이 책에서 가장 두꺼운 부분이고, 가장 중요합니다. React를 잘 쓰는 사람과 못 쓰는 사람의 차이는 결국 JavaScript 실력에서 갈립니다.
  4. 6~7부 — 도구와 TypeScript(44~56장). 혼자 파일 하나 만들던 단계에서 벗어나, 실무 개발자의 작업 환경을 갖춥니다.
  5. 8~9부 — React와 Next.js(57~74장). 현재 채용 공고에서 가장 많이 요구하는 기술입니다.
  6. 10부 — 품질·성능·보안(75~79장). 주니어와 시니어를 가르는 영역입니다.
  7. 11부 — 실전과 커리어(80~84장). 배운 것을 결과물과 이력으로 바꿉니다.

⏳ 속도에 대한 현실적인 조언

하루에 한 챕터씩이면 약 3개월입니다. 조급해하지 마세요. 진도보다 중요한 건 예제를 직접 고쳐 보는 것입니다. 읽기만 한 챕터는 대부분 일주일 안에 잊힙니다. 코드를 한 줄이라도 바꿔 본 챕터는 남습니다. 이 책의 모든 실행기는 그래서 있습니다.

📌 요약

  • 프론트엔드 = 사용자의 브라우저에서 실행되는 코드. 백엔드 = 서버에서 실행되는 코드.
  • 프론트엔드 코드는 사용자에게 전부 전달되므로 비밀을 담으면 안 된다.
  • HTML은 구조, CSS는 모습, JavaScript는 동작을 담당한다.
  • HTML은 마크업 언어라 프로그래밍 언어가 아니다. JavaScript는 Java와 무관하다.
  • 브라우저 렌더링 엔진은 Blink·WebKit·Gecko 세 갈래이고, 결과가 다를 수 있다.
  • 실무는 화면 구현뿐 아니라 상태 관리·서버 연동·성능·접근성·협업을 포함한다.
