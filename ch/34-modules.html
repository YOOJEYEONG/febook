모듈이 없던 시절

2015년 이전의 흔한 코드 
<script src="jquery.js"></script>
<script src="utils.js"></script>
<script src="app.js"></script>

모든 파일이 같은 전역 공간을 공유했습니다. 문제가 세 가지였습니다.

  • 이름 충돌 — utils.js의 format과 다른 파일의 format이 서로를 덮어씀
  • 순서 의존 — <script> 순서를 하나 바꾸면 페이지가 깨짐
  • 의존 관계가 안 보임 — 이 파일이 무엇을 필요로 하는지 코드에 드러나지 않음

2015년(ES2015)에 언어 차원의 표준 모듈 시스템 ESM이 도입되어 이 문제들이 해결되었습니다.

export

math.js — 이름 있는 내보내기 
// 선언과 동시에
export const PI = 3.14159;
export function add(a, b) { return a + b; }
export class Calculator { }

// 또는 아래에서 한 번에 (이 방식이 무엇을 공개하는지 한눈에 보입니다)
const subtract = (a, b) => a - b;
const multiply = (a, b) => a * b;
export { subtract, multiply };

// 이름을 바꿔서
export { multiply as times };
Button.js — 기본 내보내기 (파일당 하나) 
export default function Button() { }

// 기본과 이름 있는 것을 함께 쓸 수도 있습니다
export const SIZES = ["sm", "md", "lg"];

import

// 이름 있는 가져오기 — 중괄호 필수, 이름이 정확히 일치해야 함
import { add, PI } from "./math.js";

// 이름 바꾸기
import { add as sum } from "./math.js";

// 기본 가져오기 — 중괄호 없음, 이름은 마음대로
import Button from "./Button.js";
import MyButton from "./Button.js";     // 같은 것. 이름 자유

// 섞어서
import Button, { SIZES } from "./Button.js";

// 전부 하나의 객체로
import * as math from "./math.js";
math.add(1, 2);

// 실행만 (부수 효과 목적. CSS 파일 등)
import "./styles.css";

🎯 default와 named, 헷갈리는 지점

기본 (default)이름 있는 (named)
개수파일당 하나여러 개
중괄호없음필수
이름가져올 때 자유정확히 일치해야 함
오타 시알 수 없음 (다른 이름으로 받아짐)즉시 오류 — 안전

이름 있는 내보내기를 기본으로 쓰는 것을 권합니다. 오타를 도구가 잡아 주고, 자동 완성이 정확하며, 이름이 파일마다 제각각이 되는 일을 막습니다. React 컴포넌트처럼 관례상 default를 쓰는 경우만 예외로 두면 됩니다.

모듈의 세 가지 성질

성질내용
독립된 스코프모듈 안의 최상위 변수는 전역이 아닙니다. var를 써도 window에 붙지 않습니다
자동 엄격 모드"use strict"를 쓸 필요가 없습니다
단 한 번만 평가여러 파일이 같은 모듈을 가져와도 실행은 한 번. 그 결과를 공유합니다
"한 번만 평가"의 실용적 의미 — 자연스러운 싱글턴 
// config.js
console.log("설정 초기화");        // 몇 번 import 해도 한 번만 출력됩니다
export const config = { theme: "dark" };

// a.js
import { config } from "./config.js";
config.theme = "light";

// b.js
import { config } from "./config.js";
console.log(config.theme);   // "light" — 같은 객체를 봅니다

🔗 import는 복사가 아니라 살아 있는 연결입니다

// counter.js
export let count = 0;
export function increase() { count++; }

// main.js
import { count, increase } from "./counter.js";
console.log(count);   // 0
increase();
console.log(count);   // 1  ← 값을 복사해 온 것이 아닙니다

count = 100;          // ❌ TypeError — 가져온 바인딩은 읽기 전용

HTML에서 쓰기

<script type="module" src="main.js"></script>
일반 script와 다른 점
기본으로 defer처럼 동작합니다 (파싱을 막지 않고 DOM 완성 후 실행)
같은 모듈을 여러 번 불러도 한 번만 실행됩니다
CORS 규칙이 적용됩니다. 그래서 file://로 열면 대개 실패합니다 — 로컬 서버가 필요합니다
경로에 확장자를 생략할 수 없습니다 ("./math.js"). 번들러를 쓰면 생략 가능해집니다

🚫 file://로 열면 모듈이 동작하지 않습니다

파일을 더블클릭해서 연 페이지에서 type="module"을 쓰면 CORS 오류가 납니다. 모듈은 CORS 규칙을 따르는데 file://에는 출처가 없기 때문입니다. 간단한 로컬 서버(44·46장)를 띄우면 해결됩니다. 참고로 이 책 자체가 모듈을 쓰지 않는 이유가 바로 이것입니다 — 파일을 더블클릭해도 열리도록.

동적 import

// 정적 import는 파일 맨 위에서만, 조건 없이
import { heavy } from "./heavy.js";

// 동적 import는 어디서든, 조건부로. Promise를 반환합니다
button.addEventListener("click", async () => {
  const { Chart } = await import("./chart-library.js");
  new Chart(canvas, data);
});

// 조건에 따라 다른 모듈
const locale = navigator.language.startsWith("ko") ? "ko" : "en";
const messages = await import(`./locales/${locale}.js`);

📦 코드 분할의 출발점

차트 라이브러리가 300KB인데 사용자의 5%만 차트를 본다면, 나머지 95%에게 그 파일을 내려보내는 것은 낭비입니다. 동적 import()는 필요한 순간에만 내려받게 합니다. 번들러는 이 지점을 인식해 파일을 자동으로 쪼갭니다(47장). React의 lazy()도 내부적으로 이것을 씁니다(69장).

CommonJS와의 차이

Node.js는 ESM이 표준이 되기 전부터 CommonJS라는 자체 모듈 시스템을 써 왔습니다. 지금도 수많은 패키지가 이 방식으로 되어 있어 둘 다 알아야 합니다.

CommonJSESM
내보내기module.exports = {}export
가져오기const x = require("./m")import x from "./m"
시점실행 중(동기적)정적 분석 가능
조건부 로드가능 (if 안에서 require)정적 import는 불가, import()는 가능
트리 셰이킹어려움가능 — 안 쓰는 코드 제거(47장)
주 사용처과거 Node.js현재 표준 — 브라우저·Node 모두

Node.js에서 ESM을 쓰려면 package.json에 "type": "module"을 넣거나 파일 확장자를 .mjs로 씁니다(46장).

모듈 설계 실습

🛠️ 현장 노트 — 모듈 관련 실무 팁

  1. 이름 있는 내보내기를 기본으로. 오타를 도구가 잡아 줍니다.
  2. 배럴 파일(index.js에서 모아 다시 내보내기)은 편하지만 남용하면 순환 참조와 번들 크기 문제를 만듭니다. 깊은 폴더에서만 쓰세요.
  3. 순환 참조를 피하세요. A가 B를, B가 A를 가져오면 한쪽이 undefined로 보이는 미묘한 버그가 납니다. 공통 부분을 세 번째 파일로 빼는 것이 해법입니다.
  4. import 순서를 정리하세요. 보통 외부 라이브러리 → 내부 모듈 → 스타일 순으로 씁니다. ESLint가 자동 정렬해 줍니다(48장).

📌 요약

  • 모듈은 이름 충돌·순서 의존·불투명한 의존 관계를 해결한다.
  • export default는 파일당 하나·중괄호 없음·이름 자유. 이름 있는 내보내기가 더 안전하다.
  • 모듈은 독립 스코프 + 자동 엄격 모드 + 단 한 번만 평가된다.
  • import는 값 복사가 아니라 읽기 전용 연결이다.
  • <script type="module">은 defer처럼 동작하고 CORS를 따르므로 file://에서 실패한다.
  • import()는 필요할 때 불러오기. 코드 분할의 출발점.
  • CommonJS는 require, ESM은 import. ESM만 트리 셰이킹이 가능하다.
  • 순환 참조를 피한다.
