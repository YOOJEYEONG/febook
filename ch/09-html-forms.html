9장. 폼과 사용자 입력

이 챕터에서 배우는 것

  • <form>이 실제로 하는 일과 action·method
  • <label>을 연결해야 하는 진짜 이유
  • 입력 타입을 상황에 맞게 고르는 법 (모바일 경험이 크게 달라집니다)
  • HTML만으로 되는 유효성 검사와 그 한계
  • <button>이 폼을 새로고침시키는 이유

읽는 데 약 22분 · 실무에서 가장 자주 만드는 화면입니다

form 요소

기본 구조 
<form action="/signup" method="post">
  <label for="email">이메일</label>
  <input type="email" id="email" name="email" required>

  <button type="submit">가입하기</button>
</form>
속성뜻
action제출 시 데이터를 보낼 주소. 생략하면 현재 주소
methodget(기본) 또는 post
enctype파일 업로드가 있으면 multipart/form-data가 필요합니다
novalidate브라우저 내장 검사를 끕니다

🔑 name이 없으면 전송되지 않습니다

서버는 name=값 형태로 데이터를 받습니다. id는 브라우저 안에서 요소를 가리키는 이름일 뿐 전송과 무관합니다. name을 빠뜨리면 그 칸의 값은 통째로 사라집니다. 신입이 가장 자주 겪는 폼 버그입니다.

GET과 POST의 차이

method="get"method="post"
데이터 위치주소창에 ?email=a@b.com으로 붙음요청 본문에 담김
북마크·공유가능 (검색 결과 페이지에 적합)불가능
기록 남음브라우저 히스토리·서버 로그에 그대로주소에는 남지 않음
용도조회. 검색, 필터변경. 가입, 로그인, 주문

⚠️ 로그인 폼에 GET을 쓰면 안 되는 이유

비밀번호가 주소창에 그대로 보이고, 브라우저 히스토리·서버 접근 로그·중간 장비 로그에 전부 평문으로 남습니다. class="term" data-term="https">HTTPS를 써도 주소 자체는 브라우저와 서버 로그에 기록됩니다. 비밀번호를 다루는 폼은 반드시 POST입니다.

label — 가장 중요한 폼 요소

두 가지 연결 방법 
<!-- 방법 1: for 와 id 를 맞춘다 (권장) -->
<label for="username">아이디</label>
<input type="text" id="username" name="username">

<!-- 방법 2: label 로 감싼다 -->
<label>
  아이디
  <input type="text" name="username">
</label>

label을 제대로 연결하면 세 가지가 공짜로 따라옵니다.

  1. 글자를 눌러도 입력 칸이 활성화됩니다. 체크박스처럼 작은 요소에서는 사용성 차이가 큽니다.
  2. 스크린 리더가 "아이디, 편집 창"이라고 읽어 줍니다. 연결이 없으면 그냥 "편집 창"입니다. 무엇을 입력하라는 건지 알 수 없습니다.
  3. 자동 완성이 더 정확해집니다.

🚫 placeholder는 label이 아닙니다

오해 — 칸 안에 회색 글씨로 "이메일"이라고 써 두면 label은 필요 없다. 사실 — placeholder는 입력을 시작하면 사라집니다. 긴 폼을 채우다 보면 이 칸이 뭐였는지 확인할 방법이 없어집니다. 게다가 회색 글씨는 명도 대비가 낮아 읽기 어렵고, 스크린 리더 지원도 브라우저마다 다릅니다. placeholder는 예시(placeholder="hong@example.com")를 보여주는 용도이지 이름표의 대체재가 아닙니다.

입력 타입 고르기

type을 제대로 고르면 모바일 키보드가 바뀝니다. 이것만으로 사용성이 크게 달라집니다.

type용도얻는 것
text일반 텍스트기본
email이메일@ 키가 있는 키보드, 형식 검사
tel전화번호숫자 키패드. 형식 검사는 안 함(국가마다 다르므로)
number수량·나이 등 계산할 숫자증감 버튼, 숫자 키보드
password비밀번호글자 가림
search검색어지우기 버튼, 키보드에 "검색"
url주소/ .com 키, 형식 검사
date / time / datetime-local날짜·시간브라우저 기본 달력·시계
checkbox여러 개 선택 가능—
radio여럿 중 하나. 같은 name으로 묶는다—
file파일accept, multiple 사용 가능
range대략적인 값슬라이더
color색색 선택기
hidden사용자에게 안 보이는 값보안 수단이 아닙니다. 소스에 그대로 보입니다

📱 전화번호에 type="number"를 쓰지 마세요

number는 계산할 수 있는 수를 위한 타입입니다. 전화번호에 쓰면 맨 앞 0이 사라질 수 있고, 증감 화살표가 나오며, -를 입력할 수 없어 곤란해집니다. 전화번호·우편번호·카드번호는 type="tel"이 맞습니다. 숫자 키패드도 그대로 나옵니다.

HTML만으로 하는 유효성 검사

속성검사 내용
required비어 있으면 제출 불가
minlength / maxlength글자 수
min / max / step숫자·날짜 범위
pattern정규표현식 형식(42장)
type="email" 등타입에 맞는 형식

🔓 이 검사는 보안이 아닙니다

브라우저 검사는 사용자를 도와주는 편의 기능입니다. 개발자 도구를 열어 required를 지우면 그대로 제출됩니다. 악의적인 사람은 브라우저를 거치지 않고 서버에 직접 요청을 보낼 수도 있습니다. 서버는 들어오는 모든 값을 다시 검사해야 합니다. 프론트엔드 검사는 친절, 백엔드 검사는 안전입니다. 둘 다 필요합니다.

오류 표시 시점 — :invalid보다 :user-invalid

CSS의 :invalid를 쓰면 페이지를 열자마자 빈 칸이 전부 빨갛게 됩니다. 아직 아무것도 안 했는데 혼나는 기분이 들죠. :user-invalid는 사용자가 실제로 입력하거나 제출을 시도한 뒤에만 적용됩니다. Chrome·Firefox·Safari 모두 지원합니다.

select, textarea, fieldset

선택과 여러 줄 입력 
<label for="city">도시</label>
<select id="city" name="city">
  <option value="">선택하세요</option>
  <optgroup label="수도권">
    <option value="seoul">서울</option>
    <option value="incheon">인천</option>
  </optgroup>
</select>

<label for="memo">메모</label>
<textarea id="memo" name="memo" rows="4"></textarea>

<textarea>는 value 속성이 없습니다. 태그 사이의 내용이 값입니다. 그래서 초기값을 넣으려면 태그 사이에 씁니다. 여는 태그 뒤 줄바꿈은 하나까지 무시됩니다.

라디오 버튼 묶기 
<fieldset>
  <legend>배송 방법</legend>

  <input type="radio" id="fast" name="shipping" value="fast" checked>
  <label for="fast">빠른 배송</label>

  <input type="radio" id="normal" name="shipping" value="normal">
  <label for="normal">일반 배송</label>
</fieldset>
  • 라디오 버튼은 name이 같아야 한 묶음이 되어 하나만 선택됩니다. name이 다르면 전부 따로 켜집니다.
  • <fieldset>+<legend>는 묶음 전체의 질문을 알려 줍니다. 스크린 리더가 "배송 방법 그룹, 빠른 배송 라디오 버튼"이라고 읽습니다. 없으면 그냥 "빠른 배송"만 들려 무엇에 대한 선택인지 알 수 없습니다.

button — 반드시 알아야 할 함정

💥 <form> 안의 <button>은 기본이 submit입니다

버튼을 하나 추가했는데 누르면 페이지가 새로고침되는 현상. 초보자가 몇 시간씩 잡아먹는 문제이고, 원인은 이것입니다.

<form>
  <button>미리보기</button>          <!-- ❌ type 생략 = submit -->
  <button type="button">미리보기</button>  <!-- ✅ 그냥 버튼 -->
</form>
type동작
submit (폼 안에서 기본값)폼 제출
button아무 기본 동작 없음. JavaScript 전용
reset폼 초기화. 실무에서는 거의 쓰지 않습니다 — 실수로 눌러 다 날리는 사고가 흔합니다

자동 완성

autocomplete 속성은 브라우저가 저장해 둔 정보를 정확한 칸에 채워 넣게 합니다. 사용자의 입력 시간을 크게 줄이므로 로그인·주소 폼에서는 반드시 넣는 것이 좋습니다.

자주 쓰는 값 
<input type="email"    name="email"    autocomplete="email">
<input type="password" name="password" autocomplete="current-password">
<input type="password" name="new-pw"   autocomplete="new-password">
<input type="text"     name="name"     autocomplete="name">
<input type="tel"      name="phone"    autocomplete="tel">
<input type="text"     name="zip"      autocomplete="postal-code">

🛠️ 현장 노트 — 폼 체크리스트

  1. 모든 입력에 연결된 label이 있는가 (for ↔ id)
  2. 모든 입력에 name이 있는가
  3. type이 내용에 맞는가 (전화번호는 tel)
  4. 폼 안의 비제출 버튼에 type="button"을 붙였는가
  5. 오류 메시지가 어느 칸의 문제인지 알려 주는가
  6. 키보드 Tab만으로 처음부터 끝까지 작성·제출이 되는가
  7. 서버에서도 같은 검사를 다시 하는가

📌 요약

  • name이 없으면 그 값은 전송되지 않는다. id는 전송과 무관.
  • 비밀번호를 다루는 폼은 반드시 POST.
  • label은 for↔id로 연결한다. placeholder는 대체재가 아니다.
  • type을 제대로 고르면 모바일 키보드가 바뀐다. 전화번호는 tel.
  • 브라우저 유효성 검사는 편의 기능이지 보안이 아니다. 서버가 다시 검사해야 한다.
  • 오류 표시는 :invalid가 아니라 :user-invalid로.
  • 라디오는 name으로 묶고, fieldset+legend로 그룹 질문을 준다.
  • 폼 안의 <button>은 기본이 submit이다. 아니면 type="button".
