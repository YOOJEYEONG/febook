문제: 상태와 화면이 어긋난다

38장에서 배운 DOM 조작으로 장바구니를 만든다고 해 봅시다. 상품을 하나 추가하면 고쳐야 할 곳이 이만큼입니다.

function addItem(item) {
  cart.push(item);                                    // ① 데이터
  renderCartList();                                   // ② 목록 다시 그리기
  totalEl.textContent = calcTotal() + "원";           // ③ 합계
  badgeEl.textContent = cart.length;                  // ④ 뱃지 숫자
  emptyMessageEl.hidden = cart.length > 0;            // ⑤ 빈 상태 안내
  checkoutBtn.disabled = cart.length === 0;           // ⑥ 결제 버튼
  saveToStorage(cart);                                // ⑦ 저장
}

💥 무엇이 문제인가

  • 하나라도 빠뜨리면 화면이 데이터와 어긋납니다. 뱃지에는 3개인데 목록에는 2개.
  • 삭제·수정 함수에도 똑같은 목록을 다시 써야 합니다. 기능이 늘수록 곱하기로 늘어납니다.
  • 새 UI를 추가할 때 기존 함수를 전부 찾아 한 줄씩 넣어야 합니다.
  • 결국 "화면 어딘가가 안 바뀌는" 버그가 계속 나옵니다.

해법: 선언형

🧮 UI = f(state)

React의 핵심 아이디어는 한 줄로 요약됩니다.
"화면은 상태를 넣으면 나오는 함수의 결과다."
개발자는 "이 상태일 때 화면은 이렇게 생겼다"만 선언합니다. 어떻게 바꿀지는 React가 알아서 합니다.

function Cart({ items }) {
  const total = items.reduce((sum, i) => sum + i.price, 0);

  return (
    <div>
      <Badge count={items.length} />
      {items.length === 0
        ? <p>장바구니가 비어 있습니다</p>
        : <ItemList items={items} />}
      <p>합계: {total}원</p>
      <button disabled={items.length === 0}>결제하기</button>
    </div>
  );
}

// 상품을 추가하는 코드는 이것뿐입니다
setItems([...items, newItem]);
// 뱃지·빈 상태·합계·버튼이 전부 자동으로 맞춰집니다

🔑 핵심 차이

선언형에서는 "갱신을 빠뜨릴 곳" 자체가 없습니다. 화면 전체가 상태로부터 다시 만들어지기 때문입니다. React가 하는 일이 정확히 이것이고, "전체를 다시 그리는데 어떻게 느리지 않은가"를 푸는 것이 가상 DOM입니다.

가상 DOM의 진실

가상 DOM은 화면 구조를 가벼운 JavaScript 객체로 표현한 것입니다.

// 이런 JSX가
<div className="card"><h1>제목</h1></div>

// 이런 평범한 객체가 됩니다
{
  type: "div",
  props: {
    className: "card",
    children: { type: "h1", props: { children: "제목" } }
  }
}
동작 과정 
상태 변경
   ↓
① 컴포넌트 함수를 다시 실행해 '새 가상 DOM'을 만든다
   ↓
② 이전 가상 DOM과 비교한다 (재조정, reconciliation)
   ↓
③ 실제로 달라진 부분만 골라낸다
   ↓
④ 그 부분만 진짜 DOM에 반영한다

🚫 "가상 DOM이 실제 DOM보다 빠르다"는 틀린 말입니다

오해 — 가상 DOM은 DOM 조작보다 빠른 기술이다. 사실 — 가장 빠른 것은 항상 "필요한 것만 직접 고치는 것"입니다. 가상 DOM은 객체를 만들고 비교하는 작업이 추가되므로 순수한 속도로는 더 느립니다. React 팀도 이 점을 명확히 밝혀 왔습니다. 가상 DOM이 해결하는 것은 "전체를 다시 그리겠다고 선언해도 실제로는 전체를 다시 그리지 않게" 만드는 것입니다. 즉 선언형의 편리함을 감당 가능한 성능으로 제공하는 장치입니다. 비교하자면 이렇습니다.
손으로 최적화한 DOM 조작 ＞ 가상 DOM ≫ 매번 innerHTML로 전체 교체
React가 이기는 대상은 세 번째이고, 첫 번째에는 집니다. 대신 첫 번째는 사람이 유지할 수 없습니다.

⚖️ 그럼 왜 쓰나

속도를 조금 내주고 유지보수성을 크게 얻는 거래입니다. 그리고 실제 애플리케이션에서 그 "조금"은 대개 사람이 체감하지 못하는 수준입니다. 반면 명령형으로 짠 화면이 커졌을 때 생기는 버그와 개발 속도 저하는 명확히 체감됩니다.
참고로 가상 DOM을 쓰지 않는 선언형 도구도 있습니다(Svelte, Solid 등). 빌드 시점에 "무엇이 바뀔지"를 계산해 두는 방식입니다. 선언형과 가상 DOM은 같은 말이 아닙니다.

32장의 라이브러리·프레임워크 구분을 떠올려 보세요. React는 "내가 부르는" 쪽입니다. 그래서 자유롭지만 선택할 것이 많습니다. 이 선택 피로를 줄여 주는 것이 Next.js 같은 프레임워크이고 9부에서 다룹니다.

왜 널리 쓰이나

  • 컴포넌트 재사용 — 버튼을 한 번 만들어 전체에서 씁니다.
  • 거대한 생태계 — 어떤 문제든 해결책과 사례가 있습니다.
  • 채용 시장 — 한국의 프론트엔드 공고 대부분이 React를 요구합니다.
  • React Native — 같은 개념으로 모바일 앱까지.
  • 순수 JavaScript 실력이 그대로 쓰입니다 — 4·5부에서 배운 배열 메서드, 클로저, 구조 분해가 React 코드의 대부분입니다.

🛠️ 현장 노트 — 8부를 공부하는 방법

  1. 4·5부를 이해했다면 React는 어렵지 않습니다. React가 어려운 사람은 대개 JavaScript가 부족한 것입니다. 막히면 해당 챕터로 돌아가세요.
  2. 공식 문서가 매우 좋습니다. ko.react.dev는 한국어 번역도 훌륭합니다. 이 책과 함께 보세요.
  3. 클래스 컴포넌트 자료는 건너뛰세요. 2019년 이전 자료에는 this.state·componentDidMount가 나오는데, 지금은 쓰지 않습니다.
  4. 직접 만들어 보세요. 읽기만 해서는 절대 익혀지지 않습니다. 81장에 미니 프로젝트가 있습니다.

📌 요약

  • 명령형 DOM 조작은 상태와 화면이 어긋나는 버그를 구조적으로 만든다.
  • React의 핵심은 UI = f(state) — 상태를 선언하면 화면은 따라온다.
  • 가상 DOM은 실제 DOM보다 빠르지 않다. 선언형을 감당 가능한 성능으로 만들어 주는 장치다.
  • React가 이기는 대상은 매번 전체를 다시 그리는 방식이지, 손으로 최적화한 조작이 아니다.
  • 선언형 ≠ 가상 DOM. 가상 DOM 없이 선언형을 구현한 도구도 있다.
  • React는 라이브러리다. 라우팅·데이터 페칭·스타일은 직접 골라야 한다.
  • JavaScript 실력이 React 실력의 상한이다.
