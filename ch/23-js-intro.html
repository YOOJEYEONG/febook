이름과 역사

1995년, 넷스케이프의 브렌던 아이크가 웹 브라우저에 넣을 언어를 만들었습니다. 처음 이름은 Mocha, 다음은 LiveScript, 최종적으로 JavaScript가 되었습니다. 1장에서 말했듯 Java와는 아무 관계가 없고, 당시 인기 있던 Java의 이름값을 빌린 마케팅 결정이었습니다.

다른 브라우저들이 각자 비슷한 언어를 만들면서 호환성 문제가 생겼고, 1997년 ECMA International이라는 표준화 단체가 규격을 정리합니다. 그 규격의 이름이 ECMAScript(문서 번호 ECMA-262)입니다.

📘 JavaScript vs ECMAScript

ECMAScript는 규격(설계도), JavaScript는 그 규격을 구현한 언어입니다. "HTML 명세"와 "브라우저가 실제로 렌더링하는 HTML"의 관계와 비슷합니다. 일상 대화에서는 구분 없이 쓰지만, 버전 이야기를 할 때는 항상 ECMAScript 쪽입니다.

버전연도주요 변화
ES52009strict mode, 배열 메서드(map·filter), JSON
ES6 = ES20152015가장 큰 변화. let·const, 화살표 함수, 클래스, 템플릿 문자열, 구조 분해, Promise, 모듈
ES2016~매년이후로는 해마다 조금씩 추가됩니다. async/await(2017), 옵셔널 체이닝(2020) 등

"ES6 문법"이라는 말을 자주 듣는 이유는 2015년 변화가 워낙 컸기 때문입니다. 지금 배우는 문법은 대부분 ES2015 이후 것이고, 모든 현대 브라우저가 지원합니다.

Node.js — 브라우저 밖으로

2009년, V8 엔진을 브라우저에서 떼어내 일반 프로그램처럼 실행할 수 있게 만든 것이 Node.js입니다. 이때부터 JavaScript로 서버도, 명령줄 도구도 만들 수 있게 되었습니다.

🚧 언어는 같지만 쓸 수 있는 도구가 다릅니다

브라우저Node.js
있는 것window, document, alert, DOM, localStorage파일 시스템(fs), 프로세스, 네트워크 서버
없는 것파일 읽기·쓰기 (보안상 차단)document, window, 화면

문법(if, for, 함수, 배열)은 완전히 같습니다. 차이는 환경이 제공하는 기능입니다. Node.js에서 document를 쓰면 "document is not defined" 오류가 납니다. 46장에서 다시 다룹니다.

코드를 넣는 방법

세 가지 방법 
<!-- ① 외부 파일 (권장) -->
<script src="main.js" defer></script>

<!-- ② 문서 안에 직접 -->
<script>
  console.log("안녕");
</script>

<!-- ③ 모듈로 (34장) — 기본으로 defer 처럼 동작 -->
<script type="module" src="main.js"></script>

5장에서 배운 defer를 기억하세요. defer 없이 <head>에 스크립트를 두면 아직 만들어지지 않은 요소를 찾게 되어 null 오류가 납니다.

⚠️ src가 있으면 안쪽 내용은 무시됩니다

<script src="main.js">
  console.log("이 줄은 실행되지 않습니다");
</script>

둘을 함께 쓰려면 <script> 태그를 따로 만들어야 합니다.

콘솔 — 여러분의 실험실

개발자 도구(F12 / ⌘⌥I)의 Console 탭에서는 코드를 한 줄씩 바로 실행할 수 있습니다. 문법이 헷갈릴 때 파일을 만들 필요 없이 즉시 확인할 수 있어서, 학습 속도가 크게 달라집니다.

메서드용도
console.log()일반 출력. 가장 많이 씁니다
console.error()빨간 오류 표시
console.warn()노란 경고 표시
console.table()배열·객체를 표로 보여줍니다. 데이터 확인에 매우 유용
console.dir()DOM 요소를 객체 구조로 봅니다
console.time() / timeEnd()걸린 시간 측정

🏷️ 출력에 이름표를 붙이세요

console.log(user);              // 값만 나와서 뭐가 뭔지 모름
console.log("user:", user);     // 조금 낫고
console.log({ user, count });   // ✅ 이름과 값이 함께 나옴 (28장 단축 문법)

기본 문법 규칙

세미콜론은 필수인가

JavaScript에는 자동 세미콜론 삽입(ASI)이라는 규칙이 있어서, 대부분의 경우 생략해도 동작합니다. 하지만 몇 가지 상황에서 예상과 다르게 해석됩니다.

const a = 1
const b = 2
const result = a + b
;[1, 2, 3].forEach(n => console.log(n))
//  ↑ 줄이 대괄호나 괄호로 시작하면 앞 줄과 이어져 해석될 수 있어
//    앞에 세미콜론을 붙이는 방어 코드가 필요합니다

실무에서는 논쟁하지 않습니다. Prettier 같은 포매터(48장)가 팀 규칙대로 자동 정리해 줍니다. 어느 쪽이든 일관되게만 쓰면 됩니다. 이 책은 세미콜론을 붙이는 쪽으로 씁니다.

엄격 모드

"use strict";   // 파일이나 함수의 맨 앞에

x = 10;   // 엄격 모드에서는 오류. 선언 없이 변수를 만들 수 없습니다

초기 JavaScript의 관대한(그래서 위험한) 동작을 막는 모드입니다. <script type="module">과 ES 모듈, 그리고 class 내부는 자동으로 엄격 모드이므로 현대적인 코드에서는 따로 선언할 일이 거의 없습니다.

이름 짓기 규칙

  • 문자·숫자·_·$를 쓸 수 있지만 숫자로 시작할 수 없습니다.
  • 대소문자를 구분합니다. userName과 username은 다릅니다.
  • if, for, class 같은 예약어는 쓸 수 없습니다.
  • 관례: 변수·함수는 카멜케이스(userName), 클래스는 파스칼케이스(UserProfile), 상수는 대문자(MAX_COUNT).
  • 한글 변수명도 문법상 가능하지만 쓰지 않습니다. 협업·도구 호환 문제가 생깁니다.

🛠️ 현장 노트 — 좋은 이름이 주석보다 낫습니다

// 나쁨: 이름이 아무것도 말해 주지 않아 주석이 필요합니다
const d = 30;  // 배송까지 걸리는 일수

// 좋음: 이름 자체가 설명입니다
const deliveryDays = 30;

// 불리언(참·거짓)은 is·has·can 으로 시작하면 읽기 쉽습니다
const isLoggedIn = true;
const hasPermission = false;

오류를 읽는 법

초보자는 빨간 글씨를 보면 당황해서 그냥 다시 실행합니다. 오류 메시지는 문제 해결의 가장 중요한 단서입니다. 반드시 읽으세요.

메시지뜻
x is not defined그런 이름의 변수가 없습니다. 오타이거나 선언 전에 썼습니다
Cannot read properties of null (reading 'x')가장 흔한 오류. 요소를 못 찾아 null인데 그 안의 값을 꺼내려 했습니다
x is not a function함수가 아닌 것을 함수처럼 호출했습니다. 오타이거나 타입이 다릅니다
Unexpected token문법 오류. 괄호·따옴표 짝이 안 맞는 경우가 대부분입니다

콘솔의 오류 메시지 오른쪽에는 파일명과 줄 번호가 있습니다. 클릭하면 그 줄로 이동합니다. 오류가 난 줄과 그 위 몇 줄을 함께 보는 것이 요령입니다.

📌 요약

  • ECMAScript는 규격, JavaScript는 그 구현이다. "ES6"는 2015년판을 가리킨다.
  • 엔진은 V8(Chrome·Node) · JavaScriptCore(Safari) · SpiderMonkey(Firefox).
  • 브라우저와 Node.js는 언어는 같고 제공하는 기능이 다르다.
  • <script>에 src가 있으면 태그 안 내용은 무시된다.
  • 세미콜론은 대개 생략 가능하지만 포매터에 맡기고 일관되게 쓴다.
  • 모듈과 class 내부는 자동으로 엄격 모드다.
  • 오류 메시지를 반드시 읽는다. 파일·줄 번호가 함께 나온다.
