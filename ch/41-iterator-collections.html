이터러블 — for...of가 도는 것들

for...of는 아무 값에나 쓸 수 없습니다. 이터러블(iterable)이어야 합니다. 어떤 객체가 Symbol.iterator라는 이름의 메서드를 가지고 있으면 이터러블입니다.

이터러블인 것이터러블이 아닌 것
배열, 문자열, Map, Set, NodeList, arguments, FormData, 제너레이터일반 객체 {}

제너레이터

이터러블을 직접 만드는 건 번거롭습니다. 제너레이터는 같은 일을 훨씬 간단하게 해 줍니다. function*로 선언하고 yield로 값을 하나씩 내보냅니다.

💤 게으른 계산(lazy evaluation)

제너레이터의 핵심 가치는 필요할 때까지 계산하지 않는 것입니다. 1억 개의 데이터를 처리해야 할 때, 배열로 다 만들면 메모리가 감당하지 못합니다. 제너레이터는 한 번에 하나씩만 만들어 냅니다.
실무에서 직접 쓸 일은 많지 않지만, 비동기 처리의 내부 구현(async/await도 제너레이터와 유사한 일시 중단 개념 위에 있습니다)과 일부 라이브러리를 이해하는 데 필요합니다.

🤔 언제 Map, 언제 객체?

  • 구조가 정해진 데이터(사용자 정보처럼 name·age가 고정) → 객체
  • 키가 동적으로 늘고 줄어드는 사전 → Map
  • 키가 문자열이 아님(객체, DOM 요소) → Map
  • JSON으로 주고받아야 함 → 객체
  • 순서가 중요함 → Map

WeakMap과 WeakSet

일반 Map은 키로 쓴 객체를 붙잡고 있습니다. 그래서 다른 곳에서 그 객체를 다 버려도 Map 때문에 메모리에서 해제되지 않습니다.

const cache = new WeakMap();

function process(element) {
  if (cache.has(element)) return cache.get(element);
  const result = expensiveWork(element);
  cache.set(element, result);
  return result;
}
// element가 DOM에서 제거되고 다른 참조도 없어지면
// WeakMap의 항목도 자동으로 사라집니다 → 메모리 누수 없음
제약내용
키는 객체만문자열·숫자 불가
순회 불가keys(), size, for...of 없음 — 언제 사라질지 모르기 때문
용도객체에 부가 정보를 붙이되 수명은 그 객체를 따르게 할 때

🛠️ 현장 노트 — 실무 빈도

솔직하게 정리하면 이렇습니다.

  • Set — 자주 씁니다. 중복 제거와 존재 확인은 거의 매일 필요합니다.
  • Map — 가끔 씁니다. 키가 객체이거나 동적인 사전일 때.
  • 제너레이터 — 직접 쓸 일은 드뭅니다. 다만 라이브러리 코드를 읽으려면 알아야 합니다.
  • WeakMap — 거의 안 씁니다. 라이브러리 내부 구현에서 주로 쓰입니다.

📌 요약

  • for...of와 전개 구문은 이터러블에만 동작한다. 일반 객체는 이터러블이 아니다.
  • Symbol.iterator를 구현하면 내가 만든 객체도 이터러블이 된다.
  • 제너레이터(function* + yield)는 이터러블을 쉽게 만들고 게으른 계산을 가능하게 한다.
  • Map은 어떤 타입이든 키로 쓸 수 있고 순서를 보장하며 size가 있다.
  • JSON으로 주고받을 데이터는 객체가 맞다.
  • Set은 중복 제거와 빠른 존재 확인. [...new Set(arr)]는 외워 둘 관용구.
  • 객체는 내용이 같아도 다른 값이므로 Set으로 중복 제거되지 않는다.
  • WeakMap은 키 객체가 사라지면 항목도 사라진다. 순회할 수 없다.
