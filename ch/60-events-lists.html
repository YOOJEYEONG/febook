이벤트 처리

function Button() {
  function handleClick(event) {
    console.log("클릭됨");
  }

  return (
    <>
      <button onClick={handleClick}>방법 1</button>
      <button onClick={() => console.log("클릭")}>방법 2 (인라인)</button>
      <button onClick={() => handleDelete(id)}>방법 3 (인자 전달)</button>
    </>
  );
}

💥 괄호를 붙이면 즉시 실행됩니다

<button onClick={handleClick()}>      // ❌ 렌더링될 때 바로 실행됩니다
<button onClick={handleClick}>        // ✅ 함수 자체를 넘깁니다
<button onClick={() => handleClick(id)}>  // ✅ 인자가 필요하면 감쌉니다

27장에서 배운 "괄호를 붙이면 지금 실행, 안 붙이면 함수 자체"가 그대로 적용됩니다. 실수하면 렌더링될 때마다 실행되어 무한 루프가 나기도 합니다.

합성 이벤트

React의 event는 브라우저의 것을 감싼 합성 이벤트입니다. 브라우저마다 다른 동작을 통일해 주므로, 사용법은 38장에서 배운 것과 거의 같습니다.

function Form() {
  return (
    <form onSubmit={(e) => {
      e.preventDefault();          // ✅ 기본 동작 막기 — 새로고침 방지
      submitData();
    }}>
      <input onChange={(e) => setValue(e.target.value)} />
      <button type="submit">전송</button>
    </form>
  );
}

// 진짜 브라우저 이벤트가 필요하면
onClick={(e) => console.log(e.nativeEvent)}

🫧 React 이벤트도 버블링됩니다

38장의 전파 개념이 그대로 적용됩니다. 부모의 onClick이 자식 클릭에도 반응하므로, 필요하면 e.stopPropagation()을 씁니다(다만 남용은 금물).
그리고 React는 이벤트를 내부적으로 위임 방식으로 처리합니다. 그래서 목록 항목마다 onClick을 붙여도 실제 DOM 리스너가 항목 수만큼 생기지는 않습니다. 38장에서 손으로 하던 위임을 React가 대신 해 주는 셈입니다.

조건부 렌더링

네 가지 패턴 
// ① 삼항 연산자 — A 또는 B
{isLoggedIn ? <Dashboard /> : <LoginForm />}

// ② && — 있거나 없거나
{hasError && <ErrorMessage />}

// ③ 이른 반환 — 컴포넌트 전체를 대체 (26장)
function Profile({ user }) {
  if (!user) return <Loading />;
  return <div>{user.name}</div>;
}

// ④ 변수로 빼기 — 조건이 복잡할 때
function Status({ state }) {
  let content;
  if (state.status === "loading") content = <Spinner />;
  else if (state.status === "error") content = <Error msg={state.error} />;
  else content = <List items={state.data} />;

  return <div className="panel">{content}</div>;
}

0️⃣ &&의 유명한 함정

{items.length && <List items={items} />}
// items가 비어 있으면 → 0 && ... → 0
// React는 숫자 0을 '렌더링합니다'. 화면에 0이 튀어나옵니다.
해결 — 명시적으로 불리언을 만듭니다. 
{items.length > 0 && <List items={items} />}      ✅
{Boolean(items.length) && <List />}                ✅
{items.length ? <List /> : null}                    ✅
참고: false·null·undefined는 아무것도 렌더링하지 않지만 0과 NaN은 렌더링됩니다. 빈 문자열은 렌더링되지만 보이지 않습니다.

리스트 렌더링

function UserList({ users }) {
  return (
    <ul>
      {users.map(user => (
        <li key={user.id}>{user.name}</li>
      ))}
    </ul>
  );
}

29장에서 배운 map이 그대로 쓰입니다. 배열을 반환하면 React가 순서대로 렌더링합니다.

필터링·정렬과 함께 
function TodoList({ todos, filter }) {
  const visible = todos
    .filter(t => filter === "all" || (filter === "done") === t.done)
    .toSorted((a, b) => a.createdAt - b.createdAt);

  if (visible.length === 0) return <p>표시할 항목이 없습니다</p>;

  return (
    <ul>
      {visible.map(todo => (
        <TodoItem key={todo.id} todo={todo} />
      ))}
    </ul>
  );
}

key — 반드시 이해해야 할 것

key는 React가 "이전 목록의 어느 항목이 지금의 어느 항목인지"를 알아보는 신원 표시입니다.

🎫 왜 필요한가

목록의 두 번째 항목을 지웠다고 합시다. key가 없으면 React는 순서로만 비교합니다. "2번 자리의 내용이 바뀌었고, 3번 자리도 바뀌었고, 4번 자리는 사라졌다"고 판단해 여러 요소를 불필요하게 수정합니다.
key가 있으면 "id=2가 사라졌다" 하나만 처리합니다. 성능뿐 아니라 DOM 요소의 상태 유지에도 결정적입니다.

key로 쓸 것쓰면 안 되는 것
데이터의 고유 id (가장 좋음)
없다면 생성 시점에 만든 id(crypto.randomUUID())
정말 정적인 목록이라면 인덱스도 가능 		배열 인덱스 — 순서가 바뀌거나 추가·삭제되는 목록에서
Math.random() — 매 렌더링마다 달라져 항상 새로 만들어집니다
목록 안에서 중복되는 값

📋 인덱스를 써도 되는 경우

  • 목록이 절대 바뀌지 않는다 (정적 메뉴 등)
  • 항목의 추가·삭제·순서 변경이 없다
  • 항목에 자체 상태가 없다 (입력창·체크박스 등이 없음)

세 조건을 모두 만족할 때만 안전합니다. 확신이 없으면 id를 쓰세요. 데이터에 id가 없다면 목록을 만드는 시점에 id를 붙이는 것이 옳은 해결책입니다.

📍 key는 형제 사이에서만 고유하면 됩니다

전역에서 고유할 필요는 없습니다. 그리고 key는 props가 아닙니다. 컴포넌트 안에서 props.key로 읽을 수 없습니다. 값이 필요하면 <Item key={id} id={id} />처럼 따로 넘겨야 합니다.

프래그먼트에 key 주기

// 축약 문법 <>에는 key를 줄 수 없습니다
{items.map(item => (
  <React.Fragment key={item.id}>
    <dt>{item.term}</dt>
    <dd>{item.desc}</dd>
  </React.Fragment>
))}

🛠️ 현장 노트

  1. "key 경고"를 무시하지 마세요. 콘솔의 노란 경고는 실제 버그의 예고입니다.
  2. 목록 렌더링 로직은 컴포넌트로 분리하세요. map 안에 20줄이 들어가면 읽기 어렵습니다.
  3. 빈 목록 처리를 잊지 마세요. 항목이 0개일 때 화면이 텅 비면 사용자는 오류로 오해합니다.
  4. 목록이 수천 개면 가상 스크롤(react-window 등)을 고려합니다. 화면에 보이는 것만 렌더링합니다.

📌 요약

  • 이벤트 핸들러는 함수 자체를 넘긴다. 인자가 필요하면 화살표 함수로 감싼다.
  • React 이벤트도 버블링되며, 내부적으로 위임 방식으로 처리된다.
  • 조건부 렌더링: 삼항 · && · 이른 반환 · 변수.
  • && 앞에 숫자를 두지 마라. 0이 화면에 그대로 나온다.
  • key는 React가 항목의 신원을 알아보는 표시다.
  • 인덱스를 key로 쓰면 순서가 바뀔 때 상태가 엉뚱한 항목에 남는다.
  • Math.random()을 key로 쓰면 매번 전부 새로 만들어진다.
  • key는 props가 아니다. 값이 필요하면 따로 넘긴다.
