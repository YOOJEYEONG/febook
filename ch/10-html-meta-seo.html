표 — 데이터를 위한 것

제대로 만든 표 
<table>
  <caption>2026년 1분기 지점별 매출</caption>
  <thead>
    <tr>
      <th scope="col">지점</th>
      <th scope="col">1월</th>
      <th scope="col">2월</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">강남</th>
      <td>120</td>
      <td>135</td>
    </tr>
  </tbody>
  <tfoot>
    <tr><th scope="row">합계</th><td>120</td><td>135</td></tr>
  </tfoot>
</table>
요소·속성역할
<caption>표의 제목. <table>의 첫 자식이어야 합니다
<th>머리 칸. <td>는 데이터 칸
scope="col"이 머리 칸은 세로 열 전체의 제목
scope="row"이 머리 칸은 가로 행 전체의 제목
colspan / rowspan칸 합치기

🔊 scope가 왜 중요한가

눈으로 보는 사람은 표를 2차원으로 봅니다. 값 135를 보면 위로 올려다봐 "2월", 왼쪽을 봐 "강남"임을 즉시 압니다. 스크린 리더는 표를 한 칸씩 순서대로 읽습니다. scope가 있으면 "강남, 2월, 135"라고 맥락과 함께 읽어 줍니다. 없으면 그냥 "135"입니다. 표가 커질수록 이 차이는 결정적입니다.

🚫 표로 화면을 배치하지 마세요

CSS가 빈약하던 시절에는 <table>로 페이지 레이아웃을 짰습니다. 지금은 절대 하면 안 됩니다. 스크린 리더가 "표, 3열 5행"이라고 안내하는데 실제로는 데이터가 아니라 그냥 배치용이면 사용자는 혼란에 빠집니다. 배치는 Flexbox와 Grid(15·16장)의 일입니다. 표는 행과 열의 관계가 실제로 의미 있는 데이터에만 씁니다.

head 안의 메타데이터

실무에서 쓰는 head 전체 
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">

  <title>프론트엔드 입문 가이드 | 프엔북</title>
  <meta name="description" content="비전공자를 위한 프론트엔드 학습 안내. 30분 만에 첫 페이지를 만듭니다.">

  <link rel="canonical" href="https://example.com/guide">
  <link rel="icon" href="/favicon.ico">
  <link rel="stylesheet" href="/style.css">

  <!-- 공유 미리보기 -->
  <meta property="og:type" content="article">
  <meta property="og:title" content="프론트엔드 입문 가이드">
  <meta property="og:description" content="비전공자를 위한 프론트엔드 학습 안내.">
  <meta property="og:image" content="https://example.com/preview.png">
  <meta property="og:url" content="https://example.com/guide">
  <meta name="twitter:card" content="summary_large_image">
</head>

title과 description

  • <title> — 검색 결과의 파란 제목 줄이자 브라우저 탭 이름. 페이지마다 달라야 합니다. 중요한 단어를 앞에 두고, 페이지 이름 | 사이트 이름 형식이 무난합니다.
  • description — 검색 결과의 회색 설명 줄. 검색 순위에 직접 영향을 주지는 않지만, 클릭할지 말지를 결정하게 만듭니다. 너무 길면 검색엔진이 잘라 버리거나 본문에서 다른 문장을 뽑아 씁니다.

🚫 meta keywords는 죽은 태그입니다

오해 — <meta name="keywords">에 검색어를 잔뜩 넣으면 순위가 오른다. 사실 — 남용이 심해서 구글은 오래전에 이 태그를 순위에 반영하지 않는다고 공식 발표했습니다. 지금 넣어도 아무 효과가 없습니다. 옛 자료를 보고 시간을 낭비하지 마세요.

Open Graph — 링크 미리보기의 정체

카카오톡·슬랙·페이스북에 링크를 붙이면 제목·설명·이미지가 담긴 카드가 뜹니다. 그 카드는 페이지의 og: 메타 태그를 읽어서 만들어집니다.

태그내용
og:title카드 제목
og:description카드 설명
og:image카드 이미지. 반드시 절대 주소(https://…)여야 합니다
og:url이 페이지의 대표 주소
og:typewebsite, article 등

🛠️ 현장 노트 — 미리보기가 안 바뀔 때

OG 태그를 고쳤는데 미리보기가 그대로인 경우가 많습니다. 각 플랫폼이 이전 결과를 캐시하고 있기 때문입니다. 플랫폼마다 캐시를 갱신하는 디버거 도구를 제공하니 그것으로 새로 읽게 해야 합니다. 그리고 og:image에 상대 경로를 쓰면 대부분 실패합니다. 크롤러는 다른 서버에서 요청하므로 상대 경로를 해석할 수 없습니다.

canonical — 중복 페이지 정리

같은 내용이 여러 주소로 열릴 수 있습니다.

https://example.com/product
https://example.com/product?ref=kakao
https://example.com/product?utm_source=ad
https://www.example.com/product

검색엔진은 이것을 서로 다른 페이지로 볼 수 있고, 그러면 평가가 분산됩니다. <link rel="canonical" href="…">로 "이게 대표 주소"라고 알려 주면 하나로 합쳐 줍니다.

robots — 색인 통제

<meta name="robots" content="noindex, nofollow">
  • noindex — 검색 결과에 넣지 마세요. 관리자 페이지, 임시 페이지, 검색 결과 페이지에 씁니다.
  • nofollow — 이 페이지의 링크를 따라가지 마세요.

⚠️ noindex는 보안이 아닙니다

"검색에 안 나오게 했으니 안전하다"는 착각을 하면 안 됩니다. 주소를 아는 사람은 누구나 접근할 수 있습니다. 예의 바른 크롤러만 이 지시를 따릅니다. 진짜로 막으려면 서버에서 인증을 검사해야 합니다.

구조화 데이터 (JSON-LD)

검색엔진에 "이 페이지는 요리 레시피이고, 조리 시간은 30분, 별점은 4.5"처럼 기계가 이해할 수 있는 형태로 알려 주는 방식입니다. 잘 넣으면 검색 결과에 별점·가격·조리 시간 같은 풍부한 결과(rich result)가 표시될 수 있습니다.

JSON-LD 예시 
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "프론트엔드 입문 가이드",
  "datePublished": "2026-01-15",
  "author": { "@type": "Person", "name": "홍길동" }
}
</script>

type="application/ld+json"이라 브라우저는 실행하지 않고 무시합니다. 크롤러만 읽습니다. 어떤 종류가 있는지는 schema.org에 정리되어 있습니다.

프론트엔드 개발자의 SEO 책임 범위

SEO는 마케팅 영역까지 걸쳐 있어 범위가 넓습니다. 개발자가 실제로 통제하는 부분은 이렇습니다.

emantic">시맨틱 구조본문이 main 안에 있는가
고유한 title·description페이지마다 다르게

모바일 대응구글은 모바일 화면 기준으로 색인합니다
렌더링 방식JavaScript로만 그리는 페이지는 크롤러가 내용을 놓칠 수 있습니다 → 9부 SSR

💡 접근성과 SEO는 대부분 같은 일이다

검색 크롤러는 눈이 없는 방문자입니다. 스크린 리더 사용자를 위해 하는 일 — 시맨틱 태그, 제목 계층, alt, 명확한 링크 텍스트 — 이 그대로 검색엔진에도 좋은 신호가 됩니다. 접근성을 챙기면 SEO의 상당 부분이 저절로 해결됩니다.

📌 요약

  • 표는 데이터에만 쓴다. 배치에는 Flexbox·Grid.
  • caption·th·scope가 있어야 스크린 리더가 표를 맥락과 함께 읽는다.
  • title·description은 페이지마다 고유하게.
  • meta keywords는 효과가 없다.
  • 링크 미리보기는 Open Graph 태그로 만들어진다. og:image는 절대 주소.
  • canonical로 중복 주소의 대표를 지정한다.
  • noindex는 보안이 아니다.
  • 접근성을 챙기면 SEO의 상당 부분이 따라온다.
