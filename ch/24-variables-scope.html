✅ 실무 원칙 한 줄

기본은 const. 값을 바꿔야 할 때만 let. var는 쓰지 않습니다.
const를 기본으로 쓰면 "이 값은 안 바뀐다"가 코드에 드러나 읽기 쉬워지고, 실수로 덮어쓰는 버그를 실행 전에 잡을 수 있습니다.

스코프

스코프(scope)는 변수가 보이는 범위입니다. "이 변수를 여기서 쓸 수 있는가"를 결정합니다.

블록 스코프 vs 함수 스코프 
function test() {
  if (true) {
    var varValue = "var";     // 함수 전체에서 살아 있음
    let letValue = "let";     // { } 블록 안에서만
  }
  console.log(varValue);      // "var"  — 블록 밖인데도 보인다
  console.log(letValue);      // ReferenceError
}

블록이란 { }로 감싼 영역입니다. if, for, while의 중괄호도 전부 블록입니다. var는 이 중괄호를 무시하고 함수 전체를 범위로 삼습니다. 직관에 어긋나고 버그의 원인이 됩니다.

가장 유명한 var 사고

스코프 체인

변수를 찾을 때 JavaScript는 안쪽에서 바깥쪽으로 차례로 찾습니다. 찾으면 멈추고, 끝까지 없으면 오류입니다.

const outer = "바깥";

function level1() {
  const middle = "중간";

  function level2() {
    const inner = "안쪽";
    console.log(inner);   // 자기 스코프에서 찾음
    console.log(middle);  // 없으니 한 단계 밖에서 찾음
    console.log(outer);   // 없으니 또 밖에서 찾음 → 전역
  }
  level2();
}
// 반대 방향은 불가능합니다. 바깥에서 안쪽 변수는 보이지 않습니다.

섀도잉

const name = "바깥";
function test() {
  const name = "안쪽";   // 바깥 name을 가린다 (덮어쓰는 게 아님)
  console.log(name);     // "안쪽"
}
test();
console.log(name);       // "바깥" — 그대로

안쪽에서 같은 이름을 선언하면 바깥 것을 가립니다. 이를 섀도잉(shadowing)이라고 합니다. 문법적으로 정상이지만, 읽는 사람을 혼란스럽게 하므로 일부러 하지는 마세요.

호이스팅 — 정확한 의미

🚫 가장 널리 퍼진 오해

오해 — 호이스팅은 선언문이 코드 맨 위로 이동하는 것이다. 사실 — 코드는 움직이지 않습니다. JavaScript 엔진은 코드를 실행하기 전에 스코프를 미리 훑어 어떤 변수와 함수가 있는지 메모리에 등록해 둡니다. 그래서 결과적으로 위에서 참조할 수 있는 것처럼 보이는 것입니다. "올라간다"는 설명은 결과를 묘사한 비유이지 실제 동작이 아닙니다.
대상등록 시점선언 전 접근하면
var등록 + undefined로 초기화undefined (오류 아님)
let / const등록만. 초기화는 안 됨ReferenceError ← TDZ
function 선언문등록 + 함수 전체가 준비됨정상 호출 가능
class등록만ReferenceError ← TDZ

TDZ — 일시적 사각지대

TDZ(Temporal Dead Zone)는 스코프가 시작된 시점부터 선언문에 도달할 때까지의 구간입니다. 이 구간에서 그 변수에 접근하면 오류가 납니다.

💡 TDZ는 왜 만들어졌나

var의 undefined 동작은 버그를 조용히 숨깁니다. 오타로 잘못된 변수를 참조해도 오류 없이 undefined로 진행되어, 문제가 한참 뒤 엉뚱한 곳에서 터집니다. TDZ는 "선언 전에 쓰는 것은 명백한 실수다"라고 판단해 그 자리에서 멈춥니다. 불편해 보이지만 안전장치입니다.

const의 진짜 의미

🔒 "const인데 왜 값이 바뀌죠?"

const user = { name: "홍길동" };
user.name = "김철수";        // ✅ 됩니다
user.age = 20;               // ✅ 됩니다
console.log(user);           // { name: "김철수", age: 20 }

user = { name: "다른 객체" }; // ❌ TypeError: Assignment to constant variable

const list = [1, 2, 3];
list.push(4);                // ✅ 됩니다
list = [];                   // ❌ 오류

const가 고정하는 것은 "이름이 가리키는 대상"이지 "그 대상의 내용"이 아닙니다.
집 주소를 적은 쪽지를 상상하세요. const는 쪽지에 적힌 주소를 못 바꾸게 합니다. 하지만 그 집에 들어가서 가구를 옮기는 것은 막지 않습니다.
내용까지 얼리려면 Object.freeze()가 필요합니다. (단 한 겹만 얼립니다.)

전역 변수

어떤 함수나 블록에도 속하지 않은 변수가 전역 변수입니다. 어디서나 접근할 수 있어 편해 보이지만,

  • 어디서 누가 바꿨는지 추적할 수 없습니다.
  • 다른 스크립트·라이브러리와 이름이 충돌합니다.
  • 테스트가 어려워집니다.
// 일반 script 안에서 var로 선언하면 window의 속성이 됩니다
var globalVar = "위험";
console.log(window.globalVar);  // "위험"

// let / const 는 그렇지 않습니다
let globalLet = "안전";
console.log(window.globalLet);  // undefined

💀 선언 없는 대입은 절대 하지 마세요

function bad() {
  count = 10;   // var·let·const 없이 대입
}
bad();
console.log(count);  // 10 — 함수 안에서 만들었는데 전역이 되어 버렸다!

느슨한 모드에서는 선언 없이 대입하면 전역 변수가 만들어집니다. 오타 하나로 전역 오염이 일어납니다. 엄격 모드(모듈 포함)에서는 오류가 나므로, 이것이 엄격 모드를 쓰는 대표적인 이유입니다.

🛠️ 현장 노트 — 변수 선언 체크리스트

  1. const로 시작합니다. 나중에 재할당이 필요해지면 그때 let으로 바꿉니다.
  2. 선언은 쓰는 곳 가까이에 둡니다. 맨 위에 몰아 두면 읽을 때 되짚어야 합니다.
  3. 이름이 길어지는 것을 두려워하지 마세요. d보다 deliveryDays가 항상 낫습니다.
  4. ESLint(48장)가 no-var, prefer-const, no-undef 규칙으로 이 모든 것을 자동으로 잡아 줍니다.

📌 요약

  • 기본은 const, 필요할 때만 let, var는 쓰지 않는다.
  • var는 함수 스코프, let·const는 블록 스코프.
  • 변수는 안쪽에서 바깥쪽으로 찾는다(스코프 체인). 반대는 불가능.
  • 호이스팅은 코드가 이동하는 것이 아니라 실행 전에 변수·함수를 미리 등록하는 과정이다.
  • var는 undefined로 초기화되지만, let·const·class는 TDZ에 들어가 접근 시 오류.
  • const는 재할당을 막을 뿐 객체 내부 변경은 막지 않는다.
  • 선언 없는 대입은 전역을 오염시킨다. 엄격 모드에서는 오류.
