앞의 7개를 원시 타입(primitive), 마지막을 객체 타입(reference)이라고 부릅니다. 이 구분이 이 챕터의 핵심입니다.

null과 undefined

let a;                       // 선언만 → undefined
console.log(a);              // undefined

const user = { name: "홍길동" };
console.log(user.age);       // undefined — 없는 속성

function f() {}
console.log(f());            // undefined — 반환값이 없는 함수

let b = null;                // "지금은 값이 없다"고 개발자가 명시

실무 관례: "값이 없음"을 표현할 때는 null을 쓰고, undefined는 시스템이 알아서 만들게 둡니다. 직접 대입하지 않습니다.

typeof의 함정

🐛 typeof null === "object"는 고칠 수 없는 버그

class="term" data-term="javascript">JavaScript 최초 구현에서 값의 타입을 하위 비트로 표시했는데, 객체는 000으로 시작했고 null은 전부 0인 포인터였습니다. 그래서 null이 객체로 판정됩니다. 고치자는 제안이 있었지만 기존 웹의 수많은 코드가 깨지기 때문에 거부되었습니다. 지금은 언어의 영구적인 특징입니다. null 검사는 value === null로 하세요.

값 복사 vs 참조 복사 — 가장 중요한 개념

📄 종이와 주소 쪽지

원시 값은 종이에 적은 내용입니다. 복사하면 내용이 복사되어 두 장이 서로 무관해집니다.
객체는 집 주소를 적은 쪽지입니다. 복사하면 주소만 복사됩니다. 쪽지는 두 장이지만 가리키는 집은 하나입니다. 한쪽에서 가구를 옮기면 다른 쪽에서도 바뀐 것이 보입니다.

복사 방법깊이비고
{ ...obj }, Object.assign({}, obj)한 겹가장 많이 씁니다. 대부분 이걸로 충분합니다
[...arr], arr.slice()한 겹배열용
structuredClone(obj)전부표준 내장 함수. 순환 참조, Date, Map, Set도 처리합니다. 함수는 복사 못 합니다
JSON.parse(JSON.stringify(obj))전부옛 방식. undefined·함수·Date가 손상됩니다. 지금은 쓸 이유가 없습니다

structuredClone은 Chrome 98+, Safari 15.4+, Firefox 94+, Node 17+에서 지원됩니다.

🛠️ 현장 노트 — React 초보자가 겪는 대표 버그

// ❌ 화면이 안 바뀝니다
const newList = list;
newList.push(item);
setList(newList);
// 같은 객체를 가리키므로 React가 "안 바뀌었다"고 판단합니다(59장)

// ✅ 새 배열을 만듭니다
setList([...list, item]);

이 문제의 뿌리가 바로 참조 복사입니다. 8부에서 React를 배울 때 이 챕터를 떠올리게 됩니다.

==와 ===

⚖️ 규칙: 항상 ===

==는 타입을 자동으로 맞춘 뒤 비교하는데, 그 규칙이 복잡하고 일관되지 않습니다. 위 예제의 결과를 예측할 수 있는 사람은 드뭅니다.
단 하나의 예외는 value == null입니다. 이것은 null이거나 undefined일 때 참이 되므로 "값이 비었는지" 한 번에 확인하는 관용구로 널리 쓰입니다. (이 관용구를 쓰지 않겠다면 value === null || value === undefined로 명시하세요.)

?? 와 ||

// || 는 falsy 값 전부에 반응합니다
const count1 = 0 || 10;          // 10  ← 0은 유효한 값인데 무시됨!
const name1 = "" || "익명";      // "익명" ← 빈 문자열도 무시됨

// ?? 는 null·undefined 에만 반응합니다
const count2 = 0 ?? 10;          // 0   ✅ 0을 그대로 씁니다
const name2 = "" ?? "익명";      // ""  ✅
const value = undefined ?? "기본값";  // "기본값"

"값이 없을 때만 기본값"이 필요하다면 ??(널 병합 연산자)를 쓰세요. 숫자 0과 빈 문자열이 유효한 값인 상황에서 ||를 쓰면 조용한 버그가 생깁니다.

문자열은 바꿀 수 없습니다

let str = "hello";
str[0] = "H";          // 아무 일도 일어나지 않습니다 (오류도 안 남)
console.log(str);      // "hello"

str = "H" + str.slice(1);   // 새 문자열을 만들어 다시 대입해야 합니다
console.log(str);      // "Hello"

모든 문자열 메서드(toUpperCase, replace, trim 등)는 원본을 바꾸지 않고 새 문자열을 반환합니다. 반환값을 받지 않으면 아무 일도 일어나지 않습니다.

📌 요약

  • 원시 타입 7가지(string·number·boolean·undefined·null·symbol·bigint) + 객체.
  • typeof null === "object"는 고칠 수 없는 역사적 버그. 배열은 Array.isArray()로 판별.
  • 0.1 + 0.2 !== 0.3은 2진 부동소수점의 한계다. 돈은 정수로 계산한다.
  • NaN !== NaN. 판별은 Number.isNaN().
  • 원시 값은 내용이, 객체는 주소가 복사된다. 이 차이가 초보자 버그의 최대 원인.
  • 얕은 복사는 한 겹만. 전부 복사하려면 structuredClone().
  • 항상 ===. 예외는 == null 관용구뿐.
  • 기본값에는 ||가 아니라 ??를 우선 고려한다.
  • 문자열은 변경 불가능하다. 메서드는 항상 새 문자열을 반환한다.
