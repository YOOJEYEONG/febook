객체 만들기와 접근

상황표기법
속성 이름이 고정되어 있다점 표기법 user.name
속성 이름이 변수에 들어 있다대괄호 user[key]
이름에 공백·하이픈이 있다대괄호 user["my-key"]
이름이 숫자로 시작한다대괄호

단축 문법

const name = "홍길동";
const age = 20;

// 옛 방식
const user1 = { name: name, age: age };

// ✅ 속성 축약 — 변수명과 키가 같으면 한 번만
const user2 = { name, age };

// 계산된 속성 이름 — 키를 동적으로
const field = "email";
const user3 = { [field]: "hong@example.com" };   // { email: "..." }
const user4 = { [`user_${age}`]: true };          // { user_20: true }

// 메서드 축약
const obj = {
  greet() { return "안녕"; }        // greet: function() {…} 와 같음
};

🐛 디버깅에 유용한 축약 문법

console.log(userId, count, isActive);
// 출력: 42 3 true   ← 뭐가 뭔지 모름

console.log({ userId, count, isActive });
// 출력: { userId: 42, count: 3, isActive: true }   ✅ 이름과 함께

구조 분해 할당

객체나 배열에서 필요한 값만 꺼내 변수로 만드는 문법입니다. React 코드를 열면 거의 모든 줄에 등장하므로 반드시 익혀야 합니다.

⚠️ 구조 분해에서 자주 나는 오류

// ❌ 대상이 null·undefined면 오류
const { name } = null;   // TypeError

// ✅ 기본값으로 방어
function f(options = {}) {
  const { size = "md" } = options;
}

// ✅ 서버 응답처럼 없을 수 있는 값
const { data } = response ?? {};

전개 구문 ...

Object의 정적 메서드

const user = { name: "홍길동", age: 20 };

Object.keys(user);       // ["name", "age"]
Object.values(user);     // ["홍길동", 20]
Object.entries(user);    // [["name","홍길동"], ["age",20]]

// entries → 다시 객체로
Object.fromEntries([["a", 1], ["b", 2]]);   // { a: 1, b: 2 }

// 합치기 (첫 인자를 직접 수정하므로 빈 객체를 앞에 둡니다)
Object.assign({}, defaults, options);       // { ...defaults, ...options } 와 유사

// 얕은 동결 — 수정 시도가 조용히 무시됩니다 (엄격 모드에서는 오류)
Object.freeze(user);

// 소유 속성 확인 (상속된 것은 제외)
Object.hasOwn(user, "name");   // true
실전: entries로 객체 가공하기 
const prices = { apple: 1000, banana: 2000, grape: 3000 };

// 값만 10% 인상한 새 객체
const raised = Object.fromEntries(
  Object.entries(prices).map(([name, price]) => [name, price * 1.1])
);

// 2000원 이상만 남기기
const expensive = Object.fromEntries(
  Object.entries(prices).filter(([, price]) => price >= 2000)
);

JSON

JSON은 데이터를 주고받기 위한 문자열 형식입니다. JavaScript 객체 문법에서 유래했지만 더 엄격합니다.

JavaScript 객체JSON
키따옴표 선택반드시 큰따옴표
문자열작은따옴표·백틱 가능큰따옴표만
마지막 쉼표허용불허
주석가능불가
함수·undefined가능불가

🚫 JSON.parse(JSON.stringify(x))로 깊은 복사를 하지 마세요

오랫동안 쓰이던 방법이지만 위에서 본 것처럼 Date가 문자열이 되고, 함수·undefined가 사라지고, NaN이 null이 되며, 순환 참조가 있으면 오류가 납니다. 지금은 structuredClone()이라는 표준 함수가 있습니다(25장).

🛠️ 현장 노트 — 속성 순서에 의존하지 마세요

객체의 속성 순서는 명세상 규칙이 있습니다. 정수처럼 보이는 키가 오름차순으로 먼저 오고, 그다음 문자열 키가 추가된 순서대로 옵니다. 즉 { b: 1, 2: 2, a: 3, 1: 4 }의 키 순서는 "1", "2", "b", "a"입니다. 규칙이 있긴 하지만 직관과 어긋나므로 순서에 의존하는 코드를 쓰지 마세요. 순서가 중요하면 배열이나 Map(41장)을 쓰는 것이 맞습니다.

📌 요약

  • 속성 이름이 변수에 들어 있으면 대괄호 표기법을 쓴다.
  • 축약 문법 { name, age }, 계산된 키 { [field]: v }, 메서드 축약 greet() {}.
  • 구조 분해는 이름 바꾸기·기본값·중첩·나머지를 모두 지원한다. 대상이 null이면 오류.
  • 전개 구문으로 복사·합치기. 뒤에 온 값이 이긴다. 얕은 복사임을 잊지 말 것.
  • Object.entries() + map/filter + fromEntries()로 객체를 가공한다.
  • JSON은 더 엄격한 형식이다. stringify는 함수·undefined를 버리고 Date를 문자열로 만든다.
  • 깊은 복사는 structuredClone().
