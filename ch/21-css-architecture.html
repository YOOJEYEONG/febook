CSS 변수 (커스텀 속성)

:root {
  --color-primary: #1f5f4f;
  --space-md: 16px;
  --radius: 8px;
}

.button {
  background: var(--color-primary);
  padding: var(--space-md);
  border-radius: var(--radius);
}

/* 값이 없을 때 쓸 기본값도 지정할 수 있습니다 */
.card { gap: var(--card-gap, 12px); }

이름은 반드시 --로 시작합니다. :root는 <html>을 가리키는 선택자로, 여기에 정의하면 문서 전체에서 쓸 수 있습니다.

Sass 변수와 무엇이 다른가

Sass 변수 $xCSS 변수 --x
존재 시점빌드할 때 값이 박제됨브라우저에서 살아 있음
상속없음있음 — 부모에서 자식으로
실행 중 변경불가능가능 — JavaScript로, 미디어 쿼리로
범위파일·블록 단위DOM 트리 단위

이 차이가 결정적입니다. CSS 변수는 상속되고 실행 중에 바뀔 수 있어서 다크 모드, 테마 전환, 컴포넌트 변형을 선택자 하나 추가 없이 만들 수 있습니다.

JavaScript에서 읽고 쓰기 
// 읽기
const color = getComputedStyle(document.documentElement)
  .getPropertyValue("--color-primary");

// 쓰기
document.documentElement.style.setProperty("--color-primary", "#c0392b");

디자인 토큰

색·간격·글자 크기 같은 값을 이름 붙은 변수로 정리한 체계를 디자인 토큰이라고 합니다. 두 층으로 나누는 것이 좋은 관행입니다.

:root {
  /* ① 원시 토큰 — 값 그 자체 */
  --green-500: #1f5f4f;
  --green-100: #e6f0ec;
  --gray-900:  #23211d;
  --size-2: 8px;
  --size-3: 16px;

  /* ② 의미 토큰 — "어디에 쓰는 색인가" */
  --color-text:    var(--gray-900);
  --color-accent:  var(--green-500);
  --color-surface: var(--green-100);
  --space-inline:  var(--size-3);
}

컴포넌트에서는 의미 토큰만 씁니다. 그러면 다크 모드나 브랜드 색 변경 시 의미 토큰이 가리키는 원시 토큰만 바꾸면 전부 따라옵니다.

다크 모드 제대로 만들기

다크 모드에는 세 가지 상태가 있습니다. 이걸 놓치면 반드시 버그가 납니다.

  1. 시스템 설정 따르기 (기본값)
  2. 사용자가 라이트를 명시적으로 선택
  3. 사용자가 다크를 명시적으로 선택
세 상태를 모두 처리하는 구조 
/* ① 라이트 팔레트를 기본으로 — 조건 없이 정의 */
:root {
  color-scheme: light;
  --bg: #ffffff;
  --text: #23211d;
}

/* ② 시스템이 다크이고, 사용자가 라이트를 고르지 않았을 때 */
@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) {
    color-scheme: dark;
    --bg: #14161a;
    --text: #e6e6e4;
  }
}

/* ③ 사용자가 다크를 명시적으로 골랐을 때 — 시스템 설정과 무관하게 */
:root[data-theme="dark"] {
  color-scheme: dark;
  --bg: #14161a;
  --text: #e6e6e4;
}

body { background: var(--bg); color: var(--text); }

🎛️ color-scheme을 빠뜨리지 마세요

이 속성은 브라우저 기본 UI(스크롤바, 폼 컨트롤, 기본 배경)의 색을 함께 바꿔 줍니다. 없으면 다크 모드에서 스크롤바만 흰색으로 남아 어색해집니다.

⚡ 다크 모드의 화면 깜빡임(FOUC)

테마 설정을 localStorage에서 읽어 적용하는 코드가 페이지 아래쪽에 있으면, 잠깐 라이트 모드가 보였다가 다크로 바뀝니다. 해결책은 <head> 안에 작은 인라인 스크립트를 두어 화면이 그려지기 전에 data-theme을 붙이는 것입니다. (이 책도 그 방식을 씁니다.)

이름 짓기

CSS의 가장 큰 문제는 모든 것이 전역이라는 점입니다. 어딘가에 .title { color: red }를 쓰면 문서 전체의 모든 .title이 빨개집니다. 이름 규칙은 이 충돌을 막기 위한 장치입니다.

BEM

/* Block__Element--Modifier */
.card { }                 /* 블록: 독립적인 덩어리 */
.card__title { }          /* 요소: 블록의 일부 (__ 두 밑줄) */
.card__image { }
.card--featured { }       /* 변형: 블록의 다른 상태 (-- 두 하이픈) */
.card__title--large { }
  • 장점 — 이름만 봐도 구조가 보이고, 명시도가 항상 (0,1,0)으로 평평해서 캐스케이드 싸움이 없습니다.
  • 단점 — 이름이 깁니다.

유틸리티 방식

<div class="flex items-center gap-4 p-4 rounded-lg bg-white">

Tailwind CSS로 대표되는 방식입니다. 한 클래스 = 한 속성. 이름을 고민할 필요가 없고 CSS 파일이 거의 늘지 않는 대신, HTML이 길어집니다. 22장에서 다룹니다.

🛠️ 현장 노트 — 무엇을 고르든 지킬 두 가지

  1. 선택자를 깊게 중첩하지 마세요. .page .content .card .title span 같은 선택자는 명시도가 높아 덮어쓰기 어렵고, HTML 구조가 조금만 바뀌어도 깨집니다. 클래스 하나로 직접 겨냥하는 편이 거의 항상 낫습니다.
  2. 요소 선택자로 스타일을 정의하지 마세요. div { margin: 10px } 같은 규칙은 문서 어디에 영향을 줄지 알 수 없습니다. (초기화 코드는 예외입니다.)

캐스케이드 레이어 — 명시도 전쟁의 종결

12장에서 승부 순서를 배웠습니다. 사실 그 앞에 한 단계가 더 있습니다. 바로 어느 레이어에 속하는가입니다.

/* ① 우선순위를 미리 선언 — 나중에 쓴 레이어가 이깁니다 */
@layer reset, base, components, utilities;

@layer reset {
  * { margin: 0; box-sizing: border-box; }
}

@layer components {
  /* 명시도가 아무리 높아도… */
  #app .card .title { color: blue; }
}

@layer utilities {
  /* …나중 레이어의 이 한 줄이 이깁니다 */
  .text-red { color: red; }
}

🏆 레이어는 명시도보다 먼저 판단됩니다

즉 utilities 레이어의 (0,1,0)짜리 규칙이 components 레이어의 (1,2,0)짜리 규칙을 이깁니다. "유틸리티 클래스가 항상 이겼으면 좋겠다"는 오랜 요구가 !important 없이 해결됩니다.
레이어에 속하지 않은 일반 CSS는 모든 레이어보다 우선합니다. 그래서 외부 라이브러리를 @layer로 감싸 두면 내 코드가 자연스럽게 이깁니다.

외부 라이브러리를 레이어에 가두기 
@layer vendor, app;
@import url("some-library.css") layer(vendor);

@layer app {
  /* 이제 여기 쓴 것이 라이브러리를 덮어씁니다 */
}

Chrome 99+, Safari 15.4+, Firefox 97+에서 지원됩니다.

:where()로 명시도 낮추기

/* 명시도 (0,2,1) — 덮어쓰기 어렵다 */
.prose .content a { color: blue; }

/* 명시도 (0,0,1) — a 하나만큼. 쉽게 덮어쓸 수 있다 */
:where(.prose .content) a { color: blue; }

:where()는 안에 든 것의 명시도를 0으로 만듭니다. 라이브러리나 기본 스타일을 만들 때, 사용자가 쉽게 덮어쓸 수 있게 하는 데 유용합니다.

초기화

브라우저마다 기본 스타일이 조금씩 다릅니다. 이를 맞추는 코드를 리셋 또는 노멀라이즈라고 합니다. 요즘은 이 정도면 충분한 경우가 많습니다.

@layer reset {
  *, *::before, *::after { box-sizing: border-box; }
  * { margin: 0; }
  body { line-height: 1.7; -webkit-font-smoothing: antialiased; }
  img, picture, video, canvas, svg { display: block; max-width: 100%; }
  input, button, textarea, select { font: inherit; }
  p, h1, h2, h3, h4, h5, h6 { overflow-wrap: break-word; }
  ul[role="list"], ol[role="list"] { list-style: none; padding: 0; }
}

img { display: block }은 이미지 아래에 생기는 미묘한 빈 공간을 없앱니다. 이미지가 인라인 요소라서 글자의 baseline 아래 여백이 남기 때문에 생기는 현상입니다.

📌 요약

  • CSS 변수는 상속되고 실행 중에 바꿀 수 있다. Sass 변수와 근본적으로 다르다.
  • 토큰은 원시 토큰 → 의미 토큰 두 층으로. 컴포넌트는 의미 토큰만 쓴다.
  • 다크 모드는 세 상태(시스템·라이트 강제·다크 강제)를 모두 처리해야 한다. color-scheme도 함께.
  • 테마 스크립트는 <head>에 인라인으로 두어 깜빡임을 막는다.
  • 이름 규칙은 전역 충돌을 막기 위한 것. 깊은 중첩과 요소 선택자를 피한다.
  • 캐스케이드 레이어는 명시도보다 먼저 판단된다. !important의 대안이다.
  • :where()는 명시도를 0으로 만들어 덮어쓰기 쉽게 한다.
