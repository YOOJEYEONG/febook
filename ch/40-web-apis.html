IntersectionObserver — 화면에 보이는지 감지

"이 요소가 화면에 들어왔는가"를 알려 줍니다. 예전에는 scroll 이벤트에서 위치를 계산했는데, 그 방식은 초당 수십 번 레이아웃을 강제해 심각하게 느렸습니다. IntersectionObserver는 브라우저가 효율적으로 대신 감시해 줍니다.

쓰임설명

무한 스크롤맨 아래 감시 요소가 보이면 다음 페이지 요청
등장 애니메이션위 예제

광고 노출 측정실제로 화면에 보였는지 확인

ResizeObserver와 MutationObserver

ResizeObserver — 요소 크기 변화 감지 
const ro = new ResizeObserver((entries) => {
  for (const entry of entries) {
    const { width, height } = entry.contentRect;
    console.log(`${width} × ${height}`);
  }
});
ro.observe(chartContainer);

window의 resize 이벤트는 창 크기만 알려 줍니다. 사이드바가 접혀서 요소만 작아지는 경우는 감지하지 못합니다. 차트 라이브러리를 컨테이너 크기에 맞춰 다시 그릴 때 필수입니다.

MutationObserver — DOM 변화 감지 
const mo = new MutationObserver((mutations) => {
  for (const m of mutations) {
    console.log(m.type, m.addedNodes.length);
  }
});
mo.observe(container, { childList: true, subtree: true, attributes: true });

내가 통제할 수 없는 외부 스크립트가 DOM을 바꿀 때 대응하는 용도입니다. 직접 만든 코드라면 대개 필요 없습니다.

🧹 Observer는 반드시 정리하세요

observer.unobserve(element);   // 특정 요소만 해제
observer.disconnect();          // 전부 해제

해제하지 않으면 요소가 사라진 뒤에도 참조가 남아 메모리 누수가 됩니다. React에서는 useEffect의 정리 함수에서 disconnect()를 호출합니다(61장).

History API

// 새로고침 없이 주소만 바꾸기 (히스토리에 새 항목 추가)
history.pushState({ page: 2 }, "", "/products?page=2");

// 현재 항목을 교체 (뒤로 가기 목록에 남기지 않음)
history.replaceState({ tab: "info" }, "", "?tab=info");

// 뒤로/앞으로 갈 때
window.addEventListener("popstate", (event) => {
  console.log("상태:", event.state);
  renderPage(location.pathname);   // 화면을 직접 다시 그려야 합니다
});

history.back();
history.forward();

🧭 SPA 라우팅의 정체

React Router 같은 라이브러리가 하는 일이 바로 이것입니다. 링크 클릭에서 preventDefault()로 브라우저의 페이지 이동을 막고, pushState로 주소만 바꾸고, 해당하는 컴포넌트를 렌더링합니다. 68장에서 다시 다룹니다.
주의: pushState는 화면을 바꿔 주지 않습니다. 주소만 바뀝니다. 그리고 다른 출처의 주소로는 바꿀 수 없습니다.

Web Worker — 진짜 별도 스레드

35장에서 본 것처럼 무거운 계산은 화면을 멈추게 합니다. Web Worker는 완전히 다른 스레드에서 코드를 실행해 메인 스레드를 자유롭게 둡니다.

worker.js 
self.addEventListener("message", (event) => {
  const result = heavyCalculation(event.data);
  self.postMessage(result);
});
main.js 
const worker = new Worker("worker.js");
worker.postMessage({ numbers: bigArray });
worker.addEventListener("message", (event) => {
  console.log("결과:", event.data);   // 이 동안에도 화면은 부드럽게 움직입니다
});
worker.terminate();   // 다 쓰면 종료
Worker에서 되는 것안 되는 것
계산, fetch, IndexedDB, setTimeoutdocument·window·DOM 접근, localStorage

메인과 Worker는 메시지로만 대화합니다. 데이터는 복사되어 전달되므로 아주 큰 데이터를 자주 주고받으면 그 자체가 비용이 됩니다.

그 밖에 자주 쓰는 API

matchMedia — JavaScript에서 미디어 쿼리 쓰기 
const mq = window.matchMedia("(prefers-color-scheme: dark)");
console.log(mq.matches);                       // 현재 상태
mq.addEventListener("change", (e) => {
  applyTheme(e.matches ? "dark" : "light");    // 설정이 바뀌면 즉시 반응
});
클립보드 
// ⚠️ HTTPS(또는 localhost)에서만 동작하고, 사용자 동작에 의해 호출되어야 합니다
async function copy(text) {
  try {
    await navigator.clipboard.writeText(text);
    showToast("복사했습니다");
  } catch (error) {
    showToast("복사에 실패했습니다");
  }
}
페이지 가시성 — 탭이 백그라운드로 갔는지 
document.addEventListener("visibilitychange", () => {
  if (document.hidden) {
    pauseVideo();          // 배터리·데이터 절약
  } else {
    refreshData();         // 돌아오면 최신 데이터로
  }
});
페이지를 떠날 때 데이터 전송 
// fetch는 페이지가 닫히면 취소될 수 있습니다. sendBeacon은 보장됩니다
navigator.sendBeacon("/api/analytics", JSON.stringify({ event: "leave" }));
<dialog> — 모달을 직접 만들 필요가 없습니다 
<dialog id="modal">
  <form method="dialog">
    <p>정말 삭제할까요?</p>
    <button value="cancel">취소</button>
    <button value="ok">삭제</button>
  </form>
</dialog>
modal.showModal();     // 배경 클릭 차단, Esc로 닫기, 포커스 가둠 — 전부 기본 제공
modal.addEventListener("close", () => console.log(modal.returnValue));

✨ <dialog>를 쓰세요

직접 만든 모달은 포커스 가두기, Esc 닫기, 스크롤 잠금, 접근성 역할을 전부 구현해야 하고, 대부분 빠뜨립니다. <dialog>는 이 모든 것을 브라우저가 제공합니다. 게다가 17장에서 본 transform 조상 문제도 겪지 않습니다. Chrome 37+, Safari 15.4+, Firefox 98+에서 지원됩니다.

🛠️ 현장 노트 — 라이브러리를 찾기 전에 표준을 확인하세요

"모달", "툴팁", "무한 스크롤", "날짜 포맷", "복사 버튼" — 예전에는 전부 라이브러리가 필요했지만 지금은 브라우저가 기본 제공하는 것이 많습니다. <dialog>, <details>, IntersectionObserver, Intl(43장), navigator.clipboard가 그 예입니다.
표준 기능은 용량이 0이고, 접근성이 갖춰져 있고, 유지보수가 필요 없습니다. 새 의존성을 추가하기 전에 MDN에서 먼저 검색하는 습관이 실력을 크게 좌우합니다.

📌 요약

  • IntersectionObserver로 "화면에 보이는지"를 효율적으로 감지한다. scroll 이벤트 계산보다 훨씬 빠르다.
  • ResizeObserver는 창이 아니라 요소의 크기 변화를 본다.
  • 모든 Observer는 정리(disconnect)해야 한다.
  • History API가 SPA 라우팅의 토대다. pushState는 주소만 바꾼다.
  • Web Worker는 별도 스레드지만 DOM에 접근할 수 없다.
  • matchMedia로 JavaScript에서 미디어 쿼리를 쓴다.
  • 모달은 <dialog>. 접근성이 공짜로 따라온다.
  • 라이브러리 전에 표준 API를 먼저 확인한다.
