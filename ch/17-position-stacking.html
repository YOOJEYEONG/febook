position 다섯 가지

값기준원래 자리주 용도
static (기본)—차지함일반 흐름. top 등이 무시됨
relative자기 원래 자리차지함살짝 밀기 + absolute의 기준점 제공
absolute가장 가까운 위치 지정 조상차지하지 않음배지, 툴팁, 드롭다운
fixed뷰포트(화면)차지하지 않음고정 헤더, 플로팅 버튼, 모달
sticky스크롤 조상 + 자기 자리차지함스크롤 시 붙는 헤더, 표 머리글

📌 relative의 진짜 용도

relative를 요소를 움직이려고 쓰는 경우는 드뭅니다. 실무에서 position: relative의 90%는 자식 absolute의 기준점을 만들기 위해 붙입니다. 값을 하나도 주지 않은 position: relative;만으로도 그 역할은 충분합니다.

absolute의 기준 찾기

absolute 요소는 조상을 거슬러 올라가며 position이 static이 아닌 첫 번째 요소를 찾아 그것을 기준으로 배치됩니다. 끝까지 없으면 문서 전체(초기 컨테이닝 블록)가 기준이 됩니다.

가장 흔한 패턴 — 배지 붙이기 
.card {
  position: relative;   /* ← 기준점 선언 */
}
.card .badge {
  position: absolute;
  top: 8px;
  right: 8px;           /* 카드의 오른쪽 위 모서리 */
}

🎯 요소가 화면 구석으로 날아갔다면

부모에 position: relative를 안 붙였기 때문입니다. 기준이 될 조상이 없어 문서 전체가 기준이 되어 페이지 맨 위로 올라간 것입니다. absolute를 쓸 때는 항상 "기준이 누구인가"를 먼저 정하세요.

네 방향을 모두 지정하면

.overlay {
  position: absolute;
  inset: 0;          /* top:0; right:0; bottom:0; left:0 의 축약 */
}
/* 크기를 지정하지 않아도 부모를 꽉 채웁니다 */

inset은 축약 속성으로 Chrome 87+, Safari 14.1+, Firefox 66+에서 지원됩니다. 모달 배경막, 이미지 위 그라데이션 등에 자주 씁니다.

fixed의 함정

💥 "fixed인데 스크롤을 따라 움직여요"

fixed는 뷰포트 기준이라고 배웁니다. 그런데 조상 중에 transform, filter, perspective, backdrop-filter, will-change, contain 중 하나라도 적용된 요소가 있으면, 그 요소가 새로운 기준이 됩니다. 뷰포트가 아니라요. 그래서 애니메이션을 위해 부모에 transform을 넣었더니 자식 모달이 갑자기 스크롤을 따라 움직이는 상황이 생깁니다. 원인을 모르면 며칠도 헤맬 수 있는 문제입니다. 해결 — 모달·드롭다운처럼 화면 최상단에 떠야 하는 요소는 <body> 바로 아래로 옮기거나(React의 Portal), 아예 <dialog> 요소를 쓰는 것이 안전합니다.

sticky

sticky는 평소에는 relative처럼 흐르다가, 지정한 위치에 닿으면 fixed처럼 붙는 하이브리드입니다.

.sticky-header {
  position: sticky;
  top: 0;             /* ← 임계값. 반드시 필요합니다 */
  background: white;  /* ← 배경이 없으면 아래 내용이 비쳐 보입니다 */
  z-index: 10;
}

🔍 sticky가 동작하지 않는 세 가지 이유

  1. top·bottom·left·right 중 하나도 지정하지 않았다. 임계값이 없으면 붙을 지점을 알 수 없어 아무 일도 일어나지 않습니다. 가장 흔한 원인입니다.
  2. 조상 중에 overflow가 hidden·auto·scroll인 요소가 있다. 그 요소가 새로운 스크롤 기준이 되어 예상과 다르게 동작하거나 아예 붙지 않습니다.
  3. 부모의 높이가 자식과 같다. sticky는 부모 상자 안에서만 붙어 있을 수 있습니다. 움직일 여유 공간이 없으면 붙을 일도 없습니다.

z-index와 쌓임 맥락

기본 규칙

  • z-index는 position이 static이 아닌 요소에만 적용됩니다. (예외: flex·grid 아이템에는 position 없이도 적용됩니다.)
  • 값이 클수록 앞에 옵니다. 같으면 나중에 나온 요소가 앞입니다.

쌓임 맥락 — z-index가 안 먹는 진짜 이유

🪆 러시아 인형(마트료시카)으로 이해하기

쌓임 맥락(stacking context)은 독립된 층 세계입니다. 한 번 그 안에 들어간 요소는 아무리 z-index를 높여도 그 세계 밖으로 나갈 수 없습니다.

.parent-a { position: relative; z-index: 1; }
.parent-a .child { position: absolute; z-index: 9999; }  /* 소용없음 */

.parent-b { position: relative; z-index: 2; }

.parent-b(2)가 .parent-a(1)보다 앞이므로, .parent-a 안의 자식은 z-index가 9999든 100만이든 .parent-b 뒤에 있습니다. 인형 안에 들어간 인형이 아무리 커도 바깥 인형보다 앞으로 나올 수 없는 것과 같습니다.

쌓임 맥락을 만드는 것들

조건비고
문서의 루트(<html>)—
position이 relative·absolute이고 z-index가 auto가 아님가장 흔한 경우
position: fixed 또는 stickyz-index가 없어도 만들어집니다
opacity가 1보다 작음이것 때문에 자주 당합니다
transform, filter, perspective, backdrop-filter, mix-blend-mode애니메이션 최적화에 흔히 쓰는 속성들
isolation: isolate의도적으로 맥락을 만들 때 쓰는 전용 속성
will-change, contain: layout·paint—
flex·grid 아이템 중 z-index가 auto가 아닌 것—

🛠️ 현장 노트 — z-index 문제 진단 순서

  1. 대상 요소에 position이 있는가? (없으면 z-index는 무시됩니다)
  2. class="term" data-term="devtools">개발자 도구에서 조상을 하나씩 거슬러 올라가며 opacity·transform·filter·z-index가 걸린 요소를 찾습니다. 그것이 범인입니다.
  3. 해결책은 z-index를 더 올리는 것이 아니라, 그 요소를 다른 부모 밑으로 옮기는 것입니다.

팀 규칙으로 z-index 단계를 미리 정해 두면 이 싸움의 절반이 사라집니다. 예: 드롭다운 10, 고정 헤더 100, 모달 1000, 토스트 2000. z-index: 99999가 등장했다면 그것은 설계가 무너졌다는 신호입니다.

📌 요약

  • relative는 자기 자리, absolute는 가장 가까운 위치 지정 조상, fixed는 뷰포트 기준.
  • relative의 주 용도는 이동이 아니라 기준점 제공이다.
  • 조상에 transform·filter 등이 있으면 fixed의 기준이 뷰포트가 아니게 된다.
  • sticky는 임계값(top 등)이 필수이고, 조상의 overflow와 부모 높이에 영향을 받는다.
  • z-index는 같은 쌓임 맥락 안에서만 비교된다.
  • opacity: 0.99나 transform만으로도 쌓임 맥락이 생긴다.
  • 해결은 z-index를 올리는 게 아니라 DOM 위치를 바꾸는 것이다.
