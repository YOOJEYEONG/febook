📄 page.tsx가 있어야 주소가 됩니다

폴더만 만들면 주소가 생기지 않습니다. page 파일이 있는 폴더만 접근 가능합니다. 덕분에 app/blog/components/처럼 관련 파일을 같은 폴더에 두어도 주소가 되지 않습니다. 63장에서 말한 "함께 바뀌는 것을 함께 두기"가 자연스럽게 가능해집니다.

서버와 클라이언트의 경계 — 가장 중요한 개념

🚧 App Router에서는 모든 컴포넌트가 기본적으로 서버 컴포넌트입니다

69장에서 배운 서버 컴포넌트가 기본값입니다. 상호작용이 필요한 컴포넌트에만 파일 맨 위에 "use client"를 붙입니다.

// app/products/page.tsx — 서버 컴포넌트 (기본)
import { db } from "@/lib/db";
import AddToCartButton from "./AddToCartButton";

export default async function ProductsPage() {
  const products = await db.product.findMany();   // ⭐ DB 직접 조회

  return (
    <ul>
      {products.map(p => (
        <li key={p.id}>
          {p.name}
          <AddToCartButton productId={p.id} />   {/* 여기만 클라이언트 */}
        </li>
      ))}
    </ul>
  );
}
// app/products/AddToCartButton.tsx
"use client";                                    // ← 이 한 줄

import { useState } from "react";

export default function AddToCartButton({ productId }) {
  const [added, setAdded] = useState(false);     // 훅은 여기서만 가능
  return <button onClick={() => setAdded(true)}>{added ? "담김" : "담기"}</button>;
}

🍃 경계를 최대한 아래로 내리세요

"use client"는 그 파일과 그 파일이 import 하는 모든 것을 클라이언트 번들에 포함시킵니다. 페이지 최상단에 붙이면 전체가 클라이언트 컴포넌트가 되어 서버 컴포넌트의 이점이 사라집니다.
버튼 하나만 클라이언트로 만들고 나머지는 서버에 두는 것이 정석입니다. 이것을 "클라이언트 경계를 잎사귀로 밀어내기"라고 부릅니다.

📦 서버 → 클라이언트로 넘기는 props는 직렬화 가능해야

// ❌ 함수는 넘길 수 없습니다
<ClientButton onClick={() => console.log("x")} />

// ❌ Date·Map·클래스 인스턴스도 제한이 있습니다
// ✅ 문자열·숫자·불리언·배열·평범한 객체는 됩니다
<ClientButton productId={p.id} name={p.name} />

서버 컴포넌트의 결과는 네트워크로 전송되므로 문자열로 바꿀 수 있어야 합니다. 함수를 넘기려면 Server Action이라는 별도 장치가 필요합니다(72장).

클라이언트 컴포넌트 안에 서버 컴포넌트를 넣는 법 
// ❌ 클라이언트 컴포넌트가 서버 컴포넌트를 직접 import 할 수 없습니다

// ✅ children으로 넘기면 됩니다 (63장의 합성)
// 서버 컴포넌트에서
<ClientWrapper>
  <ServerContent />      {/* 서버에서 만들어져 전달됩니다 */}
</ClientWrapper>

⚡ <Link>는 미리 불러옵니다

화면에 보이는 <Link>의 대상 페이지를 백그라운드에서 미리 받아 둡니다. 그래서 클릭하면 거의 즉시 화면이 바뀝니다. 68장에서 말한 프리페치가 기본으로 동작하는 것입니다. 일반 <a>를 쓰면 이 이점이 사라지고 전체 새로고침이 일어납니다.

라우트 핸들러 — API 만들기

// app/api/products/route.ts
import { NextResponse } from "next/server";

export async function GET(request: Request) {
  const { searchParams } = new URL(request.url);       // 3장의 URL API
  const category = searchParams.get("category");
  const products = await db.product.findMany({ where: { category } });
  return NextResponse.json(products);
}

export async function POST(request: Request) {
  const body = await request.json();
  const parsed = ProductSchema.safeParse(body);        // 54장 런타임 검증
  if (!parsed.success) {
    return NextResponse.json({ error: "잘못된 요청" }, { status: 400 });
  }
  const created = await db.product.create({ data: parsed.data });
  return NextResponse.json(created, { status: 201 });
}

🤔 서버 컴포넌트가 있으면 API가 필요 없나요?

내 화면에 데이터를 보여주는 것만이 목적이라면 서버 컴포넌트에서 DB를 직접 조회하면 됩니다. API 계층이 불필요합니다.
라우트 핸들러가 필요한 경우는 이렇습니다.

  • 외부에 공개할 API (모바일 앱, 다른 서비스)
  • 웹훅 수신 (결제사 알림 등)
  • 클라이언트 컴포넌트에서 호출해야 하는 경우
  • 비밀 키를 감춰야 하는 외부 API 프록시(1·37장)

미들웨어

// middleware.ts — 요청이 페이지에 도달하기 전에 실행됩니다
import { NextResponse } from "next/server";

export function middleware(request) {
  const token = request.cookies.get("session");
  if (!token && request.nextUrl.pathname.startsWith("/admin")) {
    return NextResponse.redirect(new URL("/login", request.url));
  }
  return NextResponse.next();
}

export const config = { matcher: ["/admin/:path*"] };

인증 확인, 리다이렉트, 국가별 분기 등에 씁니다. 모든 요청을 거치므로 무거운 작업은 넣지 마세요. 68장에서 말했듯 진짜 권한 검사는 데이터에 접근하는 지점에서도 해야 합니다.

🛠️ 현장 노트 — App Router 적응 팁

  1. "기본은 서버"를 몸에 익히세요. useState가 필요할 때만 "use client"입니다.
  2. 오류 메시지를 읽으세요. Next.js는 "이건 클라이언트 컴포넌트에서만 됩니다" 같은 안내를 꽤 친절하게 줍니다.
  3. 옛 자료 주의. getServerSideProps·getStaticProps는 Pages Router의 것이고 App Router에는 없습니다.
  4. Pages Router도 여전히 지원됩니다. 기존 프로젝트라면 그쪽일 수 있으니 폴더 이름(app/ vs pages/)을 먼저 확인하세요.

📌 요약

  • Next.js는 라우팅·번들·렌더링 전략·최적화를 내장한 프레임워크다.
  • 폴더 구조가 곧 주소이고, page 파일이 있어야 접근 가능하다.
  • layout·loading·error·not-found가 특수 파일이다.
  • 모든 컴포넌트는 기본이 서버 컴포넌트다. 훅·이벤트가 필요하면 "use client".
  • 클라이언트 경계는 최대한 아래로 내린다.
  • 서버 → 클라이언트 props는 직렬화 가능해야 한다. 함수는 불가.
  • 클라이언트 안에 서버 컴포넌트를 넣으려면 children으로 전달한다.
  • <Link>는 미리 불러오기가 기본이다.
  • 서버 컴포넌트로 직접 조회할 수 있으면 API 계층이 불필요할 수 있다.
