🧩 코드 출력 맞히기 문제

// 자주 나오는 유형들
console.log(1); setTimeout(() => console.log(2), 0);
Promise.resolve().then(() => console.log(3)); console.log(4);
// → 1 4 3 2  (35장)

for (var i = 0; i < 3; i++) setTimeout(() => console.log(i), 0);
// → 3 3 3  (24·31장)

const obj = { name: "a", greet: () => console.log(this.name) };
obj.greet();
// → undefined  (30장)

console.log(0.1 + 0.2 === 0.3);
// → false  (25장)

답보다 이유를 설명하는 것이 중요합니다. "3 3 3입니다"보다 "var는 함수 스코프라 i가 하나뿐이고, 콜백은 반복이 끝난 뒤 실행되므로…"가 훨씬 좋은 답입니다.

모르는 것을 만났을 때

🎭 아는 척이 가장 나쁩니다

❌ 얼버무리기 — 후속 질문 한 번에 드러납니다
❌ "모릅니다"로 끝내기 — 대화가 끊깁니다

✅ "정확히는 모르겠습니다. 다만 제가 아는 범위에서 추측하자면 …
    맞을까요?"
✅ "써 본 적은 없지만 개념은 알고 있습니다. △△와 비슷한 것으로 이해했는데
    실제로는 어떤가요?"
✅ "모르겠습니다. 나중에 찾아보고 정리하겠습니다."

면접관이 보는 것은 지식의 양이 아니라 사고 과정입니다. 모르는 것을 정직하게 말하고 어떻게 접근할지 보여주는 것이 어설프게 아는 척하는 것보다 훨씬 좋은 인상을 줍니다. 실무에서도 아는 척하는 동료가 가장 위험합니다(82장).

📐 숫자와 구체성

무엇을 했는가보다 어떤 문제를 어떻게 해결했고 결과가 어땠는가를 쓰세요. 숫자가 있으면 신뢰도가 올라갑니다.
그리고 이력서에 쓴 모든 것은 질문 대상입니다. "Redux 사용"이라고 썼다면 왜 Redux였는지 답할 수 있어야 합니다. 확신 없는 기술은 쓰지 마세요.

🛠️ 현장 노트 — 준비 방법

  1. 소리 내어 설명해 보세요. 머릿속으로 아는 것과 말로 설명하는 것은 완전히 다릅니다. 녹음해서 들어 보면 더 좋습니다.
  2. 자기 프로젝트를 깊게 준비하세요. 모르는 기술 이야기보다 자기가 만든 것에 대한 질문이 훨씬 많이 나옵니다.
  3. "왜"에 답할 수 있게. 모든 선택에 이유를 준비하세요.
  4. 최근 관심사를 하나 준비하세요. "요즘 무엇을 공부하나요?"는 단골입니다.
  5. 떨어져도 배우세요. 못 답한 질문을 메모하고 찾아보면 그 자체가 최고의 학습 자료입니다.

면접은 시험이 아니라 대화입니다. "함께 일하고 싶은 사람인가"를 보는 자리이기도 합니다. 모든 것을 아는 사람을 찾는 것이 아니라 배울 수 있고 소통이 되는 사람을 찾습니다.
